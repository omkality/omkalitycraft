# Полный возврат лабораторного мира на Linux

`omk lab dj2-recovery --runtime linux-docker --edge-cases --full-backup-return`
расширяет прежний стенд отдельным запуском полного снимка в **новом** Linux volume.
Это проверка восстановления, а не эксплуатационная команда переключения VPS.
Существующие миры/аккаунты не принимаются как тестовые данные.

## Порядок опыта

1. Создаются новая папка `recovery-lab-*`, собственный Docker volume и временный
   Drasl. Из заданного runtime копируются моды/config/scripts, без старых миров.
   Игроки входят настоящим Forge-протоколом; графический клиент не запускается.
2. В мире задаются предметы/NBT сундуков и печи, стойки для брони, инвентарь игрока,
   FTB-команда, claim и home. Чисто остановленный полный архив сохраняется до
   намеренного изменения этих данных. Проходит прежний поблочный recovery-сценарий.
3. Перед полным возвратом исходный сервер опять останавливается. Проверяются
   process/container exit 0, OOM=false и журнал без фатальных маркеров. Текущий мир
   экспортируется отдельно: исторический архив не заменяет свежую копию перед операцией.
4. Остановленный исходный volume читается через `readonly` mount. Проверяются пути,
   ссылки, коллизии/лимиты ZIP и SHA256 файлов; сохраняется общий digest содержимого.
   Неизвестный или чужой volume запрещён. Отсутствие volume проверяется **до** mount:
   Docker иначе может создать пустой volume по указанному имени.
   [Поведение Docker](https://docs.docker.com/engine/storage/volumes/#start-a-container-with-a-volume).
5. `stage_full_world` принимает только правильный хеш исторического архива,
   остановленный источник и новый пустой путь `recovery-lab-return/server/lab-world`.
   До записи сохраняется план, после readback каждого файла — маркер завершённого staging.
   Runtime JAR исходника и замены сверяются; распаковки поверх прежнего мира нет.
6. Восстановленная копия стартует в другом volume. Проверяются сундуки/NBT, сущности,
   предметы игрока, реальный `/home`, доступ владельца и запрет постороннему в claim,
   положительный контроль снаружи claim и настоящая плавка печи.
7. Исходный остановленный volume повторно читается readonly; digest обязан совпасть.
   Обе области очищаются независимо. Удаление исходного volume разрешается только
   при сохранённом проверенном TAR и чистой остановке. Если TAR исчез/изменён,
   volume сохраняется, общий результат неуспешен. Restart сбрасывает старое разрешение.

Имена Docker-ресурсов случайные, доступ — только loopback. Сервер: закреплённый
Linux Temurin JRE, 4 CPU / 6 ГиБ контейнер / Java heap 4 ГиБ. Учётные данные и Core
не публикуются. Исходный архив и повреждённый мир не удаляются ради демонстрации.

## Воспроизведение

```text
uv run python -m omk lab dj2-recovery --runtime linux-docker --edge-cases --full-backup-return --server-source PATH_TO_DJ2_SERVER --agent PATH_TO_AUTHLIB_1_2_8 --core PATH_TO_PRIVATE_CORE_0_2_8 --mods-json PATH_TO_VERIFIED_MOD_LIST --worldedit PATH_TO_WORLDEDIT_6_1_10
```

Нужен уже полученный официальный WorldEdit file 2941712 с SHA256
`cd4768ded9e2b527e3fc093fdf4ce07f058187de7961bdc0d7fa821c1b756f75`.
Runtime/private Core и mod list фиксируются в отчёте, без скачивания плавающих версий.

## Дополнительная проверка актуальных vanilla-допусков

Флаг `--access-policy` используется только вместе с Linux
`--edge-cases --full-backup-return`. После исторического world-снимка стенд меняет
актуальные OP, бан аккаунта и whitelist. Из уже остановленного исходного volume
через readonly mount берётся отдельный архив: `ops.json`, `banned-players.json`,
`banned-ips.json`, `whitelist.json` и `server.properties` для чтения whitelist-флага.

В новый runtime переносятся четыре JSON-списка и только `white-list=true/false`.
Прочие свойства, в том числе сеть и RCON, не копируются из исторического мира или
этого отдельного архива. До записи проверяются состав/размеры/типы записей,
отсутствие ссылок/дубликатов и корректность JSON; затем выполняется readback.
План и отдельный маркер готовности обязательны. Частичная запись не разрешает
старт замены; незавершённая проверка допусков сохраняет исходный volume даже при
успешном экспорте world-файлов.

После запуска проверяются отказ забаненному аккаунту с действующей сессией,
действующие OP-права, отказ административной команды после явного deop, вход
той же сессии после pardon, запрет после удаления из whitelist и последующий
допуск после явного добавления. Затем идут обычные проверки полного world-return.
Deop/pardon/редактирование whitelist — намеренные действия **только в копии стенда**;
исходные файлы допусков повторно читаются readonly и должны остаться неизменными.

Это не механизм сброса пароля/отзыва Drasl-сессий. Действующий Drasl не откатывается
вместе с миром. Актуальные ранги FTB, членства/роли внутри исторического мира,
внешняя модерация, произвольные server.properties и production-cutover требуют
отдельного согласования. Копия `banned-ips.json` сверяется по байтам; отдельный
сетевой сценарий IP-бана этим режимом не объявляется проверенным.


Режим проверен на DJ2 2.23.4 / Core 0.2.8: **120 серверных условий / пять стартов**
и **12 независимых проверок** остановленных файлов. Бан/OP/whitelist подтверждены
парными отказами и разрешениями с теми же действующими сессиями; четыре списка
скопированы побайтно, текущий whitelist-флаг применён. Исходные world/access digests
совпали, оба stop чистые / OOM=false; свои volumes удалены после проверки экспортов.
Профильные unit: Windows 158 passed / 1 skip, Linux Docker 159 passed. Отказы
копирования/пропажи данных проверялись подставленным lifecycle, не аварией диска.
[Отдельный отчёт](validation/dj2-current-access-return-2026-11-05.json).

## Границы

Это возврат прогресса всего мира и всех игроков к моменту снимка, а не только
одной выделенной базы. Он не заменяет безопасный выборочный откат после грифа.

Полный world-return включает сущности и исторические FTB-данные; поблочный WorldEdit
restore имеет другое покрытие. Возврат старого снимка также возвращает прежние
членства/права внутри мира. До эксплуатации нужно сверять их с текущими допусками.

Внешний Drasl остаётся текущим: его БД не входит в архив мира. `ops.json`, bans,
whitelist, текущие ранги/config и прочее состояние вне `lab-world` этим архивом
не восстанавливаются. Стенд копирует проверенный runtime отдельно; готовой процедуры
сохранения всей текущей административной политики ещё нет.

Пределы маленького стенда — 20000 файлов, 512 МиБ распакованных данных, 128 МиБ на
файл. Это не пределы будущего production-хранилища. Сценарий не моделирует пропажу
диска/питания, произвольный SIGKILL во время записи мира, полный story-прогресс,
игру во всех измерениях или большие сети AE2. Планировщик/retention/внешние копии,
аварийное production-переключение и закрытый owner apply остаются #33/#34.

## Проверка 5 ноября 2026

DJ2 2.23.4 / Core 0.2.8 прошёл **112 серверных условий / пять стартов**. Исторический
архив содержал 267 файлов / 12 682 647 распакованных байт; все файлы сверены после
staging. В замене вернулись стойки для брони, сундуки/NBT, пять предметов игрока,
home и claim; проверены реальный телепорт, права владельца/постороннего и плавка печи.
Digest исходного volume до/после совпал; оба сервера остановились с exit 0,
fatal=false / OOM=false. Оба собственных volume удалены после проверенного экспорта,
временная авторизация удалена.

Ещё **6 независимых проверок** остановленных файлов подтвердили инвентарь 5 → 1 → 5,
удалённый и возвращённый home/claim, тот же UUID/команду, сохранность владельца и
членств, совпадение всех staging-файлов с ZIP/manifest. Первая версия этого reader
ошибочно ожидала пустой файл claims: после последнего unclaim FTB удаляет файл.
Reader исправлен на проверку отсутствия; игра/архивы для этого не менялись.

Первый игровой запуск остановлен оператором до приёмки ради добавления guard
от отсутствующего volume. Exit 143 не принят за чистую остановку; отчёт сохранён,
данные экспортированы отдельно как forensic, свой volume удалён после проверки.
Положительный прогон целиком выполнен заново на свежих данных с итоговым кодом.

Профильные unit/lifecycle проверки: Windows **139 passed / 1 skip**, Linux Docker
**140 passed**, без OOM. Это mock-проверки переходов/отказов, отдельно от пяти запусков
настоящего сервера. Графический Minecraft в этом этапе не запускался.
[Версии, хеши, результаты и исключённые попытки](validation/dj2-linux-full-return-2026-11-05.json).
