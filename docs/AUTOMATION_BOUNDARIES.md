# Автономные операции и границы FTB

Core 0.2.7 добавляет узкую защиту **одного подтверждённого автономного переноса
инвентарей** DJ2. Это часть [#29](https://github.com/omkality/omkalitycraft/issues/29),
выделенная в [#46](https://github.com/omkality/omkalitycraft/issues/46).
Другие машины, трубы, изменение биомов, рост деревьев и взрывы не объявляются защищёнными
этим адаптером. Предметных банов и обновления авторского модового JAR не вводилось.

## Правило

У эффекта нет сохранённого владельца-игрока. Для него используются **актуальные claims
FTB по месту источника эффекта**, а не выдуманный OP/FakePlayer или отдельная БД.

- Внутри командного claim операция видит контейнеры той же FTB-команды.
- Раздельные участки той же команды допустимы, если они находятся в штатном радиусе.
- На незанятой территории доступны только незанятые контейнеры.
- Переходы между доменами запрещены в обоих направлениях, включая вынос наружу.
- Составной контейнер допускается только целиком: обе части должны относиться к
  разрешённому домену. Смешанный контейнер не обслуживается частично.
- Серверная команда — отдельный домен с теми же правилами.

Исключённый контейнер не участвует в штатном подсчёте, выборе, перемещении и объединении
стопок. Сама авторская операция остаётся в исходном моде. Ручные права FTB не меняются;
дружба/публичный ручной доступ не являются согласием на автономный перенос между командами.
Не следует распространять это правило на все моды, пока их пути отдельно не проверены.

Новые claims из очереди учитываются до операции; долговременного кеша разрешений нет.
Неподдерживаемый артефакт/API останавливает инициализацию. При ошибке адаптера целевая
операция закрывается для контейнеров и пишет одну ошибку в ограниченный серверный журнал;
положительные контроли проверяют, что это не подменяет работающую защиту общим отказом.

## Испытания

На изолированном Linux Forge / DJ2 RU 2.21.3 выполнены **219 проверок, 28 сценариев,
два старта с полным restart**. Контейнер: 6 ГиБ / 4 CPU, heap 4 ГиБ, закреплённая Java 8.

Проверены разрешённые и запрещённые направления, составные контейнеры, раздельные
участки, отрицательные координаты, разные измерения, смена владельца/команды, серверный
домен и claim, поставленный в очередь в том же серверном тике непосредственно до эффекта.
Общее число контрольных предметов сверяется до/после настоящей авторской операции.

Обычный non-OP игрок в survival установил выданный стендом блок, активировал его,
получил перенос через настоящий scheduled tick и выключил его. Это проверка использования
выданного предмета, **не** полного прохождения квестов/выращивания/получения предмета.
Протокольный игрок не является графическим Minecraft-клиентом.

Точный предмет, координаты, внутренние точки внедрения, драйвер и полные отчёты остаются
в приватной документации владельца. Публичная запись содержит только обезличенные итоги
и SHA256; Core и диагностический мод в этот репозиторий/лаунчер не попадают.
[Обезличенное сравнение](validation/dj2-autonomous-inventory-2026-11-02.json): старый
Core 0.2.6 прошёл 206 проверок **воспроизведения исходного поведения**, новый Core —
219 проверок защиты и положительных контролей на тех же 28 сценариях. Успех baseline
означает подтверждённый обход, а не безопасность старой версии. Счётчики предметов
сохранились: подтверждён не дюп, а неразрешённая операция.

Обычный запуск Core 0.2.7 **без диагностических модов** дополнительно прошёл
[50 проверок RTP](validation/dj2-rtp-core-0.2.7-2026-11-02.json): измерения, таймеры,
отказы, повторный вход, параллельные запросы и чистая остановка без OOM/фатальных
маркеров. Повторная сборка дала тот же SHA256 Core. Изменения интерфейса лаунчера
и развёртывание публичного сервиса в этот этап не входили.

## Эксплуатация и оставшаяся работа

Тесты используют новые миры и одноразовые аккаунты. После чистой остановки свой мир
экспортируется, затем удаляются только собственные временные сервисы/volume. Старые
серверы и миры не подключаются. Это не миграция работающего сервера и не готовность DJ2
к открытию. Остальные сценарии [#29](https://github.com/omkality/omkalitycraft/issues/29)
и [общего трекера](https://github.com/omkality/omkalitycraft/issues/41) остаются открытыми.
