# RTP в текущем измерении DJ2

1 ноября 2026 новый Linux Docker-стенд DJ2 RU 2.21.3 прошёл **50 проверок** на
приватном Core **0.2.5**. FTB Utilities 5.4.1.131 и FTBLib 5.4.7.2 сохранены.
Исходный сервер не менялся. Это реальные серверные действия протокольных игроков,
а не исполнение модов/рендеринг полноценного клиента.
Python/Qt: **502 passed, 3 Windows symlink skips**, Ruff/Black прошли.

## Как работает адаптер

При явном `config/omkalitycore-rtp.properties` Core перехватывает `/rtp` и его
штатные aliases. Назначение выбирается в **мире вызова**, без временного изменения
глобального FTB `spawn_dimension`. Права `command.ftbutilities.rtp`, warmup,
кулдаун и история успешного переноса принадлежат FTB. Повторный запрос ограничен;
отложенный callback проверяет актуальное подключение и тот же объект мира/измерение.
Переключение мира или старый отключённый игрок не могут запустить поиск в новом мире.

Разрешения задаёт [профиль измерений](../profiles/server-defaults/dj2/rtp.json):

| ID | Режим | Высота проверяемого пола |
| --- | --- | --- |
| `0` Overworld | Поверхность | 8…253 |
| `−1` Nether | Пещерная посадка | 8…120, под крышей |
| `7` Twilight Forest | Поверхность | 8…253 |

Остальные ID получают отказ, включая End, DivineRPG/AbyssalCraft/планеты и служебные
измерения. Это ограничение только `/rtp`, не замена авторских порталов/прогрессии.
Ресурсный мир ещё не создан; его профиль подключается после назначения ID и тестов.
Deep Dark остаётся отдельным кандидатом, пока не проверены его особенности.

Поиск учитывает настоящий центр WorldBorder, радиусы и отступ от границы. Квантование
координат до центра блока не позволяет выйти из заданного кольца. Выбирается полный
опорный блок и два воздушных блока над ним; рядом исключаются жидкости и несколько
ванильных опасных блоков. Все затронутые чанки проверяются на FTB claims, включая
очередь текущего тика. В surface-режиме алгоритм не ищет проход под неподходящей
поверхностью; в Nether допускает поиск воздушного кармана в заданном диапазоне Y.
Магма сохранена как ранее принятое владельцем ограничение; все модовые опасности
этими условиями не классифицированы.

Поиск запрашивает только уже сгенерированные чанки. Число проб и затрагиваемых чанков
ограничено; неудача выдаёт короткое сообщение и не запускает Teleporter FTB.
Собственный интервал повторов ограничивает повторный неудачный поиск. Полную
предгенерацию перед открытием нужно закончить заранее: успешная посадка вызывает
обычную загрузку окружения игроком, а загрузка сохранённого чанка исполняет хуки модов.
Предгенерация всего мира сейчас не выполнялась.

## Конфигурация оператора

[Пример env](../deploy/dj2-rtp.example.env). Python создаёт policy **эксклюзивно в новой
остановленной копии**; существующий файл не перезаписывает. Forge не читает env сам.

| Переменная | Default | Допустимо |
| --- | ---: | --- |
| `OMK_DJ2_RTP_MIN_DISTANCE` | 1000 | 0…100000, меньше maximum |
| `OMK_DJ2_RTP_MAX_DISTANCE` | 5461 | 1…100000 |
| `OMK_DJ2_RTP_BORDER_PERCENT` | 66 | 10…90 |
| `OMK_DJ2_RTP_ATTEMPTS` | 64 | 1…256 |
| `OMK_DJ2_RTP_CHUNK_LOADS` | 8 | 1…16 |
| `OMK_DJ2_RTP_RETRY_SECONDS` | 5 | 2…60 |
| `OMK_DJ2_RTP_PROFILE` | Вложенный JSON | Необязательный путь к JSON оператора |

Максимальный радиус: `min(maximum, diameter × border_percent / 200 − 2)`.
Если места для кольца нет, перенос отклоняется. Центр берётся из WorldBorder;
ванильная команда с целыми координатами может добавлять 0.5 к центру блока.
Профиль JSON ограничен 4096 байтами/8 уникальными измерениями, проверяет типы,
режим и высоты. Ошибки env не выводят ошибочно вставленное значение.

Без policy-файла старые стенды сохраняют штатный FTB RTP. При включённом адаптере
числовой диапазон/поиск из `ftbutilities.cfg` заменяются этой политикой; штатные
ранговые таймеры продолжают действовать. Ошибка адаптера блокирует RTP до исправления,
отката к небезопасному поиску в spawn dimension нет.

## Что проверено

- Настоящая посадка в том же Overworld, Nether и Twilight Forest; Nether — на Y66
  под существующей крышей Y127. Сценарий отдельно подтверждает пол и свободное место.
- Штатные warmup/cooldown/permission denial, повторный запрос и отмена при движении.
- Отказ для воды, неполного пола, слишком маленькой границы и полностью занятых claims.
- Ненулевой центр границы; дальняя несгенерированная область не создаёт region-файлов.
- Смена измерения во время ожидания, отказ End/неразрешённому зарегистрированному миру.
- Отключение/повторный вход без расходования кулдауна старым запросом.
- Два одновременных запроса в Overworld и Nether остаются независимыми; миры отдельно
  подтверждены серверным NBT, не только локальным счётчиком пакетов.

Площадки создаёт консоль в **контексте нужного измерения** после подтверждения загрузки
окружающих чанков. Игроки имеют обычные права FTB, creative нужен только для fixture.
Новые пробы используют кольцо **8…12**, контейнер **6 GiB/4 CPU**, Java heap **4 GiB**.
[Отчёт, позиции и SHA256](validation/dj2-dimension-rtp-2026-11-01.json).

```powershell
uv run omk lab dj2-rtp `
  --server-source ../omkality_server/divinejourney2 `
  --agent data/content/releases/dj2/windows-x64/files/agent/authlib-injector-1.2.8.jar `
  --core ../omkalitycore/build/OmkalityCore-0.2.5.jar `
  --mods-json .local/verified-client-mods.json
```

Отчёт и ограниченный журнал: `.local/rtp-dimensions-<id>/report.json` и
`server-output.log`. Временный Drasl удаляется; свой volume удаляется после экспорта
и подтверждённого clean exit. При краше/неизвестном результате чтения остаётся для
диагностики, имя записывается в `owned_volume_retained`.

## Остаётся до открытия

Полноценный клиент/физика, естественные поверхности/опасности модов, реальные радиусы
и нагрузка VPS, ресурсный мир, RTP после restart и более широкий набор конкурирующих
запросов остаются отдельными тестами. Все виды урона/истории `/back` не проверены заново.
Найденный [краш WR-CBE при остановке](validation/dj2-wrcbe-shutdown-crash-2026-11-01.json)
**ещё не исправлен**; успешный RTP не закрывает этот дефект. В последнем стенде
пустые измерения успели выгрузиться при работающем сервере и остановка прошла чисто.
