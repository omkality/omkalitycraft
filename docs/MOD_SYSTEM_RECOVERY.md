# Восстановление AE2-хранилища и накопителя EnderIO

Отдельный эксперимент `omk lab dj2-recovery --runtime linux-docker --mod-systems`
проверяет небольшой функциональный пример на текущем DJ2 RU 2.21.3 / Forge
14.23.5.2860. Это расширение лаборатории, не команда отката рабочего сервера.
Сценарий не совмещается с `--edge-cases` или `--full-backup-return`.

1 ноября 2026 выполнены **38 проверок**, все прошли: четыре старта, обычный и повторный
откат, функциональные проверки после restart и сверка сохранённого NBT. Сервер завершён
с кодом 0 / `OOMKilled=false`; мир экспортирован, собственный volume и временный Drasl
удалены. [Обезличенный результат](validation/dj2-mod-system-recovery-2026-11-01.json).

## Что проверяется

Выделение overworld: `(160,241,160)` — `(171,243,164)`, **180 блоков**. Исходная
папка сервера служит источником модов/конфигов; её миры и учётные данные не копируются.
Сервер и Drasl работают на ПК владельца в изолированных Linux Docker-контейнерах;
мир находится в новом Linux volume, Drasl — в tmpfs, порты только loopback.
Сервер ограничен 6 ГиБ / 4 CPU, Java heap 4 ГиБ, образ закреплён digest.

1. ME-сундук AE2 с ячейкой 1k принимает семь именованных алмазов через воронку,
   питаясь от соседней творческой энергоячейки. Это небольшой пример ME-сети,
   не проверка ME Drive, автокрафта или всех разновидностей ячеек.
2. Два Activated Capacitor Bank EnderIO образуют многоблочный накопитель и питают
   Thermal-печь. Печь действительно переплавляет cobblestone в stone. Перед снимком
   тест ждёт полного буфера печи, чтобы продолжающаяся зарядка не искажала сравнение
   энергии двух банков. Лимиты входа/выхода заданы явно: 1234/2345.
3. После чистой остановки сохраняется согласованная полная копия, из неё готовится
   отдельный WorldEdit-снимок только dimension 0. Затем те же типы блоков создаются
   пустыми: важно проверить восстановление содержимого, а не только замену воздуха.
4. Перед откатом повреждённое состояние тоже сохраняется после чистого stop;
   read-only preflight проверяет покрытие выделения. Обычный snapshot rollback и
   повторное применение проверяют предметы, энергию, лимиты и соседний сундук вне
   выделения. Нулевые счётчики WorldEdit дополняются проверками живого мира.
5. После ещё одного полного stop/start AE2 должна принять новый предмет, а
   восстановленный накопитель — снова питать печь с изначально пустым буфером.
   Сохранённый NBT отдельно сверяет полный инвентарь ME-сундука, энергию/лимиты
   каждого банка и полный NBT соседнего сундука.

В этом опыте четыре полных старта. Игровой наблюдатель проходит настоящий
Forge/Drasl-протокол, но не запускает графический Minecraft и клиентские моды.
Startup diagnostic agent в этом сценарии не используется.

## Артефакты и воспроизведение

Используются прежние JAR установленной сборки, без обновления/загрузки новых версий:

| Артефакт | SHA256 |
| --- | --- |
| `ae2-uel-v0.56.4.jar` | `3505d2e31e9c48a0c96ca058fcde8a6a50b7d673e13af488a398878d6d33b698` |
| `EnderIO-1.12.2-5.3.72.jar` | `9b5e7756af35a191de8bc8f010c0f7c7ffc2e1e056a69ec265d1dd5ce90d19b4` |

Пины проверяются до создания лаборатории. Forge/WorldEdit/Core остаются теми же,
что в [основном сценарии восстановления](REGION_RECOVERY.md); Core не публикуется.
Происхождение этих двух JAR — прежняя установленная DJ2 RU, не вновь проверенная
официальная загрузка. Хеши фиксируют именно исполняемые файлы опыта.

```text
uv run python -m omk lab dj2-recovery --runtime linux-docker --mod-systems --server-source PATH_TO_DJ2_SERVER --agent PATH_TO_AUTHLIB_1_2_8 --core PATH_TO_PRIVATE_CORE_0_2_3 --mods-json PATH_TO_VERIFIED_MOD_LIST --worldedit PATH_TO_WORLDEDIT_6_1_10
```

Нужен закреплённый образ из [SERVER_CONTAINERS.md](SERVER_CONTAINERS.md).
Состояние: `omkalitycraft/.local/recovery-status.json`; итоговый `report.json`,
`recovery-plan.json`, ограниченные журналы, `backups/`, `snapshots/` и `export/`
находятся внутри новой `omkalitycraft/.local/recovery-lab-<id>/`.
При штатном выходе собственный volume удаляется только после экспорта мира.
Исходные и сохранённые сбойные volumes других опытов не подключаются.

AE2 нельзя готовить к опыту записью `blockdata` поверх уже работающего узла:
это вызывает исключение загрузки NBT после присоединения к grid, причём часть данных
может уже измениться. Начальный NBT передаётся при создании нового блока.
[Guard в исходниках AE2 0.56.4](https://github.com/AE2-UEL/Applied-Energistics-2/blob/v0.56.4/src/main/java/appeng/me/GridNode.java).
WorldEdit соответствующего commit сначала удаляет старую tile entity, затем создаёт
новую из NBT; его путь проверяется отдельно, а не приравнивается к `blockdata`.
[ForgeWorld, commit e6b38e8](https://github.com/EngineHub/WorldEdit/blob/e6b38e8/worldedit-forge/src/main/java/com/sk89q/worldedit/forge/ForgeWorld.java).

## Границы результата

Успех относится к указанным блокам, версиям, одному небольшому выделению и штатным
остановкам. Крупные ME-сети, контроллеры/каналы, ME Drive, автокрафт, P2P/квантовые
мосты, трубы EnderIO, внешние части сетей за выделением, другие измерения и машины
требуют отдельных опытов. Игроки/дроп/перенос предметов между снимком и откатом
не покрыты проверкой отсутствия дюпов. Сущности, частичные архивы, аварийная остановка
посреди применения и безопасный эксплуатационный plan/apply остаются отдельными задачами.
