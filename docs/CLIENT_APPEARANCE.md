# Оформление лаунчера и DJ2

Пробный стиль **obsidian black + ice gray**, задача [#117](https://github.com/omkality/omkalitycraft/issues/117).
Основные цвета: фон `#0b0d10`, панели `#12161b`, светлые элементы `#dbe7f2`.
Rubik Bold и Monocraft для ника сохранены. Предупреждения остаются тёплыми,
ошибки и успешные состояния различимы; GTNH пока недоступна.

В лаунчере изменены палитра, карточки, ссылки, состояния кнопок, прогресс,
панель персонажа и компактная форма входа. На небольшом экране форма
прокручивается, сохраняя высоту полей; кнопка регистрации доступна прокруткой.
Сессии, загрузка сборок, проверка файлов и протокол авторизации не меняются.

## Меню и загрузка Minecraft

### Стартовые настройки игры

`profiles/client-defaults/dj2.json` задаёт `initial_options`: `bobView=false`,
`gamma=1.0`, `autoJump=false`, `guiScale=2`, `fov=0.25`. В DJ2 1.12.2 это отключённые
покачивание камеры и автопрыжок, яркость 100% и обычный масштаб интерфейса, поле зрения 80°. В `options.txt` Minecraft 1.12.2
поле зрения хранится как `(градусы − 70) / 40`, поэтому 80° соответствует `0.25`.

Лаунчер заполняет отсутствующие параметры в `options.txt` перед первым запуском.
Существующие значения не перезаписываются, в том числе при обновлении сборки.
При дополнении файла сохраняется резервная копия в `.omk-defaults-backups/`
внутри папки этой сборки. Карта JourneyMap по-прежнему получает пресет только
при отсутствии своего файла настроек.

Допускаются только перечисленные пять параметров с ограниченными типами и
диапазонами. Профиль не может через это поле включить fullscreen, поменять
произвольную настройку или добавить новую строку файла. Подписанный manifest
с `initial_options` должен указывать `minimum_launcher_version=0.3.0.dev13`
или новее. Старые профили остаются совместимыми.

Исчезновение курсора при F11 разбирается отдельно в [#182](https://github.com/omkality/omkalitycraft/issues/182).
Причина подтверждена в тестовом клиенте: процесс внешнего Windows-захвата
computer-use скрывал системный курсор. После его остановки обычный
эксклюзивный fullscreen, инвентарь, повторные F11 и Alt+Tab проверены владельцем.
Для игры используем MCMCP без Windows-захвата; проверявшийся безрамочный мод
в player profile не добавлен. Это не исправление Windows для любых сторонних
программ записи экрана.

### F11 и соседний монитор

По дополнительному запросу владельца отдельно принят безрамочный режим:
из инвентаря/меню Esc курсор выходит на соседний монитор, Minecraft остаётся
развёрнутым. Во время обычной игры камера использует стандартный захват мыши.
Проверен готовый **FullscreenWindowed-1.12-1.6.0-1.jar** от comp500/Brycey92/hancin,
мод `fw=1.6.0`, а не современная Fabric-версия Borderless Mining.

Точный JAR, источник и лицензия закреплены в
[`borderless.json`](../profiles/client-addons/forge-1.12.2/borderless.json).
Тестовый сервер использует строгую политику с добавленным `fw=1.6.0`.
При выпускной композиции нужно включить JAR и notice, пересобрать такую же
политику сервера и проверить подписанный manifest. Сам профиль ничего
не скачивает и не активирует в выпущенной сборке.

У мода по умолчанию включены безрамочный режим, совместимый порядок запуска и
выбор текущего монитора (`fullscreenMonitor=0`). Его `config/fw.cfg` оставляем
личным: выбор монитора не должен сбрасываться при каждом запуске.
Нативная проверка выполнена на Windows x64 с Linux Docker-сервером;
Linux/macOS-клиенты этим результатом не объявляются принятыми.
Протокол: [проверка курсора и мониторов](validation/client-cursor-2026-11-14.json).

### Оформление экранов

Python подготавливает отдельный overlay, который пока **не включён в player release**:

```powershell
python scripts/build_client_appearance.py `
  --output .local/appearance-review-new `
  --pack-version 2.23.4 `
  --legacy-backgrounds <архивный-клиент>/resources/mainmenu/background `
  --modpack-config <исходный-клиент>/config/endermodpacktweaks/modpack.cfg `
  --minecraft-jar <исходный-клиент>/versions/1.12.2/1.12.2.jar
```

Выходной каталог должен быть новым. Команда не применяет оформление к установленной
сборке, не меняет manifest и не переносит миры/учётные записи. Исходные картинки
сохраняются; их размер остаётся прежним, тонированные копии идут в overlay.
Без `--legacy-backgrounds` используется простой тёмный фон. Архивные картинки,
моды и payload сборки в Git не добавляются. В receipt записаны SHA файлов и inputs.

Главное меню использует имеющиеся **Custom Main Menu 2.0.9.1 / ResourceLoader 1.5.3**:
центральные кнопки, плавная смена старых пейзажей, только центрированная надпись
OMKALITYCRAFT без блока руды. Название/версия сборки берутся из параметра staging.
Кнопки имеют обычное и hover-состояние, подписи/авторство сохраняются.

Стандартные настройки, звук, список серверов/миров/модов получают общие
кнопки и obsidian-фон через ResourceLoader. Раскладка и обработчики экранов
сохраняются. `--minecraft-jar` проверяется по точному SHA; в atlas меняются
только три полосы кнопок. Прочие пиксели, включая HUD/hotbar, сохраняются.
Сгенерированный atlas с исходными игровыми пикселями остаётся вне Git.
Специальные интерфейсы модов со своими текстурами требуют отдельных решений.

На загрузке — руда и OMKALITYCRAFT. Числа остаются светлыми, заливки прогресса
и памяти затемнены. Проверка контраста требует не менее 4.5:1 для фона,
незаполненной/заполненной полосы и всех трёх состояний памяти.

Forge **14.23.5.2860** жёстко выбирает центральную Mojang texture, запрещает для
неё resource-pack override и окрашивает её цветом фона. Поэтому одного
`splash.properties` для смены центральной картинки недостаточно.
Клиентский приватный адаптер добавляет два необязательных cosmetic hook:
выбор локальной картинки и нейтральный tint. Включение в проверенном профиле:
`-Domkality.appearance.forge112=true`. По умолчанию оформление выключено;
очереди загрузчика/таймеры/рендерер полос не заменяются. Сетевые классы адаптера
не меняются. Это отдельная приёмка, не доказательство готовности player release.

При первом опыте hook ошибочно нацелился на другой anonymous class Forge и
остановил запуск. Причина установлена по журналу и методам закреплённого JAR;
исходный неуспешный опыт сохраняется. Исправленный кандидат прошёл отдельную
нативную загрузку и навигацию; сборка теперь проверяет методы cosmetic target
в закреплённом JAR до компиляции и отклоняет первоначальный ошибочный класс.
Не переносить неуспешный JAR в выпуск сборки.

Источники механизма:
[Forge SplashProgress](https://github.com/MinecraftForge/MinecraftForge/blob/1.12.x/src/main/java/net/minecraftforge/fml/client/SplashProgress.java),
[Custom Main Menu](https://github.com/lumien231/Custom-Main-Menu).
Рабочие runtime-версии закрепляются входными SHA, а не состоянием этих веток.

## Список серверов

DJ2 2.23.4 добавляет `[Featured] Pixel Gaming (PvE/EU)` через настройку
`default_server` в `config/endermodpacktweaks/modpack.cfg`. Это сторонний сервер
из исходной сборки, он не относится к проекту OmkalityCraft.

Если передан `--modpack-config`, staging выключает эту функцию и очищает её
адрес/название, сохраняя остальные настройки мода. Это не замена полного конфига
минимальным файлом. Установленная раньше запись в `servers.dat` требует отдельной
точечной миграции по адресу; пользовательские серверы удалять нельзя.
Наш список по-прежнему управляется подписанным `client_defaults.servers`.

Этот же штатный мод задаёт иконку окна (квадратный canvas без растяжения
исходного блока) и заголовок `OmkalityCraft · Divine Journey 2 · <версия>`
для английского и русского языков. Новый Java hook для этого не нужен.
Выбранная владельцем исходная текстура сохранена.

## Проверки и следующие шаги

- Qt: вход, регистрация, сборки, загрузка и малый размер отрисованы с временным
  FakeDrasl и отдельным session store. Это не production-аккаунт и не тест сети.
- Windows portable EXE собирается обычным build-скриптом; smoke открывает
  настоящий packaged Qt в новом временном root и проверяет health acknowledgement.
  Локальный preview настроен на недоступный loopback endpoint и не является
  публичным игровым выпуском.
- DJ2: отдельный renderer-only клиент, без серверного подключения и без мира.
  Меню проверяется через MCP; этот опыт не проверяет серверную авторизацию,
  игровой баланс или renderer Linux/macOS. Серверные тесты остаются в Docker.
- Итог: 56 focused Python/Qt тестов; 14 Java helper-проверок, две проверки ABI
  cosmetic target и отрицательный контроль первоначального класса. Семь прежних
  сетевых Java-классов byte-identical, повторная сборка дала тот же SHA.
  Windows DJ2 прошла главное меню/настройки/звук/серверы/выбор мира/моды;
  итоговый клиент закрылся с exit 0, новых crash reports нет. Заголовок окна
  подтверждён из метаданных процесса; загрузку/меню визуально оценил владелец.
  Один промежуточный опыт после успешной загрузки остановлен принудительно из-за
  ошибки timeout cleanup в одноразовом harness; он не считается clean-exit проверкой.
- После визуальной приёмки: подписанный pack release с новым набором SHA,
  проверка установки/обновления/восстановления файлов и графические три ОС.
  Косметика не блокирует продолжение ресурсного reset и запуск сообщества.

По новому решению владельца будущие серверы проекта — **PvP, Hard**:
`pvp=true`, `difficulty=3` для Forge 1.12.2; эквивалентные настройки для других
версий. В deployment-приёмке нужно проверить также переопределения сложности
из модов/измерений. Этой задачей действующие server.properties и миры не меняются.
