# Восстановление аккаунта: проверка Drasl и игрового подключения

Задача #35. Это лабораторная проверка и проект будущей утилиты владельца.
**Готовой production-команды сброса пароля пока нет.** Рабочие аккаунты, миры и
лаунчер не менялись; новый интерфейс игрока не добавлялся.

## Что различаем

- Одноразовое приглашение разрешает регистрацию. После потребления оно не
  управляет доступом уже созданного аккаунта и не заменяет бан.
- UUID аккаунта Drasl отличается от UUID игрового профиля. Восстанавливаем
  существующий аккаунт, сохраняя профиль, инвентарь, команду, приваты и дома.
- Игровой bearer token из переносимого лаунчера не является API token владельца.
  Для административного PATCH нужен отдельный Drasl admin credential.
- Отзыв токенов запрещает следующие проверки авторизации. Уже установленное
  игровое подключение обслуживает Minecraft; ему требуется отдельное отключение.

В закрытом тесте admin PATCH меняет пароль с `resetApiToken=true` и
`resetMinecraftToken=true`. Проверяются два прежних игровых клиента, API credential,
старый/новый пароль, отказ настоящего Forge-входа по старому токену, забывание
отозванного входа настоящим `AccountService`, блокировка/разблокировка и повторный
сброс. Игрок не получает OP. Management credentials/пароли остаются в памяти
теста; переносимые game tokens записываются только в свежие папки стенда.

## Результат 6 ноября 2026

DJ2 2.23.4 / Core 0.2.9 прошёл **44 native серверных/HTTP условия** за один старт.
Reset и lock отдельно оставили уже вошедшего игрока подключённым: он получил
контрольное сообщение после операции. Явный console kick действительно отключил
его. Старые refresh/validate/join отвергнуты; после unlock прежние токены не ожили.
Вход с новым паролем прошёл настоящий Forge handshake, сохранил UUID и рабочий
home. Повторный сброс отверг предыдущий пароль и снова сохранил инвентарь/уровни.

**8 независимых проверок** остановленного архива подтвердили SHA, те же UUID,
семь изумрудов, 12 уровней, владельца команды, единственный исходный claim и home.
Файлы reader не менял. Server stop чистый, fatal=false / OOM=false; собственные
volume/auth удалены после экспорта. Среда: закреплённый Linux Java 8u504, 4 CPU /
6 ГиБ container / 4 ГиБ heap. Графическая игра/полный restart здесь не проверялись.

Три ранние попытки не приняты: ожидание FTB UI-notification как chat (6 условий),
ошибочное имя поля результата probe (22), неверный NBT-тип Count (24). Во всех
случаях Minecraft остановлен чисто, без fatal/OOM. В последнем случае reader
подтвердил сохранность вещей: в этой сборке Count — int, Slot — byte. Исправлены
проверки, игровые данные не правились. Принят полный свежий повтор на финальном коде.

Focused unit/lifecycle: Windows и Linux Docker по 76 passed. Полный Windows unit
suite до последнего исправления NBT-fixture: 715 passed / 6 skips; на финальном
коде повторён focused набор. Это mocked lifecycle, не дополнительные game tests.
[Обезличенное доказательство с точными commit/hash](validation/dj2-account-recovery-2026-11-06.json).

## Повторение стенда

```powershell
uv run omk lab dj2-account-recovery --server-source PATH_TO_APPROVED_SERVER --agent PATH_TO_AUTHLIB_INJECTOR --core PATH_TO_PRIVATE_CORE --mods-json PATH_TO_EXPLICIT_LAB_MOD_LIST
```

Нужны заранее проверенные DJ2/Forge/Core JAR, Docker и свободные loopback-порты
25576/25586, общие с остальными игровыми стендами. Команда создаёт случайные
собственные Compose project/volume и новые временные Drasl аккаунты. Она не
выбирает работающий сервер и не принимает UUID реального игрока. После игры
требуются чистый stop, отсутствие fatal/OOM, проверенный export и auth cleanup.
Неудавшийся сценарий не становится успешным из-за чистого завершения процесса.

Локальные материалы: `.local/account-recovery-<id>/report.json`, `status.json`,
`server-output.log`, `export/world-after.tar`. Там есть приватные игровые данные;
не публиковать каталоги целиком. В stdout/report нет токенов, паролей и HTTP bodies.
Unit-тесты моделируют ошибки lifecycle/сети; настоящий Forge/Drasl проверяется
отдельным запуском этой команды. Графический клиент здесь не запускается.

## Порядок будущей административной операции

1. По доверенной переписке установить владельца. Получить существующий account
   UUID и все связанные игровые UUID; сформировать проверяемый план всех серверов.
2. Заблокировать аккаунт и подтвердить состояние: это закрывает гонку нового входа
   во время восстановления. При неизвестном результате запроса не объявлять успех.
3. Сгенерировать новый пароль, изменить его и отозвать API/Minecraft credentials.
   Не пересоздавать профиль и не менять UUID. Секрет не попадает в аргументы,
   конфигурацию лаунчера, журналы или обычный JSON-отчёт.
4. Через проверенный серверный адаптер отключить все подключения связанных UUID
   на всех серверах проекта и подтвердить результат. Одного Drasl PATCH мало.
5. Разблокировать только после успешной сверки. При недоступном сервере или
   неоднозначном результате оставить операцию незавершённой и аккаунт закрытым.
   Новый пароль передаётся владельцу приватно; повтор после сбоя требует явного
   восстановления операции, а не бесконтрольной генерации новых паролей.

Утилите ещё нужны bounded журнал стадий без секретов, обработка повторов/сбоев,
контроль всех серверов и безопасная однократная выдача нового пароля. Эти пункты
остаются в #35. Проверенный вручную console kick в изолированном стенде не
подменяет этот административный адаптер. Почта/Telegram-авторизация не добавляются.
