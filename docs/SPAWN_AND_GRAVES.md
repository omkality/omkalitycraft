# Спавн FTB и возврат вещей из могилы DJ2

Этот этап касается DJ2 RU 2.21.3, Forge 14.23.5.2860, FTBU 5.4.1.131,
FTBLib 5.4.7.2 и Tomb Many Graves 4.2.0. GTNH и ресурсный мир пока не проверены.
Публичный сервер не изменяется и ещё не открыт.

1 ноября 2026 завершены **70 проверок и два старта** полного DJ2 в Linux Docker.
Первый старт проверил пустой OP-список, обе границы/внешние контроли, запрет claim/unclaim
и вступления в server-team, TNT и два возврата могил. Второй подтвердил 1444 существующих
server-claims, защиту после restart и сохранность личного claim. После restart PlaneFix
повторно добавил служебный OP: он снят отдельной проверкой. Сохранился экспорт мира,
игровой контейнер и временный Drasl штатно закрыты, только собственный volume удалён.
[Обезличенный отчёт и SHA256](validation/dj2-spawn-graves-2026-11-01.json).
Python/Qt: **478 passed, 3 Windows symlink skips**; Ruff/Black прошли.

## Устройство защиты

Приватный Core 0.2.4 получает явный `config/omkalitycore-spawn.properties`
в новой остановленной копии. При запуске он резервирует спавн за серверной
FTB-командой `omk_spawn`, без членов, владельца и свободного вступления. FTB продолжает
владеть защитой блоков/взрывов и хранением claims; отдельной БД нет.

Overworld: запрошенный квадрат X/Z −300…300 включительно покрывают **1444 чанка**,
фактические края **−304…303**. Это только записи claims, не предгенерация и не
принудительная загрузка этих чанков. Личные квоты игроков не расходуются.
Ресурсный ID ещё не назначен, его зону −100…100 не подменяем старым модовым миром.

Python `omk.dj2_spawn_policy.write_spawn_policy` эксклюзивно создаёт файл в offline
staging. `OMK_DJ2_SPAWN_RADIUS`: default 300, допустимо 1–768. Некорректное значение
отклоняется без вывода его содержимого; существующий policy-файл не перезаписывается.
Старые стенды без файла сохраняют прежнее поведение. Автоматического применения к
существующему серверу нет.

Core проверяет версию адаптера, формат/размер/бюджет политики, доступность измерения,
существующие claims и права server-team. Чужая территория или неожиданная политика
останавливают инициализацию; автоматического захвата, снятия старых claims и уменьшения
защиты при сокращении радиуса нет. Проверка конфликтного запуска и других измерений
должна быть отдельно зафиксирована до эксплуатационного применения.

## Могилы

Требование владельца: после возрождения игрок возвращает свои вещи через **Shift**
даже внутри чужого или серверного привата. Посторонний, включая хозяина территории,
не должен получать содержимое чужой могилы.

По исходникам установленной ветки Tomb Many Graves обработчик столкновения проверяет
владельца/друзей самого мода и приседание; ломать блок для возврата вещей не требуется.
FTB-исключение для всех взаимодействий с могилами не добавлялось. В исходном конфиге
`requireSneaking=true`, `allowGraveRobbing=false`, `defaultToLocked=false`,
`dropItemsOnGround=false`. Дружба TMG — отдельное добровольное разрешение, не членство FTB;
лабораторные аккаунты не являются друзьями.

Сценарий создаёт могилу **настоящей смертью**, а не консольной подменой tile entity:
17 именованных алмазов → смерть → возрождение без них → отказ постороннему с Shift →
без Shift могила остаётся → Shift владельца возвращает ровно эти вещи и убирает могилу.
Проверяются чужой обычный claim и server-owned спавн. Штатный режим сохранения вещей
и новые профили доступа в рабочем сервере не менялись.

## Повторение опыта

```powershell
uv run omk lab dj2-spawn `
  --server-source ../omkality_server/divinejourney2 `
  --agent data/content/releases/dj2/windows-x64/files/agent/authlib-injector-1.2.8.jar `
  --core ../omkalitycore/build/OmkalityCore-0.2.4.jar `
  --mods-json .local/verified-client-mods.json
```

Только новая `.local/spawn-policy-<id>` и свой Docker volume; Drasl временный,
listeners loopback. Linux Java 8 закреплена digest, контейнер 6 GiB/4 CPU, heap 4 GiB.
Консоль создаёт площадки и выдаёт fixture-предметы; протокольные игроки исполняют
действия настоящего сервера, но не рисуют GUI и не запускают клиентские моды.
Отчёт и серверный журнал сохраняются в этой папке; сессии в Git не попадают.

Начальные пробы выявили две ошибки fixture: недогруженные чанки не позволяли создать
площадку, а Underground Biomes подменял vanilla stone. Сценарий сначала переносит
игрока/загружает место, проверяет существование bedrock-площадки и wool-мишени,
а затем выполняет действия. Контроли снаружи обязаны разрешать ломание и установку.

## Особенность PlaneFix

Установленный PlaneFix 1.0.0 при старте выдаёт OP **служебному** профилю `[Minecraft]`.
Это не игровой аккаунт и не зарегистрированный пользователь. В одноразовом стенде
перед первой проверкой снимаются права только у точного известного UUID/имени/уровня;
при неизвестной/человеческой записи сценарий отказывает. Затем подтверждается пустой
OP-список. После restart PlaneFix снова добавляет запись, что учитывается отдельно.
Исходный JAR не удаляется, а эксплуатационная политика AE2 этим не определяется.

Авторский артефакт: [PlaneFix 1.0.0](https://www.curseforge.com/minecraft/mc-mods/planefix/files/2703755),
SHA256 `7aceca6356b0a7a1a970298081c60135bb458d7780bf1058694c1f0eb8a5172f`.
До открытия отдельно испытать planes/автоматизацию через границу чужого и серверного
FTB-claim; снятие OP служебного профиля без проверки может менять поведение AE2.

Исходники могил:
[TombManyGraves2, snapshot f98cfdb](https://github.com/M4thG33k/TombManyGraves2/tree/f98cfdbec9aa38674e9489b82ae3ad135d0b0b77).
[Артефакт 4.2.0](https://www.curseforge.com/minecraft/mc-mods/tomb-many-graves-2/files/2619249).
Версия исходников не заменяет реальные тесты установленного JAR.

## Ограничения

Не заявляются защита от всех модовых прямых записей/взрывов, fluids/поршней/деревьев,
возврат всех baubles/инвентарей/XP, locked/friends-могилы, могилы в пустоте/лаве,
полный диск/перезапуск между смертью и получением вещей и графический клиент.
Ресурсный мир, spawnpoint/постройка спавна и перенос на VPS остаются отдельными этапами.
