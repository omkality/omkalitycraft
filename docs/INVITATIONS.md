# Одноразовые приглашения в проект

Решение владельца 4 ноября 2026: ключ нужен только для первой регистрации.
Тот, кто первым **успешно зарегистрировался**, получает обычный постоянный аккаунт.
Использованный код сгорает. Ключ не требуется для последующих входов и не привязан
к аккаунту пожизненно. Вход запоминается игровой сессией, отдельно от приглашения.

До использования владелец может отозвать код через `omk admin … access revoke-invite`.
После использования код уже отсутствует: попытка отзыва сообщает об этом и не блокирует
аккаунт. Бан игрока/отзыв его сессий — отдельная административная операция.
Почта, привязка Telegram и автоматизация выдачи сейчас не требуются.

## Розыгрыш на стриме

1. Создать один код командой `access invite` из [инструкции владельца](ADMIN.md).
2. Открыть указанный закрытый JSON и самостоятельно скопировать только `code` в чат.
3. Игрок использует код в регистрации лаунчера. Победитель — успешно созданный аккаунт;
   остальные получают отказ и второй аккаунт по этому коду создать не могут.
4. Если розыгрыш отменён до активации — отозвать именно этот файл приглашения.

Публичную отправку кода утилита автоматически не делает. Для индивидуальной проходки
владелец так же самостоятельно передаёт код в личной переписке. Утёкший уже активированный
код больше никого не зарегистрирует; разбор того, кому он достался, остаётся у владельца.

## Конкурентная одноразовость

Последовательный reuse-тест был недостаточен. На свежем неизменённом Drasl 4.0.0
конкурентный контроль обнаружил более одного аккаунта по одному коду. В образ
`4.0.0-omk.1` добавлена проверка успешного потребления приглашения внутри транзакции,
без изменения схемы БД или реализации паролей/токенов. [Исходники и сборка](../deploy/drasl/README.md).

В новом Linux Docker-стенде проверены:

| Условие | Результат |
| --- | --- |
| 20 раундов по 2/4/8 одновременных регистраций | 64 попытки, 20 аккаунтов, по одному на код |
| Реальные пользователи и профили | В БД/API ровно один победитель; проигравшие не могут войти |
| Повтор с другим ником по использованному коду | Отказ |
| 20 гонок регистрации и отзыва | Один согласованный исход: либо отзыв и отсутствие аккаунта, либо регистрация и отсутствующий код |
| Уже завершённая регистрация выиграла гонку | Аккаунт остаётся действующим, отзыв старого кода его не блокирует |
| Невалидная регистрация | Код остаётся доступным для корректной попытки |
| Перезапуск auth-контейнера с отдельным volume | UUID, профили и сессии 20 победителей сохранены |
| Другое неиспользованное приглашение | Работает после restart |
| API/скины/Yggdrasil, expiry, owner CLI/inbox | Отдельные 18 / 6 / 16 условий на исправленном образе |

Для независимой проверки транзакции только в concurrency-стенде поднят HTTP rate limit;
production/default лимиты не ослаблялись. Первый прогон при обычном лимите дошёл до
12 парных раундов и получил 429 при расширении нагрузки — он не принят как полный.
В части гонок отзыв намеренно задержан, чтобы проверить также завершение регистрации
до отзыва; это управляемый порядок акторов, а не измерение сетевой задержки.

[Закреплённые результаты/hash](validation/atomic-invitations-2026-11-04.json).
Подробный конкурентный fixture и закрытые тестовые файлы остаются локальными.
Реальные аккаунты не участвовали; собственные containers/volume удалены после проверки.
Публичный auth-сервис не развёрнут, новый Minecraft-клиент этим API-тестом не запускался.
