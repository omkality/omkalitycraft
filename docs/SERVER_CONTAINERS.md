# Серверные проверки в Linux Docker

Целевая среда игрового сервера — Linux amd64 в Docker на VPS. Нативный Windows Forge
остаётся полезным для отладки, но его успешный тест не считается проверкой Linux.
Windows, Linux и macOS как клиентские ОС проверяются отдельно.

## Что уже воспроизведено

1 ноября 2026 полный DJ2 Forge 1.12.2 / 14.23.5.2860 запущен в Linux-контейнере
Docker Desktop. Мир находится в новом named volume внутри Linux, с проверкой
регистрозависимости файловой системы, а не в Windows bind mount.
Закреплён официальный образ
`eclipse-temurin:8-jre@sha256:377fe8e36a4b1530d9d52020069367ef44313fa891a82ae102b1016a6a3a72f5`;
исполненная Java — Temurin 8u504-b01. Источник образа:
[Docker Official Image](https://hub.docker.com/_/eclipse-temurin).

Проверены запуск полного Forge, настоящий протокольный вход и вход полноценного
Windows DJ2 с отдельной Java и свежей папкой клиента. Drasl работает в другом
Linux-контейнере; `online-mode=true`, authlib-injector 1.2.8 и приватный Core 0.2.3.
После проверки сервер штатно остановлен, мир экспортирован с SHA256, временные
контейнеры и volume удалены. [Машиночитаемый результат](validation/dj2-linux-docker-2026-11-01.json).

Захват окна клиента дважды завершился `FrameArrived timed out` / `window capture
timed out`. В следующем прогоне использована штатная F2 самого Minecraft через
Computer Use: сохранённые игрой PNG осмотрены напрямую. Подтверждены стандартный Slim,
второй игрок после трёх вариантов загрузки/переподключения, квадратная миникарта без
сетки и читаемая русская надпись инвентаря. Кеш клиента содержит точные SHA256 всех
трёх PNG. [Отдельные кадры и результат](validation/dj2-skin-visual-2026-11-01.json).
Это не исчерпывающая проверка всех ракурсов и произвольных скинов. Полная карта и
меню списка серверов визуально ещё не проверены.

## Воспроизведение

Сначала загрузить именно закреплённый образ:

```text
docker pull eclipse-temurin:8-jre@sha256:377fe8e36a4b1530d9d52020069367ef44313fa891a82ae102b1016a6a3a72f5
uv run omk lab dj2-linux --help
uv run omk lab dj2-linux --server-source PATH_TO_DJ2_SERVER --agent PATH_TO_AUTHLIB_1_2_8 --core PATH_TO_PRIVATE_CORE_0_2_3 --mods-json PATH_TO_VERIFIED_MOD_LIST
```

Для настоящего графического клиента добавить `--client-source` с папкой файлов
подписанного релиза для текущей настольной ОС и `--manifest` с этим manifest.
Все перечисленные файлы проверяются по подписанным SHA256 и копируются в новую
папку; пользовательские миры, сессии и настройки прежнего клиента не импортируются.
`--visual-seconds` ограничивает время просмотра (0–1800 секунд).

Порты стенда опубликованы только на `127.0.0.1`: игра 25576, Drasl 25586. До запуска
они должны быть свободны. Внутри Docker сервер обращается к Drasl по имени сервиса;
его публичные discovery/texture URL отдельно доступны настольному клиенту.
Память контейнера ограничена 6 ГиБ, Java heap — 4 ГиБ, CPU — 4. Это параметры
лаборатории, а не рекомендации для рабочего тарифа.

Результаты и ограниченные журналы остаются в новой `.local/linux-skin-lab-*`.
Файл `finish-visual-checks` в этой папке завершает просмотр. Удаление разрешено
только для ресурсов с уникальной меткой текущего запуска; чужой volume отклоняется.
При неудачном экспорте тестовый volume сохраняется для расследования.

## Что ещё нужно подтвердить

Дополнительно прошёл отдельный Linux `--mod-systems`: 38 проверок небольшого
ME-хранилища AE2 и двухблочного накопителя EnderIO, повторного отката и работы
после четвёртого старта. [Версии/команда/границы](MOD_SYSTEM_RECOVERY.md).

- В Linux повторены 93 проверки восстановления области: контейнеры/печь/NBT,
  соседние изменения, undo/redo, сущности, неполный снимок и полноценные restart.
  [Результат](validation/dj2-linux-region-recovery-2026-11-01.json),
  [команда](commands/dj2/TESTING.md). Прежние 111 проверок полного возврата мира —
  Windows; Linux replacement volume ещё не поддержан. Полные команды/приваты отдельно.
- Для непостоянного ItemBlock/ThaumcraftFix startup crash получен конфигурационный
  обход: новые DJ2 lab/staging-копии отключают только `optimizeFMLRemapper` FermiumASM 5.24.
  Парный контроль: с `false` 6 стартов, после возврата `true` тот же сбой на первом.
  Без диагностического агента прошли 4 старта и 93 проверки восстановления области.
  Исходный сервер и сбойные volume сохранены; первоначальный триггер Mixin не исправлен
  upstream. Длительный/нагрузочный прогон ещё нужен.
  [Диагностика, память, env и границы вывода](DJ2_STARTUP_DIAGNOSTICS.md).
- Испытать аварийный stop/kill и восстановление согласованного снимка, заполнение
  диска, права файлов, ротацию всех используемых журналов и длительный запуск.
- Подготовить рабочий Compose: отдельные постоянные данные, непривилегированный
  пользователь, секреты, healthcheck, политика restart и проверенное выключение
  до резервного копирования. Лабораторный `docker run` не является production deploy.
- На выбранном VPS проверить реальный диск/CPU/лимиты, задержки и доступность из РФ,
  HTTPS, публичную авторизацию и вход приглашённого игрока. Docker Desktop на WSL2
  даёт настоящую Linux-среду процесса, но не воспроизводит нагрузку и сеть VPS.

Аренда VPS для этих локальных проверок пока не требуется. Рабочие миры и действующие
сервисы стенд не подключает. GTNH требует собственного образа Java и отдельных тестов.
