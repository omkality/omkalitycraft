# Сквозной тест клиентского краша

Проверка от 1 ноября 2026: **27 условий прошли**. Настоящий графический Windows-клиент
DJ2 RU 2.21.3 вошёл на полный Forge 1.12.2 / 14.23.5.2860 в Linux Docker. Затем
тестовый агент попросил Minecraft создать crash-report через его собственный обработчик.
Это управляемый сбой для проверки доставки, а не самопроизвольный баг игрового мода.

FermiumASM оставил процесс игры работать на экране ошибки. Отчёт был сохранён ещё при
работающей Java, с `process_state=running` и `exit_code=null`. API в этот момент был
остановлен. После запуска API на прежнем адресе и штатного закрытия игры (exit 0)
GameRunner автоматически повторил доставку: Drasl подтвердил UUID/имя, сервер принял
один отчёт, локальный JSON удалился только после подтверждения. Повторного отчёта
при выходе не появилось. Чтение inbox игровым токеном отклонено; `omk admin reports
list/export` создали закрытые файлы владельца.

Проверено отсутствие тестового маркера секрета, реальных игровых токенов стенда,
локальных путей и секции System Details в коротком отчёте. Исключение и его стек
сохранились. Полный необработанный crash-report остался только в локальной игровой папке.
Политика лимитов и точные пути — в [LOGGING.md](LOGGING.md) и основном [README](../README.md).

## Воспроизведение

Из корня репозитория, при уже подготовленных проверенных локальных артефактах:

```powershell
uv run omk lab client-crash --server-source ../omkality_server/divinejourney2 --agent data/content/releases/dj2/windows-x64/files/agent/authlib-injector-1.2.8.jar --core ../omkalitycore/build/OmkalityCore-0.2.3.jar --mods-json .local/verified-client-mods.json --client-source data/content/releases/dj2/windows-x64/files --manifest data/content/releases/dj2/windows-x64/manifest.json --compiler ../omkalitycore/tools/ecj-3.26.0.jar
```

Все аргументы обязательны; `--help` показывает их список. Нужны Docker Desktop с Linux
контейнерами, графическая Windows-сессия и достаточно ресурсов для DJ2. Порты стенда
25576/25586 должны быть свободны. Серверный источник копируется без прежнего мира,
паролей и списков игроков. Клиент клонируется из файлов подписанного релиза с проверкой
размеров/хешей; изменять рабочую установку для теста не требуется.

В `.local/client-crash-lab-<id>/` создаются отдельный клиент, очередь, private inbox,
операторские файлы и `report.json`. Текущая фаза записывается в
`.local/client-crash-status.json`. Drasl использует уникальный Compose-проект и tmpfs;
полный Forge — отдельный Linux named volume. Granian API работает на Windows loopback,
на случайном порту. При восстановлении API тест занимает тот же принадлежащий ему порт.
Это не испытание производственного API-контейнера или VPS-сети.

После успеха игра и сервер штатно останавливаются, новый мир экспортируется, принадлежащие
стенду контейнеры/volume/API удаляются. При раннем отказе неполученный экспорт не заменяется
удалением мира: Linux-стенд сохраняет volume и указывает его в локальном отчёте.
Локальные raw-файлы/экспорты не публикуются в Git.

## Тестовый агент и границы

`tests/fixtures/ClientCrashAgent.java` компилируется только для этого стенда отдельным
ECJ **3.26.0**, SHA256
`ac0ba5876eaf7ebb47749a0d1be179c51f194b9dd0b875d1c09e1b530f5a2db5`.
Источник: [Maven Central](https://repo.maven.apache.org/maven2/org/eclipse/jdt/ecj/3.26.0/ecj-3.26.0.jar).
Компилятор с другим хешем отклоняется до выполнения Java. Агент подключает только
lab-подкласс GameRunner; обычный лаунчер его не добавляет. Lab-модули и Java fixture
не входят в allowlist игрокового дистрибутива. Подписанный payload, состав модов и
закрытый OmkalityCore не меняются. Хеши исходника и собранного агента записаны в отчёт.

Первый прогон воспроизвёл недостаток старого сборщика: отчёт появился только после
принудительного закрытия Minecraft. Новый watcher устранил задержку в повторном
27-сценарном прогоне. Unit-тесты отдельно проверяют растущий файл, несколько инцидентов
одного запуска, отказ диска, атомарную публикацию очереди и старую schema 1.

Не проверены этим тестом: падение драйвера/JVM, OOM/SIGKILL/отключение питания,
падение самого лаунчера, графические клиенты Linux/macOS, публичная сеть и все возможные
секреты в произвольном стороннем тексте. Непостоянный сбой Linux-сервера при старте
ThaumcraftFix/Forge остаётся отдельной открытой проблемой; успешный crash-lab его не исправляет.

Машиночитаемое подтверждение: [client-real-crash-2026-11-01.json](validation/client-real-crash-2026-11-01.json).
