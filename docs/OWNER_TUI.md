# Терминал владельца

Для рабочего VPS откройте `OmkalityCraft-TUI-VPS.exe` на рабочем столе.
Он подключается по настроенному SSH-профилю владельца и запускает TUI на сервере.
После обновления серверной части закройте старое окно и откройте EXE снова.
Доступ дают SSH-ключ и права учётной записи ОС. RCON, конфиги и ключи остаются
на сервере. Административные действия выполняются через этот терминал, список
игровых OP пуст.

## Клавиши

| Клавиша | Действие |
| --- | --- |
| `←/→` | Выбрать сервер |
| `1` / `2` | Игроки проекта / Forge TPS по измерениям |
| `3` | Открыть список серверов для сохранения мира. Сейчас `1` сохраняет DJ2 |
| `4` | Активные баны и муты с поиском и фильтрами |
| `5` | Почасовые резервные копии и состояние передачи на Windows |
| `6` | Полученные краш-отчёты игроков |
| `k` / `b` / `m` / `s` | Кик / бан / мут / статистика игрока |
| `i` / `l` | Выдать приглашение / открыть список активных |
| `w` | Выбрать мир для вайпа |
| `r` / `t` | Обновить обзор / выбрать период TPS |
| `Esc` | Назад. В главном меню — подтверждение выхода |

Клавиши работают в русской и английской раскладке. `PgUp/PgDn` прокручивают
списки и длинные ответы. Обзор и график обновляются каждые пять секунд, в том
числе во время операций. Периоды графика — 5 и 15 минут, 1 и 3 часа.
Пропуск измерения отображается как отсутствие данных. Показания хоста
и выбранного Minecraft-сервера берутся из [Prometheus](RESOURCE_HISTORY.md).

## Резервные копии

По `5` видны последний запуск, этап копирования и пути к последним проверенным
ZIP на VPS и на Windows. `3 → 1` сразу записывает изменения DJ2 в игровое сохранение.
Таймер делает копию после каждого часа, в котором кто-то был в игре, даже если
все вышли к концу часа. В 04:00 МСК создаётся копия за день, если сегодня ещё
нет готовой. После простоя копия за день создаётся при следующем запуске задачи
с работающим Minecraft.
Если в это время выполняется операция владельца, задача ждёт до десяти минут.
Minecraft сообщает о начале и результате копирования в чате. После сохранения
сервис собирает временный снимок и сверяет его с исходными файлами. ZIP создаётся
из снимка и проверяется перед публикацией. Сохранения игры во время сжатия
на него не влияют. Если файлы меняются в момент создания снимка, сервис
повторяет попытку после паузы. Сбой оставляет предыдущие копии.

На VPS сохраняются до шести проверенных почасовых копий. В `:04` каждого часа
Windows в фоне проверяет, появились ли новые копии. Задача сверяет архивы по
SHA-256, сохраняет до шести в `F:\omkalitycraft_backup\dj2\hourly` и подтверждает
копирование терминалу. Для передачи нужны доступный диск `F:` и сеанс владельца.
На очередной проверке задача подбирает копии, которые ещё хранятся на VPS. Холодные
копии перед вайпом хранятся отдельно.

## Краш-отчёты игроков

По `6` откройте список последних полученных краш-отчётов. Стрелками выберите
запись, чтобы увидеть путь её выгрузки на VPS. Нажмите `Enter`, чтобы скачать
JSON в папку `CrashReports` рядом с EXE. Список обновляется по `r`. В обычной
SSH-сессии без Windows-передачи `Enter` сохраняет файл по указанному пути на VPS.
Отчёты, которые игрок сохранил только на своём компьютере, в списке не появляются.

## Выдача ключей регистрации

По `i` выберите «Да» и нажмите `Enter`. Windows-терминал копирует выданный код
в буфер обмена. По `l` открывается список с полными кодами.
В списке нажмите `c` для копирования или `o` для отзыва, введите номер строки
и нажмите `Enter`. Для отзыва подтвердите выбранный код. В обычном SSH
копирование зависит от поддержки OSC 52. При неизвестном результате сверяйте
список перед повтором. [Настройка Drasl](ADMIN.md#доступ-по-приглашениям)

## Модерация игроков

Ник можно взять из списка по `1`. В формах начните вводить ник и нажмите `Tab`.
Повторный `Tab` перебирает совпадения. Офлайн-профили тоже доступны.

- `k` отключает игрока от выбранного сервера.
- `b` и `m` действуют на весь проект. Срок от `1s` до `365d`, например `10m`,
  `20h` или `1d`. Бан требует подтверждения.
- В форме бана `perm` блокирует аккаунт Drasl и отзывает его сессии. Данные
  аккаунта сохраняются. Бессрочный бан заменяет временный, мут действует отдельно.
- В разделе `4` клавиша `Tab` переключает «Все», «Баны» и «Муты», `f` включает
  поиск по нику. Для выбранного игрока `u` снимает бан, `n` снимает мут.

Бан и мут продолжают действовать при закрытом терминале. Проектный мут
блокирует публичный чат и ванильные `tell/msg/w/me/say`. Каналы других модов
могут использовать свои правила.

Для подключения нового Forge-сервера укажите общий Drasl и локальный RCON
в приватном конфиге. Инициализируйте список командой
`omk admin --config <path> project-moderation --command init`. Подключите
каталог `project-moderation` на чтение и укажите путь к файлу
`restrictions.tsv` внутри контейнера через `OMK_PROJECT_MODERATION_FILE`.
Используйте текущий Core, `online-mode=true` и тот же Drasl через
authlib-injector на клиенте и сервере.

## Статистика игрока

Выберите сервер, нажмите `s` и введите ник. Карточка показывает статус
профиля, активные ограничения, до 12 последних действий модерации и
[игровое время](PLAYER_TIME.md) в текущем сохранении. Время обнуляется
после вайпа основного мира. История модерации хранится отдельно.

## Вайп мира

1. Выберите сервер, нажмите `w` и стрелками выберите мир.
2. Нажмите `Enter`, сверьте название и подтвердите «Да» один раз.
3. Дождитесь результата и открытия игрового входа. Следить за этапами
   можно в TUI.

| Выбор | Что будет сброшено |
| --- | --- |
| Основной мир | Все измерения, инвентари, достижения и квестовый прогресс на сервере |
| Отдельный мир | Выбранное измерение. Инвентари и общий прогресс сохраняются, затронутые игроки возвращаются в безопасную точку |

В обоих случаях создаётся резервная копия и выбирается новый сид. Учётные
записи остаются в Drasl. Вход закрывается, игроки отключаются с указанием
мира. Сервер сохраняется и останавливается, TUI проверяет копию, подготавливает
и устанавливает новые данные. После запуска Forge и проверки мира вход
открывается автоматически. При включённом входном шлюзе причина и название
мира видны в Minecraft. После подтверждённого отключения TUI показывает
ноль игроков, пока вход закрыт.

Если запуск не подтверждён, вход остаётся закрыт. При ошибке TUI показывает
путь к `OmkalityCraft-Wipe.log`. Версия для VPS скачивает новый отчёт, полученный
в текущем сеансе, в папку рядом с EXE. В отчёте есть этап и причина сбоя.
Если выборочный вайп остановили привязки между мирами, неизвестный формат
сохранения или отсутствие безопасной точки переноса, причина видна в окне вайпа.
Перед повтором сверьте результат предыдущей операции. [Установка и восстановление](OWNER_WORLD_CUTOVERS.md)

Для настройки нового хоста используйте [каталог измерений DJ2](../deploy/owner/world-catalog.example.json)
и шаблон `resource-resets.toml`. Хранилище каждого вайпа выделяется по его
операции обслуживания, вручную создавать том для следующего вайпа не нужно.

В списке видны и выгруженные из памяти измерения RFTools Dimensions 5.71.
Если у измерения есть сохранённые чанки и поддерживаемая запись в реестре,
его можно сбросить отдельно через то же меню. Измерение сохраняет название и
настройки генерации, а при следующем посещении его чанки создаются с новым
сидом. Игроки, оставшиеся в нём, вернутся на защищённый спавн Основного мира.
Общий квестовый прогресс и данные других миров сохраняются. RFTools создаст
новый приёмник на спавне сброшенного измерения при генерации чанков.

На RFTools 7.73 из копии удаляются старые приёмники выбранного измерения и
ссылки на них в портерах, переносимых приёмниках в инвентаре и эндер-сундуке.
В избранном интерфейса настройки телепортов удаляются точки только этого измерения.
Заряд устройств, другие точки и содержимое инвентаря сохраняются.

Терминал оставляет измерение без сохранённых чанков доступным для просмотра.
Если при подготовке обнаруживаются ссылки на выбранный мир, для которых
отдельный сброс не поддерживается, установка останавливается до замены мира.
Например, сброс остановят ссылки в установленных передатчиках, Simple Dialer
и портерах во вложенных контейнерах. Проверенная холодная копия содержит
исходные привязки, реестр RFTools и чанки. [Привязки RFTools](RESOURCE_RESET_RFTOOLS.md)

## Локальная сборка

Нужны Rust 1.93.1, Python 3.14.2 и native toolchain. Windows-сборка требует
MSVC Build Tools с Windows SDK или MinGW с `windres`.

```console
uv sync --locked --no-default-groups --group shared --group dev
cargo +1.93.1 build --manifest-path tui/Cargo.toml --locked --release -j 4
cargo +1.93.1 run --manifest-path tui/Cargo.toml --locked -- --demo
```

Для рабочего запуска передайте `--repo`, `--python` и `--config` с
абсолютными путями. На VPS Linux-бинарник запускается в SSH-сеансе.
На Windows локальный EXE может читать те же пути из соседнего `owner-tui.json`
(`schema_version=1`, поля `repo`, `python` и `config`) или получить их при сборке
через `OMK_TUI_EMBEDDED_DEFAULTS`. Встроенная конфигурация содержит только пути.
`--snapshot <file.svg>` сохраняет отрисовку без открытия терминала.
`--compact-header` включает компактную шапку. [Тестовый Docker-стенд](../deploy/tui-lab/README.md)

Приватный каталог Unix имеет права `700`, закрытые JSON — `600`. На Windows
CLI проверяет владельца и ACL перед чтением данных. Настройте
[`operator.toml`](../deploy/owner/operator.example.toml) и при необходимости
`tui.json` с полями `schema` (значение `1`), `prometheus_origin` (loopback HTTP)
и `host`. `host` должен совпадать с настройкой метрик, `service` — с ID
игрового сервера. Адреса мониторинга и RCON остаются частными.

Код и схемы ответов находятся в [`tui/`](../tui/) и [`docs/contracts/`](contracts/).
Для проверки используйте `uv run --no-sync python scripts/check_owner_tui.py`.
