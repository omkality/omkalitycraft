# Терминал владельца: первый рабочий срез

`tui/` — native Rust/Ratatui клиент существующих Python services. Открывается
локально на машине владельца или в SSH-терминале на будущем VPS. Отдельный
backend daemon, HTTP API администрирования и scheduler не нужны. Доступ определяется
учётной записью ОС и правами к private operator config; player launcher этого интерфейса не получает.

## Доступ только владельца

Перед чтением конфигурации и ключей Python backend проверяет права ОС. Проверка
действует и при прямом запуске CLI, без TUI. На Linux/macOS приватный корень требует
mode 700 и владельца текущего процесса; конфигурация и ключи принадлежат ему же,
секретные JSON требуют mode 600. Закрытый корень защищает существующие внутренние
папки journals без ужесточения их штатных modes.

На Windows native Win32 API проверяет владельца и DACL каталога, operator.toml,
читаемых JSON и папок назначения новых файлов. Разрешены текущая учётная запись,
OWNER RIGHTS/наследуемый CREATOR OWNER и привилегированные SYSTEM/Administrators.
Группы Everyone/Users/Authenticated Users и неизвестные grants приводят к отказу
до чтения ключей/отправки RCON. Неизвестный результат проверки тоже даёт отказ.
Проверки читают права, не меняют их автоматически. Используются
[GetNamedSecurityInfoW](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getnamedsecurityinfow)
и [стандартные Windows SID](https://learn.microsoft.com/en-us/windows/win32/secauthz/well-known-sids).

Это граница учётной записи ОС: программы, работающие под владельцем, и
root/SYSTEM/администратор ОС остаются привилегированными. На будущем VPS вход
планируется через отдельную учётную запись владельца по его SSH-ключу; игровые
аккаунты/OP не дают административного доступа к ОС. TUI запускается внутри SSH
сессии на том же host, где находятся ключи и loopback endpoints. Сам VPS/sshd
этим изменением не развёрнуты; их ручная приёмка остаётся перед запуском.

## Что можно делать

- Видеть CPU/RAM Linux Docker host, занятое место файловой системы проекта.
- Видеть TPS, среднее время tick и число игроков выбранного сервера.
- Смотреть график TPS за последние 5/15 минут, 1/3 часа с обновлением 5 s.
- Запросить `list uuids` и `forge tps` через прежний loopback RCON transport.
- Отправить `save-all flush`, введя `SAVE <server-id>` в диалоге подтверждения.
- Кикнуть игрока с выбранного сервера, выдать временный бан или мут на весь
  проект, снять проектный бан. Подтверждение бана открывается с выбранным «Нет».
- Выдать одноразовый ключ регистрации в проекте по `i`.
- Подготовить резервную копию и выполнить вайп ресурсного мира DJ2 по `w`.
- Выбрать allowlisted сервер и посмотреть последние live backup/maintenance/restore
  journals: фазу, полный ID и признак завершения workflow.

Показатели берутся из уже реализованных Prometheus + Telegraf + server-only
cpburnz exporter, без второго сборщика и БД. В локальном Docker Desktop host —
Linux VM Docker, а не физическая Windows. Метрики CPU/RAM/диска относятся к этому
host; TPS/MSPT/игроки — к выбранному `service` того же `host`.

График — сетка квадратных ячеек со столбцами TPS. Верхняя ячейка яркая, заполнение
ниже приглушено; серые ячейки показывают свободную сетку. Цвет столбца зависит от
измеренного TPS: зелёный ≥19, жёлтый 15..19, оранжевый 10..15, красный <10
(верхние границы жёлтого/оранжевого не включены). Легенда находится под графиком.
Ноль отмечается красной ячейкой снизу, отсутствие данных — серым столбцом без
цветного значения. При сжатии нескольких точек в столбец сохраняется минимум;
если среди них есть пропуск, столбец остаётся без значения. Устаревшие столбцы и
легенда приглушаются. Квадрат занимает один символ × половину строки. Ячейки
соприкасаются, границы различимы по чередующимся оттенкам; один терминальный символ
содержит две ячейки. Расчёт — для обычного шрифта с пропорциями 1:2.

Пустой список операций не означает здоровый сервер. Терминальная фаза restore
`staged` не означает promotion/готовность игроков. Старые архивы journals в этот
короткий обзор не включаются; их по-прежнему можно читать через owner status CLI.
Живые записи могут измениться между чтениями: обзор не является atomic snapshot.

## Сборка и запуск

Нужны Rust **1.93.1** с `rustfmt/clippy`, Python **3.14.2** и зависимости проекта.
Для native Windows Rust нужен C++ linker из Visual Studio Build Tools; Linux/macOS
используют свой native toolchain. Из корня репозитория:

```console
uv sync --locked --no-default-groups --group shared --group dev
cargo +1.93.1 build --manifest-path tui/Cargo.toml --locked --release -j 4
```

Linux, запуск на том же owner host, где находятся config и loopback endpoints:

```console
./tui/target/release/omk-tui --repo /opt/omk --python /opt/omk/.venv/bin/python --config /opt/omk/.omk-admin/operator.toml
```

Windows PowerShell, из корня своего checkout:

```powershell
.\tui\target\release\omk-tui.exe --repo "$PWD" --python "$PWD\.venv\Scripts\python.exe" --config "$PWD\.omk-admin\operator.toml"
```

TUI не содержит SSH-клиента. Для VPS сначала входим по SSH и запускаем Linux binary
там: RCON/Prometheus сохраняют loopback binding. Ничего публично не публикуем.

```console
cargo +1.93.1 run --manifest-path tui/Cargo.toml --locked -- --demo
```

В демо используются явно помеченные синтетические данные, команды отключены.
`--snapshot <file.svg>` сохраняет отрисовку настоящих widgets в TestBackend 120×38,
без открытия терминала. С `--config` snapshot читает реальный Python backend;
с `--demo` он остаётся демо. Это не снимок настоящего terminal emulator.

## Запуск exe без аргументов

`omk-tui.exe` — терминальная админка, а не отдельный сервер. Ей нужны Python и
checkout проекта. Прежняя сборка без `--config`/`--demo` печатала ошибку и сразу
закрывала консоль при двойном клике. Теперь без параметров программа читает
необязательный `owner-tui.json` рядом с exe:

```json
{"schema_version":1,"repo":"/opt/omk","python":"/opt/omk/.venv/bin/python","config":"/opt/omk/.omk-admin/operator.toml"}
```

Все три пути абсолютные; в Windows используйте `C:/...`. Это только пути, без
паролей/ключей. Файл не загружается при явных аргументах командной строки.
Неизвестные поля/версия, относительные пути и файл >8 KiB отклоняются.
Локальный review bundle содержит настроенный файл и `Start-Live.cmd`.
При отсутствии файла интерактивный запуск открывает явно подписанное демо с
отключёнными командами. Неверный файл не подменяется демо; в Windows ошибка
запуска без аргументов остаётся видимой до Enter. Private config/credentials
по-прежнему проверяет Python backend до чтения ключей и отправки RCON.

## Выдача ключей регистрации

`i` открывает подтверждение выдачи одного приглашения. По умолчанию выбран
«Нет». Стрелками или `Tab` выберите «Да» и нажмите `Enter`. Приглашение
действует на весь проект. Нужны `[auth]` в `operator.toml` и
[сохранённый вход администратора Drasl](ADMIN.md#доступ-по-приглашениям).

После выдачи TUI сразу выводит код и путь к закрытому JSON. На Windows
копирование в системный буфер идёт в фоне. В SSH копирование зависит от поддержки
OSC 52 в локальном терминале. Код остаётся видимым для ручного копирования.
Если результат неизвестен, перед повтором сверяйте список через `access invites`.
Инвентаризация и отзыв описаны в [инструкции владельца](ADMIN.md#доступ-по-приглашениям).

## Модерация игроков

`k` — кик с выбранного сервера, `b` — бан, `m` — мут, `u` — разбан на всём
проекте. Срок нужен для бана и мута, например `10m`, `20h` или `1d`.
Допустимы `s`, `m`, `h`, `d`, `w` и сроки от `1s` до `365d`. Причина
необязательна, до 128 символов без управляющих и форматирующих символов.
`Tab`/`↑`/`↓` переключают поля, `Enter` принимает форму, `Esc` отменяет.
В подтверждении бана `←`/`→`/`Tab` выбирают ответ. По умолчанию выбран «Нет».

Бан и мут сохраняются по UUID в `project-moderation/restrictions.tsv` под
приватным каталогом владельца. Каждая запись содержит ник, причину и даты
создания и истечения в UTC. При настроенном Drasl админка получает UUID
зарегистрированного профиля по нику, включая профиль до первого входа.
При тестовом offline mode без Drasl поиск требует, чтобы игрок был подключён
хотя бы к одному серверу. Кик всегда требует присутствия на выбранном сервере.

**Подключение серверов.** В приватном конфиге укажите один Drasl и RCON endpoints
всех серверов проекта. Выполните `omk admin --config <path> project-moderation
--command init`, установите Core **0.3.12** на каждый Forge-сервер и подключите
один каталог `project-moderation` ко всем серверам в режиме только чтения.
Java-процессу нужен доступ на чтение каталога и файла, например через совпадающий
UID с владельцем на Linux. Укажите абсолютный путь к файлу внутри каждого
сервера через `OMK_PROJECT_MODERATION_FILE`. Монтируется каталог, чтобы серверы
видели атомарную замену файла. В рабочих конфигурациях используйте
`online-mode=true` и один Drasl через `authlib-injector` на клиенте и сервере.

Core сверяет ограничения при входе и обновляет их примерно раз в секунду,
пока идёт игровой цикл. Подключённого игрока с активным баном отключает штатный
Minecraft disconnect. Сервер, который был выключен в момент записи, прочитает её
при запуске. Разбан снимает запись из общего списка по сохранённому нику.
Срок действует при закрытой TUI. Новый более короткий мут сохраняет прежний
срок, а действующий бан требует явного разбана перед заменой.

Проектный мут блокирует публичный чат и vanilla `tell/msg/w/me/say`.
Команды вне этих каналов работают штатно. Локальные `banned-players.json`,
`config/omkality-owner-mutes.properties` и FTB-муты действуют независимо и
обслуживаются прежним CLI или своим модом. Каналы чата других модов требуют
отдельной проверки.

Игровые OP для администрирования не выдаются. Служебный transport принимает
только RCON console source, не игроков/command blocks. Даже OP не даёт доступа
к нему. В рабочей конфигурации список OP должен оставаться пустым; тестовые
операторы допустимы только в изолированных проверках и снимаются после них.

## Вайп ресурсного мира

Выберите сервер и нажмите `w`. TUI показывает ресурсный мир DJ2
(`DIM-18000`), текущий этап и ID резервной копии. Для подготовки, установки и
запуска открывается «Вы уверены?» с выбранным «Нет». `←`/`→` меняют ответ,
`Enter` принимает его. Во время выполнения этапа ждите результат в терминале.

1. Закройте игровой вход через [ingress](OWNER_INGRESS.md) и дождитесь, пока
   все игроки выйдут. Укажите свежий выделенный том по
   [настройке ресурсного сброса](OWNER_RESOURCE_STAGING.md).
2. Подтвердите **Подготовить вайп и резервную копию**. Сервер штатно остановится.
   Админка создаст или использует проверенную холодную копию именно этой
   остановки и подготовит новый мир в отдельном томе.
3. Сверьте ID копии и подтвердите **Установить новый мир**. По
   [процедуре установки](OWNER_WORLD_CUTOVERS.md) прежний каталог мира
   сохранится в истории, а новый займёт его место.
4. Подтвердите **Запустить сервер с новым миром**. Поднимется тот же контейнер.
   Игровой вход можно открыть отдельной командой после приёмки.

`r` читает журналы и показывает текущий этап. При прерванной записи сначала
сверьте фазу журнала с описанием восстановления в соответствующей инструкции.
Для следующего вайпа назначьте свежий выделенный том. Занятое историей место
учитывается при проверке свободного диска.

Все этапы выполняет Python через существующие журналы обслуживания, копии,
подготовки и установки. `world-reset --server <id> --command inspect` возвращает
`owner.world-reset` версии 1. Подтверждение привязано к точному состоянию
выбранного сервера и этапу. Если журнал или цели операции изменились,
подтвердите новое состояние.

Локальная проверка DJ2 2.23.4 прошла с настоящей остановкой, копированием,
установкой и повторным входом двух тестовых профилей. Инвентари и опыт
сверены с прежним поколением. [Протокол](validation/tui-world-reset-2026-11-18.json).

## Частная конфигурация

Для двух небольших постоянно работающих тестовых серверов есть отдельный
[локальный sandbox](../deploy/tui-lab/README.md): `lab-alpha` и `lab-beta`,
с ограниченными периодическими CPU-всплесками и настоящим мониторингом.
Запускается только по явному запросу владельца; автоматического stop/cleanup нет.

Прежний `operator.toml`: allowlist `[servers.<id>]`, корень и `[servers.<id>.recovery]`
с loopback портом и `credential_file`. Формат RCON credential: `{"password":"…"}`,
как в существующих owner services. Для save нужны именно права консоли владельца;
игровой OP игрокам не требуется. Пароль не передаётся в argv/Rust и не печатается.

Необязательная `.omk-admin/tui.json`, mode 600 на Unix:

```json
{"schema":1,"prometheus_origin":"http://127.0.0.1:9090","host":"omk-pl"}
```

`host` должен совпадать с `metrics.json`, `service` игрового scrape — с server ID.
Допускается только явный loopback HTTP origin с port 1024..65535. Redirects и
environment proxies выключены. Исходные exporter endpoints остаются в частной
Docker network. Нет файла — «мониторинг не подключён»; нет series/экспортера —
«нет данных». Нули показываются только при настоящем свежем измерении.

Запрос Prometheus ограничен 3 s / 64 KiB / 128 series. `up == 1` обязателен;
samples старше 90 s, отрицательные/NaN/Inf или неоднозначные labels не становятся
числом. CPU берётся по `cpu-total`, диск — `/storage/project`. Изменение инфраструктуры
отражаем в private monitoring config, не подставляем другие узлы автоматически.

## Управление и ошибки

`←/→` — сервер, `↑/↓` — операция, `1` — игроки, `2` — Forge TPS, `3` — сохранение,
`k`/`b`/`m`/`u` — кик/бан/мут/разбан, `r` — чтение обзора, `q`/`Ctrl+C` — выход. Минимальное окно 84×28. Диалог save
закрывается по `Esc`, `PgUp/PgDn` прокручивают ответ консоли. Автообновление
обзора и графика каждые 5 s не отправляет команды. `t` открывает выбор периода:
`↑/↓`, затем `Enter`; `Esc` отменяет выбор. Период сохраняется при переключении
серверов в этой сессии. `--window 5m|15m|1h|3h` задаёт начальный период (default 5m).
`i` открывает выдачу ключа регистрации.

По выбору владельца используется вариант Б: при высоте окна от 34 строк в шапке
показывается плоская квадратная руда без подписи, без перспективы куба. Исходная текстура
32×32 извлечена без перерисовки из локального DivineRPG 1.7.1;
[происхождение и SHA256](../tui/assets/provenance.json). В шапке она занимает
16 столбцов × 8 строк полублочных символов. Пропорции зависят от шрифта
терминала. Генератор `scripts/tui_branding.py` сохраняет пиксельный рисунок
через nearest resampling. CI сверяет Rust cells с PNG.
`--compact-header` отключает руду в шапке. На меньшей высоте шапка компактная автоматически.

Rust запускает не более **одного одновременно** дочернего Python CLI с явными argv:
обзор, затем историю TPS выбранного сервера. stdin закрыт, stderr
не показывается. Вызов ограничен 15 s (модерация — 25 s) и 256 KiB stdout; timeout/выход дожидается
своего процесса. Tempfile вместо pipe исключает зависший reader из-за открытого
stdout. Private stdout не сохраняется после закрытия. Неизвестная версия/поля,
нарушенные инварианты, неверный server/command или противоречивый exit code
отклоняются. Последние показания при ошибке остаются явно устаревшими.

`ok` у консольной команды означает полученный читаемый ответ, **не** независимую
проверку сохранения/backup. При отправке save его effect остаётся `unknown`:
потеря ответа не позволяет доказать, выполнил ли Minecraft команду. Повторной
отправки автоматически нет. `save-all flush` не заменяет cold backup.

## Контракты и проверки

`omk admin --config <path> overview [--server <id>]` выдаёт отдельный
`owner.overview` schema 1; [JSON schema](contracts/owner-overview-v1.schema.json).
Не меняет прежний [owner result v1](OWNER_RESULT.md): его 15 действий и запрет
unsupported actions сохранены. `--result-version 1 overview` возвращает отказ.
Обзор читает максимум 2000 entries каждого из трёх live каталогов и проецирует
не более 128 последних записей. `skipped/truncated` видны в TUI. Не читает миры,
не запускает Docker, не берёт owner lock и не пишет audit/credentials.

`omk admin --config <path> console --server <id> --command players|tps|save`
возвращает `owner.console` schema 1. Для save обязателен `--confirm-save`.
Произвольных shell/RCON команд в этом интерфейсе нет.

`omk admin --config <path> project-moderation --command init|ban|mute|unban
[--player <name>] [--duration 10m] [--reason <text>] [--confirm-ban]` возвращает
[`owner.project-moderation` schema 1](contracts/owner-project-moderation-v1.schema.json).
Успешный результат с `effect=applied` подтверждает запись общего списка.
В `unreachable` перечисляются недоступные при проверке серверы. Доступный
сервер с другим идентификатором списка даёт отказ для бана или мута.

`omk admin --config <path> moderation --server <id> --command kick|ban|mute|unban
--player <name> [--duration 10m] [--reason <text>] [--confirm-ban]` возвращает
результат локального действия `owner.moderation` schema 1;
[JSON schema](contracts/owner-moderation-v1.schema.json). Для бана backend сам
требует `--confirm-ban`. `ok=true/effect=applied` означает проверенный server receipt;
отказ — `effect=none`, потерянный/неверный ответ после отправки — `effect=unknown`.
Автоповтора нет. UUID, nonce и действие связывают receipt с запросом; reason
передаётся как UTF-8/base64url по фиксированной грамматике, без shell/RCON injection.
Прежние overview/console/history и owner result v1 не расширяются этими полями.

`omk admin --config <path> tps-history --server <id> [--window 5m|15m|1h|3h]` возвращает отдельный
`owner.tps-history` schema 1; [JSON schema](contracts/owner-tps-history-v1.schema.json).
Это чтение `query_range` существующего Prometheus, без нового sampler/БД. Диапазон
по умолчанию 300 s; доступны также 900/3600/10800 s. Шаг соответственно 5/15/60/180 s,
максимум 61 точка, значения 0..20; правый край округляется вниз на сетку 5 s. В длинных
диапазонах берётся минимум за каждый интервал, не разреженные мгновенные значения:
короткие просадки между точками сохраняются. Интервал минимума подписан под графиком.
Если сбор данных начался позже левого края, ранние точки остаются пустыми. Проверяются
server/host, порядок и точная сетка времени, конечность значений и единственность
series. `up == 1` и свежесть проверяются в каждой исторической точке. Отсутствующие
измерения дают `null` и столбцы без цветных значений, настоящий ноль остаётся нулём.
Ошибка чтения не стирает уже полученный график того же сервера и периода: он
приглушается и помечается устаревшим, а правый край оси подписывается «посл. ответ».
При смене сервера чужой график не показывается. `--result-version 1 tps-history` отклоняется;
прежние overview/console и 15 действий owner result v1 сохраняют свои схемы.


Rust проверяет Python examples, строгий разбор, корреляцию, пустые/устаревшие данные,
resize, timeout/oversize/exit и настоящий CLI с временным config. Native CI строит
Linux/Windows/macOS binary и хранит его как семидневный workflow artifact,
не player release. Python покрывает HTTP/redirect/fault и отсутствие автоповтора.
Реальный minimal Forge/exporter/Prometheus/Telegraf и Linux PTY проверены в
изолированном стенде: [протокол](validation/owner-tui-2026-11-17.json).
График и квадратная руда отдельно проверены на работающих alpha/beta: 111 focused
Python, 9 Rust tests, 16 native PTY условий, включая настоящее обновление,
все четыре периода, переключение, console, F1 и отмену save без отправки:
[протокол](validation/tui-tps-history-2026-11-17.json).
