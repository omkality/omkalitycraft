# DJ2: команды, лимиты и права

DJ2 RU **2.21.3**, Minecraft **1.12.2**, Forge **14.23.5.2860**.
FTB Utilities **5.4.1.131**, FTB Library **5.4.7.2**, FTB Backups **1.1.0.1**.

[Общий справочник](../README.md) · [Все 438 записей сервера](REGISTRY.md) · [JSON](registry.json)

Команды вводятся в игровом чате с `/`; в консоли сервера — без `/`.
`<...>` — обязательный аргумент, `[...]` — необязательный. Игроки/имена в примерах — заполнители.
«Игрок» ниже означает исходный доступ/назначение, а не завершённую проверку каждого действия.

## Дома и телепортации

| Команда | Назначение | Доступ/особенности |
| --- | --- | --- |
| `/sethome [имя]` | Сохранить дом; без имени используется `home` | Игрок; лимит `ftbutilities.homes.max` |
| `/home [имя]` | Телепорт к своему дому | Игрок; warmup и cooldown |
| `/home list` | Список своих домов и используемый лимит | Игрок |
| `/delhome [имя]` | Удалить свой дом | Игрок |
| `/home [имя] <игрок>` | Телепорт к дому другого игрока | Дополнительно `ftbutilities.other_player.homes.teleport` |
| `/home list <игрок>` | Смотреть чужие дома | Дополнительно `ftbutilities.other_player.homes.list`; отказ обычному игроку проверен |
| `/home list_all` | Обход списка домов всех игроков | Содержит проверки чужих homes; не выдавать как обычную возможность |
| `/spawn` | В точку spawn настроенного измерения | Игрок; отдельные таймеры |
| `/warp list` | Список глобальных warp | Игрок |
| `/warp <имя>` | К существующему глобальному warp | Игрок; можно запретить конкретную точку через `command.ftbutilities.warp.teleport.<имя>` |
| `/setwarp <имя>` | Создать/заменить глобальную точку у себя | OP по умолчанию; владения точкой и лимита игрока нет |
| `/setwarp <имя> <игрок>` | Создать глобальную точку у игрока | Админская команда |
| `/setwarp <имя> <x> <y> <z> [dim]` | Глобальная точка по координатам | Админская команда |
| `/delwarp <имя>` | Удалить любую глобальную точку | OP по умолчанию; проверки владельца нет |
| `/tpa <игрок>` | Запроситься к игроку | Игрок; срок запроса в этом коде — 30 секунд |
| `/tpaccept <игрок>` | Принять запрос указанного игрока | Игрок; переносится отправитель запроса |
| `/back` | Вернуться в сохранённую точку | Доступный тип возврата контролируется отдельными `ftbutilities.back.*` |
| `/rtp` | Случайная телепортация | Игрок; включена. FTB допускает точку над магмой — известное ограничение принято владельцем |
| `/tpl (<x> <y> <z>)` или `/tpl ([кто] <игрок>)` | Админский перенос в указанное место/к игроку | OP по умолчанию |

`command.ftbutilities.home`, `.sethome`, `.delhome`, `.spawn`, `.warp`, `.tpa`,
`.tpaccept`, `.back`, `.rtp` — точные command nodes с соответствующим окончанием.
Разрешение команды не отменяет её внутренних проверок лимита, мира и владельца.

Проверено на настоящем Forge с протокольными игроками: 3 дома/отказ 4-му, чужие homes,
ожидание/кулдауны home/spawn/warp/TPA/back/RTP, движение/урон при home, TPA с изменившейся
позицией получателя и истечением запроса, одноразовый back. Подробности и границы доказательств:
[TESTING.md](TESTING.md). Измерения, смерть, конкурирующие запросы и выход во время ожидания
ещё требуют отдельных сценариев. Протокольный игрок не заменяет полноценный клиент.

## Задержки, кулдауны и числовые лимиты

**Warmup** — ожидание перед переносом. **Cooldown** — интервал до следующего использования.
Для каждого действия они независимы. Формат значений: `0s`, `3s`, `10s`, `1m`, `5m`.

| Действие | Warmup обычного игрока в моде | Cooldown в моде | Наш текущий тестовый профиль |
| --- | --- | --- | --- |
| Home | `ftbutilities.homes.warmup = 5s` | `ftbutilities.homes.cooldown = 5m` | **3s / 10s** |
| Spawn | `ftbutilities.spawn.warmup = 5s` | `ftbutilities.spawn.cooldown = 1m` | Пока заводские **5s / 1m** |
| Warp | `ftbutilities.warps.warmup = 5s` | `ftbutilities.warps.cooldown = 1m` | Пока заводские **5s / 1m** |
| TPA | `ftbutilities.tpa.warmup = 5s` | `ftbutilities.tpa.cooldown = 3m` | Пока заводские **5s / 3m** |
| Back | `ftbutilities.back.warmup = 5s` | `ftbutilities.back.cooldown = 3m` | Пока заводские **5s / 3m** |
| RTP | `ftbutilities.rtp.warmup = 5s` | `ftbutilities.rtp.cooldown = 10m` | Пока заводские **5s / 10m** |

Заводские OP-значения всех этих таймеров — `0s`. В нашем примере `admin extends player`
наследует явно заданные home 3s/10s. `moderator extends player` сохраняет обычные игровые
параметры. Для равных игровых
условий использовать обычный аккаунт, а не считать любой OP равным `player`.

Лаборатория временно задаёт всем шести группам **3s/10s**, не меняя заводские значения
остальных команд в стартовом профиле. Home отменяется при переходе в другой блок и
потере здоровья; движение внутри того же блока не отменяет ожидание. Отменённый home
не расходует кулдаун. Кулдаун сохраняется при переподключении к работающему серверу,
но **сбрасывается при полном перезапуске** FTB. Это проверено с часовым кулдауном.
Ожидание не является защитой от любого движения/урона между серверными проверками.

| Параметр | Заводской игрок | Заводской OP | Наш тестовый player |
| --- | --- | --- | --- |
| `ftbutilities.homes.max` | 1 | 100 | **3** |
| `ftbutilities.claims.max_chunks` | 100 | 1000 | Пока **100** |
| `ftbutilities.chunkloader.max_chunks` | 50 | 64 | Пока **50** |
| `ftbutilities.chunkloader.load_offline` | Разрешено | Разрешено | Пока разрешено |
| `ftbutilities.claims.bypass_limits` | Не выдано | По умолчанию NONE | Не выдавалось |

Количество claim-чанков — площадь привата; лимит загрузки — сколько чанков продолжает
работать. Загрузка офлайн — ещё одно отдельное право. Это важные настройки для TPS;
50 чанков — исходный дефолт мода, не утверждённое нами значение будущего сервера.
Командные приваты учитывают состав команды: нельзя считать `max_chunks` простой
независимой квотой прямоугольника на каждого игрока без проверки правил команды.

Дополнительные права телепортации: `ftbutilities.homes.cross_dim`,
`ftbutilities.tpa.cross_dim`. Возврат `/back`: `ftbutilities.back.respawn` по умолчанию ALL,
а `.home`, `.spawn`, `.warp`, `.tpa`, `.rtp`, `.back` — OP; бесконечные возвраты
`ftbutilities.back.infinite` — NONE. Нужно выбирать не только доступ к `/back`, но и причины возврата.

## Команды, приваты и загрузка чанков

Приват FTB работает по чанкам через интерфейс команды/карту и команды. WorldEdit-топор
и `/wand` для этой защиты не нужны. Двумя non-OP игроками проверены ломание, установка
блоков и открытие обычного сундука: вне привата действия разрешены, внутри — владельцу.
Дополнительно проверен перенос одного слитка из vanilla- и Iron Chest в survival,
отказ чужому в claim, клик с закрытым ID окна и отсутствие добавочного слитка при повторе.
Успех сверяется по серверным инвентарям. Это не проверка всех вариантов дюпа или GUI клиента.
Составные сундуки на границе, отзыв прав открытого контейнера, другие модовые контейнеры,
машины, трубы, жидкости, модовые взрывы и права союзников ещё предстоят.
Обычный TNT проверен внутри/снаружи и на границе claim: приватные блоки сохранились,
внешний контроль разрушился. Урон игрокам/сущностям этим не проверялся.

| Команда | Назначение | Исходный доступ |
| --- | --- | --- |
| `/team create <id> [цвет]` | Создать команду | Игрок, если разрешено создание команд |
| `/team list`, `/team info <команда>` | Список/информация о командах | Игрок |
| `/team get <игрок>` | Команда игрока | Игрок |
| `/team request_invite <команда>`, `/team join <команда>` | Запрос/вступление с проверками членства | Игрок; не обещание свободного вступления в чужую команду |
| `/team leave` | Выйти из команды | Игрок, с проверками владельца |
| `/team kick <игрок>` | Исключить участника | Команда проверяет полномочия в своей команде |
| `/team status <игрок> [статус]` | Статус/отношения участника | Команда проверяет отношения/владение |
| `/team transfer_ownership <игрок>` | Передать владение командой | Проверки владельца |
| `/team settings <config id> [значение]` | Настройки своей команды | Проверки команды |
| `/team create_server_team <id>`, `/team delete <команда>`, `/team settings_for ...` | Серверная команда/управление другими | Админские |
| `/chunks claim` | Заприватить текущий чанк своей команды | Игрок с командой и свободным лимитом |
| `/chunks unclaim`, `/chunks unclaim_all` | Снять свой приват / все доступные свои приваты | Игрок, внутренние проверки; не запускать ради просмотра |
| `/chunks info` | Информация о текущем чанке | Игрок; чужая информация может требовать отдельное право |
| `/chunks load`, `/chunks unload`, `/chunks unload_all` | Управление загрузкой чанков | Игрок в пределах лимитов/владения |
| `/chunks claim_as ...` | Claim серверной команды | Админская |
| `/chunks unclaim_everything`, `/chunks unload_everything` | Глобальные операции с приватами/загрузкой | Админские и потенциально разрушительные |

Точные leaf nodes: `command.ftbutilities.chunks.claim`, `.unclaim`, `.unclaim_all`,
`.info`, `.load`, `.unload`, `.unload_all`, `.claim_as`, `.unclaim_everything`, `.unload_everything`.
У `/team ...` префикс **`command.ftblib.team.`**, а не `command.ftbutilities.team.`.

Работу с чужими приватами отдельно контролируют `ftbutilities.other_player.claims.claim`,
`.unclaim`, `.load`, `.unload`, `.see_info`. Блочные исключения — семейства
`ftbutilities.claims.block.edit.*`, `.block.interact.*`, `.item.*`; выдача всех таких
прав может отменить смысл защиты. Точные исключения базового доступа есть в JSON-снимке.

| `/kickme` | Отключить самого себя | Игрок |
| `/inv view <игрок>` | Просмотр инвентаря | Админская; права и аудит ещё проверяются |
| `/inv disable_right_click ...` | Глобальная настройка запрещённых действий | Админская |
| `/nbtedit block/entity/item/player ...` | Редактирование NBT | Только технический администратор |
| `/fly`, `/god`, `/heal [игрок]`, `/killall ...` | Игровые/админские возможности | Не включать в обычные/косметические роли; отказ fly/god обычному игроку проверен |
| `/tpl ...`, `/reload ...`, `/shutdown` | Перенос, перезагрузка конфигов/остановка | Технический администратор/консоль |

`ftbutilities.chat.speak` — отдельный контроль возможности говорить.
Разрешение command node модерации не должно автоматически означать доступ к чужим
инвентарям, NBT, приватам или редактированию рангов.

Готовый пример `moderator` выдаёт только `command.ban`, `.pardon`, `.banlist`, `.kick`,
`command.ftbutilities.mute` и `.unmute`. Назначение — **консолью своего сервера**:
`ranks add <игрок> moderator`. OP не требуется. Владелец может играть с обычным рангом.
Проверенные запреты включают OP, fly/god, gamemode/give, ранговую эскалацию, NBT,
чужие homes/инвентари, массовое снятие приватных чанков, ban-ip, worldborder и reload.
Проверка этих запретов не заменяет аудит всех команд модов.

Сам штатный FTB mute блокирует обычный чат, но пропускает `/me` и `/tell`/`msg`/`w`.
Для закрытия этих путей используется отдельный серверный адаптер приватного Core 0.2.2,
который читает существующий FTB mute/`chat.speak`. Собственная БД мутов не вводится.
Новые моды с другими каналами связи требуют отдельной проверки.
Активный мут проверен после переподключения и полного stop/start сервера.
После unmute обычный чат/личные сообщения работают и при следующем входе.

## Диагностика, бэкапы и граница

| Команда | Назначение/ограничение |
| --- | --- |
| `/forge tps` | Встроенная диагностика Forge по измерениям и общая; зарегистрирована |
| `/spark ...` | Профилировщик spark; его собственные подкоманды и проверки доступа отдельно |
| `/laggoggles` | Серверная команда установленного LagGoggles, уровень 4; GUI мода проверяется отдельно |
| `/forge dimensions`, `/forge entity list`, `/forge track ...` | Техническая диагностика Forge |
| `/forge generate ...`, `/forge setdimension ...` | Генерация/перенос между измерениями; требуют отдельного теста и прав |
| `/backup start [имя]` | FTB Backups: создать резервную копию; уровень 2 |
| `/backup size` | Размер мира/копий; уровень 2 |
| `/backup time` | Срок до резервного копирования; уровень 0 |
| `/worldborder get` | Узнать размер границы; уровень 2 |
| `/worldborder set <размер> [секунды]` | Задать диаметр границы |
| `/worldborder add <изменение> [секунды]` | Изменить диаметр; можно увеличивать постепенно |
| `/worldborder center <x> <z>` | Центр границы |
| `/worldborder damage ...`, `/worldborder warning ...` | Урон/предупреждения у границы |

`/worldborder` — диаметр, не радиус: размер 10000 означает ширину 10000 блоков.
Наш окончательный размер/отдельные измерения и переходы через порталы ещё не настроены.
Ресурсного мира с безопасным входом/вайпом и CoreProtect-подобных откатов пока нет.
Архивный backup мира не является откатом отдельной постройки.

RTP в исходном конфиге: минимум 1000, максимум 100000 блоков, максимум 200 попыток.
Только стенд уменьшает диапазон до 8–12 ради быстрой проверки. Это не граница мира
и не утверждённый диапазон будущего сервера. Вода/лава/пустота, приваты и нагрузка от
генерации остаются отдельными проверками; команда не обещает безопасную точку во всех ситуациях.

В испытании FTB выбирает точку над специально созданной магмой. Владелец принял это
ограничение для первого запуска; в стартовом `player` задано **`command.ftbutilities.rtp: true`**,
наследуемое остальными ролями. Обязательной замены RTP ради этого случая не требуется.
Слишком маленькая граница отклоняет все точки, но неудачный поиск всё равно расходует кулдаун.

## Настройка рангов

Файл новой DJ2: `local/ftbutilities/ranks.txt` относительно корня сервера.
Наш образец — [profiles/server-defaults/dj2/ftbutilities-ranks.txt](../../../profiles/server-defaults/dj2/ftbutilities-ranks.txt).
Общие флаги включения команд находятся в `config/ftbutilities.cfg`; ранги не включат
группу команд, полностью отключённую в этом конфиге.

| Команда | Назначение |
| --- | --- |
| `/ranks info <ранг\|игрок>` | Информация о ранге; исходный уровень 0, политику видимости ещё проверяем |
| `/ranks create <id> [родитель]` | Создать ранг |
| `/ranks add <ранг\|игрок> <ранг>` | Добавить родителя/ранг игроку |
| `/ranks remove <ранг\|игрок> [ранг]` | Убрать наследование/ранг |
| `/ranks delete <ранг>` | Удалить ранг |
| `/ranks get_permission <ранг\|игрок> <node>` | Посмотреть конкретное право/параметр |
| `/ranks set_permission <ранг> <node> <true\|false\|значение\|none>` | Записать право/значение; `none` снимает локальную настройку |

В runtime есть алиас `setp` для `set_permission`. Управление рангами — техническому
администратору, не обычному модератору. Синтаксис/регистрация подтверждены; все изменения
рангов через эти команды ещё не прогнаны в игре. Не выполняйте примеры на рабочем сервере
просто ради просмотра справки.

Примеры будущих значений (не команды, автоматически выполненные этим README):

```text
/ranks set_permission player ftbutilities.homes.max 3
/ranks set_permission player ftbutilities.homes.warmup 3s
/ranks set_permission player ftbutilities.homes.cooldown 10s
/ranks set_permission player ftbutilities.spawn.warmup 5s
/ranks set_permission player ftbutilities.spawn.cooldown 1m
```

Настройки ещё не принятые для старта: лимит загружаемых/офлайн-чанков, задержки остальных
телепортов, ограничение измерений, политика старших модераторов, собственные публичные warp. Нет
готового `warps.max` в текущем моде: такой node нельзя просто придумать в ranks.txt.
Не выдавать `command.*`, `ftbutilities.*` или права редактирования чужих блоков ради
одной команды — это даёт значительно больше возможностей.
