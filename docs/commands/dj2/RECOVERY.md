# Откат выделенной базы: проверенные команды WorldEdit

WorldEdit **6.1.10**, официальный Forge-файл **2941712**, испытан отдельно в DJ2 RU
2.21.3 / Forge 14.23.5.2860. В рабочий сервер и подписанный клиентский релиз он пока
не добавлен. Это дополнение к базовому реестру 438 команд, а не часть уже установленного профиля.

## Что делает восстановление

Возвращает **все блоки выбранного объёма** к сохранённому снимку. Разрушенная база
восстанавливается вместе с проверенными инвентарями/данными машин; поставленные после
снимка блоки исчезают. Законные изменения внутри объёма тоже откатываются. Это не отмена
действий одного указанного грифера и не возврат предметов, уже вынесенных за границы.

Проверено выделение **130,241,130 → 135,243,134**, 90 блоков, верхний мир. Два сундука
и печь восстановлены, изменения соседей в том же чанке сохранены, включая блоки сверху,
снизу, с запада и с севера. Полный сохранённый NBT vanilla/Iron Chest и Thermal Redstone
Furnace совпал со снимком, включая типы тегов и ForgeCaps; NBT соседнего сундука не изменился.
Повтор, undo/redo и запрос отсутствующего снимка проверены на настоящем сервере.
Полный сценарий прошёл **71 проверку**: после restart состояние сохранилось, а восстановленная
печь действительно переплавила предмет. [Результаты и хеши](../../validation/dj2-region-recovery-2026-10-31.json).

## Команды в Minecraft

Только техническому администратору. В проверенном Forge-провайдере WorldEdit доступ
даёт OP; `cheat-mode=false`, `use-in-creative=false`. Обычному игроку `//restore`
отказано, база осталась повреждённой до действий администратора. FTB-роль `moderator`
сама по себе не должна получать OP ради откатов.

| Команда | Проверенное действие |
| --- | --- |
| `//pos1 <x>,<y>,<z>` | Первая точка прямоугольного выделения; все три координаты через запятую |
| `//pos2 <x>,<y>,<z>` | Вторая точка; границы включены |
| `/snap list` | Список доступных подготовленных снимков текущего мира |
| `/snap use <имя.zip>` | Выбрать конкретный снимок |
| `//restore` | Восстановить выделение из выбранного снимка |
| `//undo` | Отменить последнюю операцию WorldEdit в текущей истории администратора |
| `//redo` | Вернуть отменённую операцию |

Испытанный пример **на новом стенде**, после полной резервной копии:

```text
//pos1 130,241,130
//pos2 135,243,134
/snap list
/snap use before-grief.zip
//restore
```

Успешный ответ: `Restored; 0 missing chunks and 0 other errors.` Наличие слова
`Restored` без нулей недостаточно: возможно частичное восстановление. `undo/redo`
не заменяют согласованный backup и не обещают сохранения истории после restart.
`//wand` и выделение топориком в этот прогон не входили; проверены именно координаты.

## Снимок должен соответствовать измерению

У этой версии подтверждена неоднозначность чтения ZIP: если первым в архиве находится
`lab-world/DIM-1/region/r.0.0.mca`, WorldEdit может прочитать его вместо
`lab-world/region/r.0.0.mca`. Поэтому **обычный ZIP всего мира нельзя просто направить
в `//restore`**. Факт выбора неверного файла воспроизведён на настоящем классе
`ZippedMcRegionChunkStore` из закреплённого jar, без запуска Minecraft.

Стенд сохраняет полный backup отдельно в `backups/`, а для WorldEdit готовит
`snapshots/` только с `lab-world/level.dat` и файлами верхнего `region/`. Исходный backup
не изменяется. Подготовка потоковая, без распаковки; другие измерения, данные игроков
и команд не попадают в snapshot. Дубликаты выбранных путей и отсутствующий верхний мир
отклоняются. Проверка класса WorldEdit после подготовки выбирает правильный регион.

Это пока **лабораторный адаптер только для dimension 0**, не универсальная команда
администратора `omk recovery apply`. Другие измерения, FTB-архивы на рабочем сервере,
сети AE2/EnderIO, жидкости, многоблоки, нехватка диска и авария посреди операции
требуют отдельных проверок. Лимит 4096 блоков относится к стенду; проверенный объём — 90.
Нет гарантии атомарности или автоматического устранения дюпов после возврата инвентарей.

Дополнительный `--edge-cases` проверяет стойки для брони: уничтоженная внутри области
не возвращается, новая после снимка остаётся, внешняя контрольная не меняется. Поэтому
`//restore` нельзя обещать как возврат всех сущностей базы. Для неполных архивов добавлена
лабораторная read-only проверка покрытия до применения; она не превращает WorldEdit
в атомарный инструмент и не заменяет согласованную копию или проверку результата.
На двух блоках по разные стороны чанка подтверждено частичное применение с ответом
`Restored; 0 missing chunks and 1 other errors.` Доступная часть изменилась, вторая
осталась повреждённой. Немедленный `//undo` в стенде вернул исходное повреждённое состояние;
сбой процесса/диска и возврат после него этим не проверены. Любой ненулевой счётчик
ошибок требует разбора результата, даже при нулевом `missing chunks`.

Расширенный полный Forge-прогон прошёл **92 проверки**, включая restart, NBT и работу
печи; временные сервисы остановлены/удалены. Это подтверждает перечисленные ограничения,
а не полноту восстановления базы. [Дополнительные результаты](../../validation/dj2-recovery-edges-2026-11-01.json).

Воспроизведение — [TESTING.md](TESTING.md), требования и результаты —
[REGION_RECOVERY.md](../../REGION_RECOVERY.md).

## Полный возврат мира в новый сервер — только стенд

`omk lab dj2-recovery --edge-cases --full-backup-return …` требует те же обязательные
пути, что [команда TESTING](TESTING.md). Новый сценарий прошёл **111 проверок**:
полная чистая world-копия запущена в пустой папке другого тестового runtime, после
записи/чтения всех 266 файлов. Старый мир сохранён. Возвращены сущности и инвентарь
игрока, работает home и защита FTB с контролями владельца/постороннего, печь переплавляет.
[Полная запись](../../validation/dj2-full-world-return-2026-11-01.json).

Это не Minecraft-команда администратора для рабочего сервера. Баны/OP/whitelist/ранги/
конфигурация и Drasl не входят в старую копию мира; старые FTB-членства в ней входят
и тоже откатываются. До публичного переключения нужны актуальная политика доступа
и сверка членств. Обрыв процесса и рабочий cutover пока не испытаны.
