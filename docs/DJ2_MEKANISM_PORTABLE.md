# Серверная проверка переносимого телепортера Mekanism

DJ2Fix 0.1.4 добавляет узкий серверный адаптер для DJ2 2.23.4 и Mekanism
9.8.3.390. Core 0.3.5 и Client 0.1.1 не изменены. Рецепты, квесты, стоимость
перехода и сами предметы остаются штатными.

## Правило

Проверка выполняется внутри запланированной задачи на серверном потоке, перед
нативными изменениями. Клиентская кнопка и сообщённое клиентом состояние не
считаются разрешением на операцию.

- Используется предмет в указанной руке **в момент обработки**. Проверяются
  живой серверный игрок, тип предмета и штатное право доступа Mekanism.
- Для перехода выбирается текущая частная сеть самого игрока либо публичная
  сеть. Адрес и стоимость вычисляет установленный Mekanism.
- Адресат должен быть загруженным настоящим телепортером с той же частотой.
  Проверка сама не загружает измерение или чанк и не создаёт новую частоту.
- Конечные значения энергии и стоимости должны быть допустимыми, заряда должно
  хватать. Ровно достаточный заряд разрешён, проверяются обе руки.
- При отказе исходный обработчик не вызывается: позиция, заряд, выбор частоты
  и инвентарь остаются прежними. При разрешении списание и переход выполняет
  единственный исходный обработчик Mekanism.
- Смена/удаление частоты сохраняют штатные правила владельца. Ответное
  клиентское сообщение не исполняется на сервере.

Обязательная точка Mixin и native API закреплены. SHA256 установленного
Mekanism: `17573e0c3b2ff9d071a719a06a84c8cd89ca26d1ea3bd7f6e9f3842c4df88ea1`.
Источник — серверный архив DJ2 2.23.4, записанный вместе с его SHA256 в
[`reset-preflight.json`](../profiles/server-defaults/dj2/reset-preflight.json).
Чужой JAR и декомпилированный код в публичный репозиторий не включаются.

Неизвестный артефакт/несовместимый API отклоняют запуск. Ошибка адаптера во
время работы запрещает дальнейшие запросы этого устройства, отмечает
`fix.mekanism.portable=failed closed` и один раз пишет причину в серверный лог.
Профиль исходников требует точный DJ2Fix 0.1.4 и включённую возможность
`fix.mekanism.portable`; молчаливое продолжение без неё не допускается.

## Приёмка

Контроль на исходном DJ2Fix 0.1.3 воспроизвёл недостаточную серверную проверку;
отдельный reader подтвердил её в сохранённом player NBT. На кандидате 0.1.4
в полной DJ2 / Linux Docker проверены достаточный и недостаточный заряд,
точная граница стоимости, серия запросов, чужой предмет, неподходящий предмет,
основная/вторая рука, штатная смена частоты и публичная сеть. Отдельно проверены
выгрузка мира, отказ без его загрузки и успешный переход после обычной загрузки.

Основной проход: 65 зарегистрированных условий с observer и 91 независимое
условие по сохранениям и очистке. Реальные cooldown/warmup команд не уменьшались;
фикстура ждёт их окончания. Подробные пакеты, аккаунты и полные миры остаются
в приватной native-лаборатории.

Отдельный цикл сохранённой сети: 59 native условий / 62 независимых, три
штатных запуска/остановки. Проверены отказ с пустым устройством после полного
restart и reset, заряженный переход в восстановленной основной сети, два
владельца и отсутствие прежнего ресурсного адресата. Data stage изменяет только
эвакуируемого игрока и ресурсные server claims: остальные 327 retained файлов
побайтно сохранены; 19 старых ресурсных файлов исключены из новой копии.
Источник остаётся прежним, все свои game/auth volumes удалены после экспорта.
Ранние неполные controls исключены; загруженный адресат в принятом lifecycle
удерживал второй аутентифицированный игрок.
[Итоговый протокол](validation/dj2-mekanism-portable-2026-11-10.json).

Это серверные протокольные проверки настоящего Forge, не графический клиент
и не полное прохождение сборки. Peaceful и отключённый спавн мобов — условия
фикстуры, не приёмка рабочего Hard/PvP. Проверены перечисленные состояния;
полный аудит десериализации и остальных устройств Mekanism не заявляется.

Рабочий owner wipe остаётся выключенным до полной приёмки #32. Существующие
миры, клиентские manifests, настройки работающих служб и player releases этим
изменением не переключаются. VPS для этой проверки не нужен.
