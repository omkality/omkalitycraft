# Ender Utilities: привязки после сброса ресурсного мира

Принят отдельный адаптер **остановленной копии** для Ender Utilities 0.7.15
из DJ2 2.23.4. Он удаляет ссылку на сбрасываемое измерение у обычных location
crystals в инвентаре игрока и в модулях Ender Porter. Предметы остаются у игрока;
привязки к другим мирам, заряд, выбранный модуль и остальные NBT сохраняются.

Это часть #32, не разрешение рабочего вайпа. Owner-команда по-прежнему умеет
только инспекцию; `ready_for_start=false`, `portal_adapters_reviewed=false`,
`ready_for_players=false`. Существующие серверы и миры не менялись.

## Что разрешено переписывать

Адаптер `enderutilities-0.7.15-player-location-target-v1` включается только после
проверки SHA256 установленного `enderutilities-1.12.2-0.7.15.jar`:
`c0a604aac57853f76f16e21958b02f4d6adbc543c20dda67eb1088ca91ba618c`.
Происхождение — официальный server pack DJ2 2.23.4, закреплённый в
[`reset-preflight.json`](../profiles/server-defaults/dj2/reset-preflight.json).

Проверяются только канонические файлы `playerdata/<uuid>.dat` и `.dat_old`:

- `Inventory`: отдельный `enderutilities:linkcrystal` с `Damage=0`;
- `Inventory`: модули `tag.Items` предмета `enderutilities:enderporter`
  с `Damage=0` или `1`, включая невыбранные модули;
- только `tag.Target` с типизированным `Dim`, равным измерению из плана.

Удаляется целиком только соответствующий `Target`, как при штатной отвязке мода.
Пустой `tag` сохраняется. Проверяются типы известных полей, расположение и
уникальность слотов; неизвестная схема целевого `Target` даёт отказ до записи.
Другие поля предмета и цели в других мирах не нормализуются.

Имена сегментов NBT-пути экранируются (`~0`, `~1`), чтобы необычный ключ
с `/` не мог совпасть в отчёте с допущенным путём настоящего Target.

Предметы внутри сумок, EnderItems, ForgeCaps, мировых контейнеров и entities,
а также другие tiers link crystal **не приняты этим адаптером**. Их известные
ссылки остаются блокирующими находками общего прохода. Неизвестные сериализаторы
и отсутствие находок не считаются доказательством полного покрытия.

## Связь с планом сброса

Read-only preflight продолжает показывать все найденные ссылки. Теперь отдельно
считает обработанные и необработанные; допущенным путям ставит имя адаптера.
`can_stage_data=true` возможно только при найденной площадке, отсутствии
необработанных ссылок и непрозрачных записей. Это разрешает подготовку новой
копии, а не запуск.

Внутренний `position:"auto"` фиксирует proof, SHA профиля/модов и полный inventory
источника в плане. Stage повторяет проверку и требует свежий проверенный backup
текущего остановленного мира. Изменение proof или источника запрещает запись.
Профиль preflight теперь `dj2-2.23.4-forge112-reset-preflight-v2`;
планы прежнего профиля нужно построить заново.

Ручной data-only режим с явно заданной позицией не включает адаптер. Общая
политика разрешённых измерений не расширялась: это приёмка ресурсного мира
`-18000`, не новая возможность сбрасывать основной мир.

## Что проверено настоящим сервером

Полная DJ2 2.23.4 / Forge 1.12.2 запускалась **в Linux Docker** три раза.
Core 0.3.5 / DJ2Fix 0.1.4 не менялись. Отдельный Drasl, обычный survival-игрок
без OP, gated test-only observer для подготовки и наблюдения. Переходы и повторная
привязка выполнены обычными игровыми пакетами использования предмета; observer
не телепортировал игрока вместо Ender Porter. Графического клиента в опыте нет.

Проверено последовательно:

1. Штатное использование Advanced Ender Porter переносит игрока между основным
   и ресурсным мирами и списывает обычный заряд.
2. Штатный API отвязки удаляет ровно три целевых `Target` в контрольном инвентаре.
   Результат Python-преобразования совпадает с этой семантикой.
3. После остановки preflight находит шесть допустимых ссылок: три в основной
   записи игрока, три в `.dat_old`. Новая копия эвакуирует offline-игрока
   в сохранённую безопасную точку основного мира и очищает эти ссылки.
4. Сохраняются предметы, заряд, выбор модулей, здоровье, опыт и неизвестные поля.
   При stage изменяются ровно три файла: обе записи игрока и server claims
   ресурсного спавна. Остальные **295 сохраняемых файлов побайтно прежние**;
   19 файлов старого ресурсного измерения исключены только из новой копии.
5. В новой копии попытка использовать отвязанный Porter не меняет позицию
   и инвентарь; сохранённая основная цель работает со штатной стоимостью 5000.
6. Обычный `/resource` создаёт новый ресурсный мир. Старой контрольной площадки
   там нет. Обычное sneak + использование блока заново привязывает очищенный
   модуль; переходы в обе стороны работают.
7. После полного перезапуска повторная привязка, выбранный модуль и заряд
   сохраняются. Проверены обычные переходы, включая расход ровно последнего
   достаточного заряда, здоровье 20, контрольный предмет и опыт.

Основной проход: **39 условий**, независимый аудит сохранений/TAR/очистки:
**56 условий**. Аудит не импортирует код адаптера или transformer. Все три
остановки штатные, OOM и серверного crash-report нет. Свои test volumes удалены
после экспорта. Ранний пилот и остановленный опыт с ошибкой декодирования
`Properties` в лабораторном observer не выдаются за полную приёмку или краш игры.

Дополнительно: 47 новых синтетических unit/filesystem тестов, включая отказ
для неизвестного хранилища/схемы, подменённого артефакта и изменённого плана.
Linux focused: 129 passed; Windows unit/UI: 1371 passed / 12 skipped, Ruff/Black.
Тест неоднозначного имени NBT-поля сначала воспроизвёл ошибочный допуск, затем
прошёл после экранирования сегментов. Повторное read-only чтение native source
в Docker итоговым scanner даёт тот же полный frozen preflight.
Это не новая графическая
приёмка и не тест Hard/PvP. Конфигурация стенда: 4 CPU, 6 GiB контейнер,
4 GiB Java heap; она не обещает такую же вместимость для будущего VPS.

Обезличенные факты и хэши: [протокол](validation/dj2-enderutilities-reset-2026-11-10.json).
Исходники наблюдателя, пакеты теста и полные сохранения остаются в частной
лаборатории. Java-моды, player manifest и launcher releases не изменены.

## Что ещё требуется

Для Ender Utilities остаются вложенные хранилища, другие устройства/tiers и
нестандартные сериализаторы. Для общей процедуры — остальные модовые переходы,
online-эвакуация, maintenance/start barrier, прерывание/recovery и owner lifecycle.
Эти пункты остаются в #32/#41. Перед рабочим сбросом нужно принимать их отдельно;
VPS для текущих локальных проверок пока не нужен.
