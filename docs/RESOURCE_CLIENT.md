# Графический ресурсный мир DJ2 — 7 ноября 2026

Проверен настоящий Windows-клиент DJ2 2.23.4 с сервером в Linux Docker.
Принята только конфигурация **Core 0.3.5 / DJ2Fix 0.1.3 / server view-distance=6**.
Бинарники Core/Fix не менялись. Это приёмка графического перехода, а не разрешение
пускать игроков: manifest, гайд, безопасный сброс и эксплуатация ещё впереди.

## Как проверяли

Свежая установка подписанного клиента получила только явный тестовый overlay
JED и MCMCP 2026.11.02. Клиент управлялся через MCMCP: координаты, измерение,
загруженные чанки, экран, чат, действия и реальные кадры. Проверки сервера,
сохранений и остановки выполнялись в Docker: 4 CPU / 6 GiB / Java heap 4 GiB,
закреплённый Temurin 8. Тестовый игрок не OP; creative использовался для просмотра.

Два запуска Core 0.3.5 с дальностью 3 воспроизвели отсутствие 5 из 16 соседних
чанков при первом `/resource`. Переподключение восстанавливало их. Read-only
наблюдатель подтвердил, что сервер не отправил часть ещё не готовых чанков.
Гипотеза об отложенной выгрузке проверена на отдельном кандидате: не помогла,
изменения Core полностью откатили. Кандидат не принят и не выпущен.

На исходном Core 0.3.5 с дальностью **6** первый вход прошёл: клиент загрузил и
отрисовал **49 из 49** проверяемых чанков. Серверное наблюдение подтвердило отправку
тех же 49 чанков. Между контрольными staging-копиями совпали все 209 файлов mods,
1489 config, 130 scripts и 42 groovy; в `server.properties` отличалась только
дальность. Это проверенная рабочая настройка, а не доказательство устранения
первопричины или минимально допустимой дальности. Значения 4/5 не исследованы.
Перед VPS конфигурацию нужно закрепить и повторить проверку на целевом хосте.
Первопричина и меньшие значения отслеживаются в [#113](https://github.com/omkality/omkalitycraft/issues/113).

## Что прошло

- Вход без зависшей плашки, `/resource` с native warmup 5 секунд, `/spawn`.
- Два дома в разных мирах; возврат `/home` с native warmup 3 секунды и rejoin
  непосредственно в ресурсный мир. После переходов повторно проверены 49 чанков.
- Настоящая попытка ломания ресурсного спавна отклонена; блок сохранён.
  Сервер отказал обычному игроку в `/setwarp`, не создав warp.
- Скин по умолчанию отображается; миникарта квадратная, сетка выключена.
  Русский язык и FM_NewFont присутствуют в отдельной portable-установке.
- В отдельном графическом прогоне граница ресурсного мира видна, движение
  ограничено X=8191.7 при границе +8192. Вернуться через `/spawn` удалось.
- Три графических процесса закрыты штатно с кодом 0; новых crash reports и
  task/fatal markers нет. Четыре игровых Docker-сервера остановлены с кодом 0,
  без OOM. Один отказ подготовки стенда исключён из приёмки.

**29 независимых проверок** остановленного TAR/NBT подтвердили версии модов,
генератор/seed/границу, два маркера, игрока в ресурсном мире, точную позицию,
здоровье/опыт/исходный инвентарь без дублирования при rejoin, оба home и точные
server-owned приваты: 1444 чанка основного спавна и 196 ресурсного. Запрещённого
warp нет. Архив после чтения не изменился.

## Границы проверки и следующий этап

Полноэкранная JourneyMap через горячую клавишу не подтверждена: её raw key event
не воспроизводится обычным MCMCP keybinding-press; Windows input не дал
подтверждённого открытия. Это ограничение автоматизации, не установленный баг карты.
Миникарта проверена настоящими кадрами.

Два `/rtp` в ещё непрогенерированном ресурсном мире ожидаемо вернули отсутствие
безопасной точки. Игрок не переместился. Политика намеренно пропускает
несгенерированные чанки. Успешный RTP на настоящих рабочих радиусах проверяется
после финальной предгенерации #37; этот прогон не засчитывает такой успех.

Для следующего reset-стенда сохранена read-only инвентаризация: один offline-игрок
в ресурсе, один ресурсный и один основной home, обе группы server claims.
**Это не исполняемый план сброса.** Игровые player claims и портальные адаптеры
этой инвентаризацией не покрыты. Процедура — в [контракте сброса](RESOURCE_WORLD.md#контракт-безопасного-сброса).

Рабочие миры, релизы и расписания backup не переключены. Все пять собственных
scopes очищены; архивы и диагностика остались в `.local`. Для поиска конкретных
папок используются `.local/mcmcp-client-latest.json` и
`.local/resource-peer-latest.json`. Внутри — `native-validation.json` либо
`peer-validation.json`, `resource-mcp-checks*.json`, `stream-observations-*`,
`export/world-after.tar`; у принятого peer также `independent-client.json` и
`reset-reference-inventory.json`. Последняя лишь описывает ссылки, ничего не меняя.
Эти папки содержат тестовые данные и не входят в Git/дистрибутив.

[Обезличенный протокол и SHA](validation/dj2-resource-client-2026-11-07.json).
`ready_for_players=false`; VPS ради этого этапа не нужен.
