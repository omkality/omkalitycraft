# Восстановление базы после грифа

Статус на 1 ноября 2026: **лабораторный прототип на Forge/WorldEdit работает**.
Восстановление выделенной территории, сундуков и Thermal-печи испытано на отдельной DJ2.
Рабочий сервер не менялся. Эксплуатационной команды `omk recovery apply` пока нет;
FTB Backups 1.1.0.1 и автоматическая политика хранения/восстановления требуют отдельной проверки.

Практический список команд — [commands/dj2/RECOVERY.md](commands/dj2/RECOVERY.md),
запуск нового стенда — [commands/dj2/TESTING.md](commands/dj2/TESTING.md).

## Требуемое поведение

Администратор выбирает сервер/измерение, трёхмерную область и доступный снимок до грифа.
План показывает точные границы, время/версию снимка, объём изменений и пересечение
с соседними базами. После проверки создаётся свежая согласованная резервная копия;
восстановление сначала испытывается только на отдельном стенде. Для первого рабочего
варианта допустима безопасная остановка сервера. В лаунчере игрока таких действий нет.
Будущий интерфейс — административная утилита `omk`, с адаптером выбранной сборки.
Это требования, а не существующие команды CLI.

Откат области возвращает **всё** её содержимое к снимку, в том числе полезные изменения
после него. Точность по времени ограничена реально доступными резервными копиями.
Отмена исключительно действий выбранного игрока требует другого источника данных —
проверенного журнала изменений с автором и состояниями до/после. Он пока не выбран.

## Выбранный инструмент и альтернативы

WorldEdit поддерживает восстановление выделения из snapshots:
[официальная документация](https://worldedit.enginehub.org/en/latest/usage/snapshots/).
Она описывает современную версию; переносить все её гарантии на 1.12.2 нельзя.

Для нашего loader существует официальный
[WorldEdit 6.1.10 / Forge 1.12.2, file 2941712](https://www.curseforge.com/minecraft/mc-mods/worldedit/files/2941712).
Автор указывает Forge/Java 8 и исправление переноса tile-entity данных при замене
блока тем же типом. Старый SNAPSHOT file 2655056 автор просит не использовать.
WorldEdit 6 больше не поддерживается upstream; наличие файла не подтверждает
совместимость отката с каждой машиной DJ2. Этот финальный файл установлен **только в новом
стенде**. Runtime-аннотация сообщает `6.1.10`; `mcmod.info` внутри официального jar
содержит старое `6.1.10-SNAPSHOT;e6b38e8`. Выбор определяется file ID и SHA256, а не
одной строкой metadata:
`cd4768ded9e2b527e3fc093fdf4ce07f058187de7961bdc0d7fa821c1b756f75`.
Ядро остаётся авторским Forge, собственный журнал истории не разрабатывается.

| Решение | Что выяснено | Решение сейчас |
| --- | --- | --- |
| WorldEdit 6.1.10 Forge | Snapshots/выделение/undo/redo, отдельная подготовка измерения | Испытан в настоящей DJ2; основной кандидат для восстановления из backup |
| [ForgeEssentials](https://github.com/ForgeEssentials/ForgeEssentials/tree/028ac920f4fe6cadf3f09fabe859b737ef26104f/src/main/java/com/forgeessentials/playerlogger) | В ветке 1.12.2 есть PlayerLogger, журнал NBT и rollback по области/времени | Изучен исходный код, не установлен/не испытан; возможный отдельный кандидат для истории действий. Его подсистемы прав/защиты пересекаются с FTB |
| [Fast Log Block](https://github.com/LionZXY/FastLogBlock) | Формат журнала содержит координаты/игрока/блок/время, но не полное состояние инвентаря/NBT | Не выбран как средство восстановления модовой базы; совместимость в игре не проверялась |
| [BlockTrace](https://www.curseforge.com/minecraft/mc-mods/blocktrace) | Заявлена Forge 1.20.1 | Не подходит как готовый бинарный мод для DJ2 1.12.2 |

## Подтверждённая ошибка выбора измерения

Класс `ZippedMcRegionChunkStore` из закреплённого WorldEdit в неоднозначном ZIP берёт
первый подходящий путь к `.mca`. На синтетическом архиве, где Nether стоит перед верхним
миром, запрос `r.0.0.mca` для `lab-world` прочитал `NETHER_DECOY` вместо
`OVERWORLD_EXPECTED`. Это тест настоящего класса мода на Java 8, **без запуска Minecraft**,
не предположение по современным docs. Воспроизведение —
`tests/fixtures/WorldEditSnapshotProbe.java`; компилятор ECJ 3.26.0.

После `prepare_overworld_snapshot` тот же класс прочитал `OVERWORLD_EXPECTED`.
Подготовка не редактирует source ZIP и не распаковывает файлы. В снимок попадают только
`lab-world/level.dat` и верхние `region/r.*.*.mca`, с ограничениями размера и отказом при
дубликатах/отсутствующем мире. Полная копия, включая остальные измерения и player data,
сохраняется отдельно для аварийного восстановления. Этот адаптер намеренно ограничен
лабораторным dimension 0; обычные многомерные FTB-backup ZIP не объявляются совместимыми.

## Подтверждённое восстановление базы

Новый мир и новые Drasl-аккаунты, online-mode=true, loopback, Core 0.2.3. После проверки
работающей Thermal Redstone Furnace создаётся полный backup с чистой остановкой.
Затем повреждаются база/инвентари/энергия/направление, а за границей выделения создаются
законные изменения. Перед применением — ещё одна чистая полная копия и записанный план.
Выделение включает 90 блоков в одном чанке; `.mca` целиком не заменяется.

Проверены обычный и Iron Chest с именованными предметами, восстановление пустоты,
удаление нового блока, состояние печи, обе операции undo/redo, повтор и отсутствие снимка.
За границей остаются новый инвентарь соседнего сундука и блоки по четырём направлениям,
включая верх/низ. Полный NBT трёх сохранённых tile entities совпадает с исходным снимком,
в том числе ForgeCaps и типы тегов; соседний сундук совпадает с состоянием перед откатом.
Обычный non-OP игрок получил отказ. Для положительного теста временный OP выдан только
новому тестовому аккаунту; после операций он снят.

Итоговый прогон прошёл **71 проверку**, включая полный restart и настоящую переплавку
предмета восстановленной печью. Стенд штатно остановлен, временный Drasl удалён,
портов его сервисов в LISTEN нет. Python/Qt: 234 passed, один Windows symlink skip;
Ruff/Black прошли. [Санитизированная запись с хешами и всеми проверками](validation/dj2-region-recovery-2026-10-31.json).

Серверный протокольный наблюдатель не исполняет клиентские моды/GUI. Успех одного типа
машины не подтверждает все контейнеры, сети, многоблоки, жидкости и сущности DJ2.
Ответ с ненулевыми missing chunks/errors не считается успехом. История `undo` не заменяет backup.

## Сущности и покрытие снимка

### Повторение на Linux Docker

Те же условия выполнены на полном Linux Forge в новом регистрозависимом named volume:
**93 проверки** (прежние 92 и проверка Linux volume). Три backup созданы после чистых
stop; tar мира преобразован в ограниченный проверенный ZIP без распаковки на хосте.
Подготовленные снимки доступны WorldEdit через отдельный read-only mount. Подтверждены
NBT, соседи, undo/redo, ограничения сущностей/неполного снимка и работа печи после restart.
Стенд остановлен, финальный мир экспортирован, контейнер/volume удалены.

В первом отдельном запуске второй boot упал **до применения** снимка в
ItemBlock/ThaumcraftFix Mixin. Mod jar не изменились; этот volume сохранён для разбора.
Повтор со штатными настройками прошёл полностью, но причина сбоя ещё не установлена.
Это не признак повреждения откатом и не доказательство стабильности рабочего сервера.
[Оба результата, хеши и границы](validation/dj2-linux-region-recovery-2026-11-01.json).
Полный возврат мира в новый Linux volume, VPS, аварийный kill и большие сети отдельно.

### Ранее выполненный нативный прогон

Расширенный полный Forge-прогон прошёл **92 проверки**, включая прежние сценарии,
финальный restart, переплавку и полное сравнение сохранённого NBT. Стенд остановлен,
временный Drasl удалён, принадлежащих им процессов/listeners нет. Python/Qt: 251 passed,
один Windows symlink skip; Ruff/Black прошли.
[Результаты, все проверки и хеши](validation/dj2-recovery-edges-2026-11-01.json).

На двух соседних чанках подтверждено **частичное применение**: из экспериментального
снимка убрана запись чанка (9,8), исходный backup сохранён. Read-only проверка отклонила
снимок и оставила оба блока повреждёнными. При намеренном обходе проверки только в стенде
WorldEdit восстановил доступный блок (143,241,132), но оставил повреждённым (144,241,132).
Ответ — `Restored; 0 missing chunks and 1 other errors.` Эта версия относит отсутствующую
MCA-запись к `other errors`; полагаться только на счётчик `missing chunks` нельзя.
Немедленный `//undo` вернул оба тестовых блока в состояние до частичного применения.
Это не проверка возврата после краша: история WorldEdit не заменяет свежую полную копию.

В opt-in сценарии `--edge-cases` уничтоженная стойка для брони внутри выделения
**не восстанавливается**, а добавленная после снимка остаётся. Контрольная стойка
снаружи не меняется. Поэтому восстановление блоков/NBT не объявляется восстановлением
всех объектов базы; другие виды сущностей отдельно не испытаны.

Новый `omk/recovery_preflight_lab.py` только читает подготовленный снимок: до применения
проверяет наличие каждого выбранного чанка, его координаты и базовую NBT-структуру.
Разрешён лишь dimension 0, до 4096 блоков/16 чанков, с ограничением высоты/координат,
размера region и распакованного NBT. Unit-тесты отклоняют отсутствующий чанк/регион,
неверные координаты, испорченное zlib-сжатие и недопустимые границы; проверена работа
отрицательных координат и неизменность исходного ZIP. Проверка не валидирует все
состояния блоков/модовые данные, совместимость версий, весь архив или неизменность файла
между проверкой и применением. Это лабораторный компонент, а не эксплуатационный apply.

Следующий этап: репрезентативные AE2/EnderIO сети/многоблоки и процедура возврата после сбоя.
Ограничение сущностей должно быть явно отражено в плане восстановления. Затем оформить
закрытый административный `omk` plan/apply с allowlist сервера/измерений, проверкой версии
и границ, maintenance-режимом, согласованной полной копией и ограниченным журналом.
Это план, не уже существующие команды. Другие требования ниже остаются актуальными.

## Критерии приёмки

### Полная world-копия как отдельный путь восстановления

Расширение `--full-backup-return` прошло **111 проверок** на новом Forge-стенде:
включены прежние откаты, затем чистая остановка, свежая копия перед возвратом и запуск
исторического полного мира в **пустом новом сервере**. Все 266 файлов прочитаны обратно
и сверены по SHA256. Старый мир сохранён без замены/перемещения/удаления и совпал по хешам.
Возвращаются исходный инвентарь игрока, стойки для брони и FTB-данные: home телепортирует,
приват блокирует постороннего и разрешает владельца. Печь снова переплавляет предмет.
[Отчёт и границы опыта](validation/dj2-full-world-return-2026-11-01.json).

Перед staging записывается план, после полного readback — отдельный маркер готовности.
27 unit-проверок покрывают пути/ссылки/коллизии/лимиты/хеш и ошибки CRC/записи;
незавершённая папка не становится готовой и не допускает повтор поверх неё.
Это лабораторный world-backup с лимитом 512 МиБ, а не эксплуатационное переключение.
Актуальные bans/OP/whitelist/ранги/config и внешний Drasl не восстанавливаются из старого
мира; их перенос и сверка членств FTB до открытия доступа ещё требуют отдельного процесса.
Полная копия возвращает и исторические права команд внутри мира. Обрыв Java посреди
операции, реальный большой мир, другие измерения в игре и FTB Backups ещё не испытаны.

### Оставшиеся требования

- Два соседних участка: разрушенный восстанавливается, контрольные блоки/инвентари
  вне выделения остаются неизменными, включая соседство в одном чанке/region-файле.
- Пустота/поставленные грифером блоки, обычные и железные сундуки с предметами,
  данные модовых машин, ориентация/состояние и Forge/NBT данные.
- Сущности, жидкости, многоблочные структуры и сети, пересекающие границу: отдельно
  определить и проверить покрытие. Скопированный видимый блок не доказывает исправность машины.
- Приваты/членство и данные игрока изменяются только если это явно предусмотрено
  планом; не восстанавливать случайно старый доступ исключённому игроку.
- Сбой, неверный/неполный снимок, несовместимая версия сборки, недоступный диск,
  повтор операции, проверка результата и возврат из свежей копии после ошибки.
- Учесть предметы, уже вынесенные за область или находящиеся у игроков: откат базы
  может создать дополнительные копии. Зафиксировать административную процедуру
  разбора инцидента, не обещать автоматическое устранение всех дюпов.
- Ограничить размер операции и память; журналировать план/результат с ротацией,
  сохраняя резервные копии отдельно от публичного CDN/клиентской диагностики.

Файлы `.mca` содержат много чанков: замена всего файла может затронуть соседние базы.
Поблочный и почанковый откаты имеют разные границы; инструмент обязан их показывать.
Ни один эксперимент не выполняется на старых мирах или существующем сервисе.
