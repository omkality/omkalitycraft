# Утилита владельца

`omk admin` — локальная Python-утилита владельца на машине/SSH-хосте сервера.
Это **не** игровая `/omk`, не интерфейс игрока и не публичная админская HTTP API.
Сборка лаунчера не содержит `omk.admin`, экспорт архивов, серверное хранилище отчётов,
operator-config или управляющие токены Drasl. Доступ к локальным данным определяют
права файловой системы; знание команды или скачивание исходников прав не даёт.

## Настройка

Скопировать [шаблон](../deploy/operator.example.toml) в `.omk-admin/operator.toml`.
На Linux/macOS каталог должен иметь mode `700`, управляющая сессия — `600`.
Новые credential/invitation/export-файлы создаются приватно. На Windows используются
права выбранной папки; это не шифрование и не защита от процессов того же пользователя.
Административную папку держать на своей машине/VPS, отдельно от папки игры и дистрибутива.
Она исключена из Git, CDN и staging.

В `[servers.<id>]` перечислить только разрешённые для диагностики серверные папки.
Пути могут быть абсолютными или относительно `.omk-admin`. Экспорт не позволяет
передать произвольный `--server-root`: требуется ID из явного allowlist.
Папки ещё не развёрнутых DJ2/GTNH шаблон сам не создаёт и не объявляет готовыми.

В рабочем Drasl регистрация должна требовать приглашение (`RequireInvite=true`);
одно создание кодов не заменяет эту серверную настройку. Стенд уже работает так.

В `[auth].origin` нужен доверенный Drasl origin: HTTPS, за исключением loopback-стенда.
До `login` должен существовать **административный** аккаунт Drasl; первоначальную
настройку владельца делаем при развёртывании. Логин обычного игрока не повышает его права.
Пароль вводится интерактивно, не аргументом командной строки; сохраняется отдельный
API token владельца, пароль не сохраняется. В лаунчер эти данные не передаются.

```powershell
uv run omk admin --config .omk-admin/operator.toml login --username operator
```

Minecraft OP, игровые ранги и административная роль Drasl — разные вещи.
Ни одна команда ниже не выдаёт OP, fly, god или бонусы игровому аккаунту.

## Доступ по приглашениям

```powershell
uv run omk admin --config .omk-admin/operator.toml access invite
uv run omk admin --config .omk-admin/operator.toml access invites
uv run omk admin --config .omk-admin/operator.toml access revoke-invite --invitation-file PATH_FROM_INVITE_COMMAND
```

Результат содержит **путь к закрытому JSON**, а не код/управляющий токен в stdout.
В созданном файле находится `code`: его владелец самостоятельно передаёт игроку.
Автоматических сообщений/оплат/сайта нет. Игрок вводит код при регистрации в лаунчере.
Код Drasl 4.0.0 одноразовый; сам по времени не истекает, до использования его можно
отозвать. Инвентаризация сохраняет актуальные неиспользованные приглашения в закрытый файл.
После неоднозначного сетевого сбоя сначала проверить `access invites`, не создавать коды
бесконечными повторами. Если локальное сохранение нового кода не удалось, утилита
пытается отозвать именно этот новый код; при ошибке отзыва сообщает о необходимости проверки.

Это выдача **права зарегистрироваться в сообществе**, а не готовый per-server ACL.
Отдельный доступ существующего аккаунта к DJ2/GTNH, бан/разбан UUID и изменение рангов
нужно проверять как отдельные игровые функции. Отзыв неиспользованного приглашения
не является баном уже зарегистрированного игрока.

## Серверная диагностика

```powershell
uv run omk admin --config .omk-admin/operator.toml diagnostics dj2
```

Читает только заранее разрешённую папку и создаёт очищенный ZIP внутри `.omk-admin`.
Не останавливает сервер, не вызывает команды, не меняет мир и не подключается к RCON.
Работает с остановленным сервером и без доступа к Drasl: здесь полномочия — локальный
доступ владельца к файлам. У игроков нет ни этих файлов, ни HTTP-метода получения архива.
Это отдельная операция от приёма клиентских крашей.

## Отчёты клиентов

```powershell
uv run omk admin --config .omk-admin/operator.toml reports list
uv run omk admin --config .omk-admin/operator.toml reports list --player PLAYER_UUID
uv run omk admin --config .omk-admin/operator.toml reports export --id REPORT_ID
uv run omk admin --config .omk-admin/operator.toml reports prune
```

`list` сохраняет закрытый JSON со временем получения, UUID, подтверждённым Drasl ником,
версией сборки и типом ошибки. `export` сохраняет выбранный отчёт в закрытый JSON.
В stdout снова только путь/количество, без stack trace и токенов.
Чтение inbox выполняется локально: публичной read/admin API для отчётов нет.
Текст отчёта — данные, утилита не выполняет из него команды и не открывает вложения.

Для реальной доставки на сервере API нужно явно задать:

```text
CLIENT_REPORTS_ROOT=/absolute/path/.omk-admin/client-reports
CLIENT_REPORTS_AUTH_URL=https://trusted-auth.example.invalid
```

Первый путь должен совпадать с `[reports].root` operator-config и находиться **вне CDN**.
У каждого worker API есть почасовая очистка; `reports prune` позволяет запустить её вручную.
При выключенном сервисе очистка выполняется при следующем запуске/записи/ручной команде.
Истёкшие записи не выдаются утилитой даже до физической очистки.

Приём включён только при этих настройках. Лаунчер использует доверенный API origin своего
дистрибутива, не адрес из игрового manifest. До публичного развёртывания есть только стенды.
Отчёты не заменяют world-backup, rollback построек или серверный профилировщик.

## Проверки и границы

Отчёты schema 2 различают `process_state=running` и `exited`; `exit_code=null`
означает, что Minecraft ещё работал при сборе. `run_id` связывает несколько сбоев
одного запуска. Эти поля доступны в закрытом `reports list`; stack trace — в export.
Старые отчёты schema 1 читаются без миграции БД. Новый API следует выпускать раньше
клиента schema 2; отказ старого API не удаляет локальную очередь.

`uv run omk lab admin smoke` создаёт отдельные tmpfs Drasl + настоящий Granian HTTP,
проверяет operator CLI, одноразовую регистрацию/отзыв приглашения, отказ обычному игроку,
доставку клиентской очереди, UUID, отказ чтения по HTTP и отозванному игровому токену.
Текст crash-report в этом тесте синтетический; это не намеренное падение настоящего DJ2.
Отдельный тест запускает реальный дочерний процесс с exit code 1 и проверяет автоматический
сбор отчёта без GUI. Упаковка/интерфейс проверяются отдельно на трёх ОС.

Дополнительно [client-crash lab](CLIENT_CRASH_TESTING.md) прошёл 27 проверок с настоящим
Windows DJ2 и Linux Forge: файл краша создал сам Minecraft по команде тестового агента;
очередь, восстановленный API и закрытый operator export проверены сквозным сценарием.
Это не проверка всех причин самопроизвольных падений и не готовое публичное развёртывание.

API token владельца не принимается за игровую сессию лаунчера. Аудит операций в
`.omk-admin/audit.jsonl` ограничен 3×1 МиБ и не содержит кодов приглашений, паролей,
HTTP-body или содержимого crash-report. При ротации/expiry удаляются только собственные
диагностические записи, не миры, учётные данные или резервные копии.

Drasl API проверен по исходникам **4.0.0**, commit
[`0fe488c`](https://github.com/unmojang/drasl/tree/0fe488c087bbe792485e9c5dae751c6e5fbdc380):
`/drasl/api/v3/invites` требует admin API token, `/minecraft/profile` принимает игровой
bearer token и даёт проверенный UUID для авторства отчёта.

Ручные JSON/ZIP-экспорты — отдельные копии владельца: срок inbox не удаляет уже
сохранённые для расследования файлы. [Отчёт проверок](validation/operator-tools-2026-10-30.json).
