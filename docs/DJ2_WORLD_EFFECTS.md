# Автономные изменения мира и границы FTB

Проверено 5–6 ноября 2026 на отдельном Linux Docker-стенде DJ2 2.23.4.
Приватный Core 0.2.9 ограничивает две проверенные автономные операции:
дополнительные тики блоков/машин и изменение биома. Это часть #29, задача #81.
Рабочий профиль 2.21.3 и существующие миры не менялись.

## Поведение

Эффект без игрока-владельца работает внутри владения одной FTB-команды либо
внутри незанятой территории. Переход между разными владельцами, а также между
приватом и незанятой территорией закрыт в обоих направлениях. Приват сервера
образует отдельную область. Общий адаптер читает актуальные FTB claims с учётом
измерения и очереди изменений; своей БД приватов или кеша разрешений нет.

Та же проверка владения используется ранее проверенной автономной сортировкой.
Обычные операции внутри своей области сохраняются. Предметы, рецепты, скрипты и
квесты не запрещались и не редактировались. При ошибке адаптера эти эффекты
закрываются с одной записью в серверный лог; ошибки исходного алгоритма выбора
цели не скрываются. Неизвестные версии/байты зависимостей не принимаются молча.

## Проверки

| Прогон | Результат | Граница доказательства |
|---|---|---|
| Baseline Core 0.2.8 | 37 условий / 12 случаев | Подтверждён переход эффекта через приват; дюп/краш не заявляется |
| Новый адаптер | 300 условий / 73 случая / два старта | Реальные native callbacks, отдельный приватный probe; положительные и отрицательные контроли |
| Сортировка | 220 условий / 28 случаев / restart | Повтор прежней проверки на Core 0.2.9 |
| RTP | 50 условий | Текущий мир, границы, FTB warmup/cooldown и отказы |
| Claims/контейнеры/мут/TNT | 54 условия | Обычные игровые протокольные клиенты без OP |
| Спавн/могилы | 70 условий / два старта | Включая owner-only получение вещей из могилы и сохранность после restart |
| Независимый reader | 8 проверок | SHA архива, сохранённые биомы/claims/UUID и состояние после restart |

Итого **694 серверных условия** нового Core, baseline и reader посчитаны отдельно.
Проверены отрицательные координаты, разные измерения, соседние/раздельные территории
одной команды, смена владельца/участника, удаление и ещё не обработанная очередь
claims, серверный приват, восстановление после контролируемой ошибки адаптера.
Все свои серверные области остановлены чисто: fatal=false, OOM=false; временные
auth/volumes удалены после проверенного экспорта. Контейнер: 4 CPU / 6 ГиБ,
Java heap 4 ГиБ. В spawn/RTP использован прежний лабораторный deop служебного
аккаунта для отрицательных контролей; production-политика PlaneFix не менялась.

Исходные и целевые методы двух эффектов сравнены по фактическому ASM без номеров
строк. Scripts (130 файлов), groovy (42) и DefaultQuests совпали побайтно с исходным
целевым runtime. Это не проверка прохождения всех квестов. Первоначальное ожидание
reader о регистре типа server-team исправлено по native данным; мир не исправлялся.

Обычный Windows-клиент из свежей подписанной установки (5274 файла, без probe)
вошёл на Linux-сервер и отрисовал мир без зависшей плашки входа. Пока он был
подключён, консоль активировала native эффект. Клиент штатно закрылся с exit 0
**до cleanup**; ещё 55 секунд наблюдения не выявили новых/перезаписанных reports
или поздних task/fatal markers. Графическое нажатие на блок не принято:
средство захвата/координатного ввода отказало. F2-снимок подтверждает отрисовку,
а не полный игровой сценарий или длительную стабильность.

## Что ещё открыто

Это защита двух конкретных путей в закреплённой версии, а не всех модовых изменений
мира. Деревья/структуры, поршни, жидкости, модовые взрывы, AE2 planes и прочие
механики требуют собственных проверок. Полный survival, Linux/macOS renderer,
длительная нагрузка и приёмка новой русской сборки остаются в #29/#49/#36.
Новых пользовательских команд нет; VPS для этой проверки не требуется.
