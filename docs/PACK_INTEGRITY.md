# Проверка сборки и входа

Лаунчер сверяет файлы с подписанным manifest при каждом запуске игры. Пропавшие и
изменённые управляемые файлы скачиваются повторно. Даже порча без изменения размера
определяется по SHA256. До окончания проверки/ремонта Java не запускается.

По решению владельца посторонние файлы и каталоги в `mods`/`coremods` удаляются без
уведомления в игровом интерфейсе. Разрешены только пути подписанного релиза, включая
его версионную подпапку и известный `memory_repo`. Очистка не обходит symlink/junction
и не касается содержимого внешней цели ссылки. Ошибка доступа останавливает запуск.
После установки и непосредственно перед Java проверяются размеры и хеши модов.
Это не защита от враждебного процесса с доступом к файлам самого лаунчера.

Миры, JourneyMap и ресурспаки вне папок модов этой очисткой не затрагиваются.
JourneyMap создаётся из исходного шаблона только при отсутствии файла; пользователь
может менять форму, сетку и размер. Неизменённый options.txt больше не перезаписывается.
При удалении игроком личного мира установщик восстановит файлы сборки, но не личный мир:
для пользовательских данных нужны отдельные резервные копии.

## Авторизация отдельно от списка модов

`online-mode=true` сохраняет проверку игровой сессии и UUID. С authlib-injector сервер
обращается к нашему Drasl. Без агента тот же режим использует официальную авторизацию.
Ник не является доказательством владения аккаунтом; неверный/отозванный токен и чужой
ник уже проверены отрицательными сценариями настоящего Forge login-протокола.

В приватном `../omkalitycore` новая версия 0.2.0 использует стандартный
[Forge NetworkCheckHandler](https://github.com/MinecraftForge/MinecraftForge/blob/1.12.x/src/main/java/net/minecraftforge/fml/common/network/NetworkCheckHandler.java).
Она сравнивает объявленные клиентом ID/версии с заранее утверждённым списком релиза.
Старая схема паролей и mixin-пакетов Core архивирована. Исходники/бинарники Core в
публичный репозиторий не включаются; рабочий сервер не менялся.

Список сообщает сам клиент, поэтому он может быть подделан изменённым клиентом.
Серверная проверка списка не доказывает целостность клиента и не заменяет серверные
правила движения, защиты территорий, инвентарей и модерации. Это отдельные проверки.

## Автоматические игровые проверки

`omk.forge_player.LabPlayer` — ограниченный loopback протокольный участник для тестов
команд и серверной защиты. Он проходит авторизацию и FML handshake, подтверждает
телепорты, принимает чат и отправляет игровые действия. Он не запускает моды клиента,
не рисует игру и не проверяет её физику/совместимость. Поэтому результаты отделены
от реального запуска DJ2 и визуальной проверки.

Формат handshake сверялся с исходниками Forge 1.12.x, packet IDs — с
[PrismarineJS minecraft-data 1.12.2](https://github.com/PrismarineJS/minecraft-data/blob/master/data/pc/1.12.2/protocol.json).
Локальные снимки исходных справочных файлов имели SHA256:

- FMLHandshakeClientState.java: `da1ca5741b8277c2e1762262ddf831bbc54e1b72bc213842c297d0298cc74994`.
- FMLHandshakeServerState.java: `0dcfc023c29aba7f40b355644185d64d7e3b02469e65aef47cb934f3240da981`.
- protocol.json: `2dad4c918f6bd4492bfa8159b4db6ffbbf8f088b628258f03d437b0c0b760af9`.

Справочные Java/JSON-файлы не включены в продукт; реализация тестового участника наша.
Проверки прав, home и обычного ломания привата — часть [матрицы](GAME_TEST_MATRIX.md),
а не обещание отсутствия всех читов, дюпов и способов грифа.


Запуск стенда с явными входными артефактами:

```text
uv run omk lab dj2 --server-source SERVER_FILES --java JAVA_8 --agent AUTHLIB_INJECTOR_JAR --core PRIVATE_CORE_JAR --mods-json VERIFIED_CLIENT_MODS_JSON
```

JSON — объект ID → версия из заранее проверенного клиента этого релиза. Это не список
из входящего подключения. Порты 25576 и 25586 должны быть свободны. Полный клиент добавляется
параметрами `--client-root PORTABLE_LAB_ROOT --manifest SIGNED_PACK_MANIFEST`; он должен быть
уже установлен. `--visual-seconds 300` оставляет его открытым для отдельной проверки окна.
Маркер `finish-visual-checks` в новой папке стенда завершает ожидание. По умолчанию после
успешного входа клиент останавливается. Логи/тестовый мир остаются в `.local/ftb-guard-lab-*`,
контейнеры и процессы закрываются. CI не скачивает DJ2: этот тест выполняется на локальном ПК.
