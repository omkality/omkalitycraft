# Связные территории FTB

Общий Core 0.3.3 добавляет необязательную политику количества территорий для
проверенной пары FTBU 5.4.1.131 / FTBLib 5.4.7.2. Она проверена в изолированном
Linux Docker; действующий сервер и его приваты не переключены.

## Правила

FTB остаётся владельцем приватов, прав и сохранений. Новый адаптер не создаёт свою
БД, не заменяет защиту блоков и не требует клиентского мода. Территория — группа
чанков одной команды, соединённых сторонами. Диагональ не соединяет; одинаковые
координаты в разных измерениях относятся к разным территориям.

По умолчанию каждый участник даёт команде 3 территории. Для одного, двух и трёх
участников это 3, 6 и 9 соответственно. Квота FTB в 50 claim-чанков на участника
применяется отдельно; 3 дома остаются личными. Офлайн-участник сохраняет свой вклад.
Server-owned команды, включая спавн без участников, не расходуют эту квоту.

Если участник вышел, существующие чанки не удаляются из-за превышения новой квоты.
Допустимы изменения, не увеличивающие число территорий: в том числе достраивание
соединяющего коридора несколькими шагами. Новая отдельная территория запрещается.
Снятие мостового чанка запрещается, если оно увеличивает число территорий сверх
доступного бюджета. Снятие всей территории остаётся доступным.

Адаптер проверяет обычные команды и серверный обработчик выделения на FTB-карте.
Пакет снятия чанков проверяется целиком до штатного изменения. При занятии чанков
сначала обрабатываются присоединения к существующим участкам; каждое реальное
добавление затем проходит нативное событие FTB. Проверки прав FTB сохраняются.

## Настройка владельцем

Показать план, ничего не записывая:

```text
uv run omk policy dj2-territories
```

Создать новый файл в существующем `config` **отдельной остановленной копии**:

```text
uv run omk policy dj2-territories --config-directory PATH_TO_STAGING/config
```

Команда создаёт `omkalitycore-territories.properties` исключительно как новый файл.
Существующий файл не перезаписывается, ссылки на каталоги отклоняются. Она не
останавливает сервер, не переносит и не изменяет мир. Неправильные env отклоняются
до записи. Пример: [deploy/dj2-territories.example.env](../deploy/dj2-territories.example.env).

| Переменная | Default | Диапазон |
| --- | ---: | --- |
| `OMK_DJ2_TERRITORIES_PER_MEMBER` | 3 | 1–50 |
| `OMK_DJ2_CLAIM_REQUEST_CHUNKS` | 1024 | 1–4096 |
| `OMK_DJ2_TERRITORY_GRAPH_CHUNKS` | 20000 | 50–100000 |

Python преобразует env в файл; Forge сам эти переменные окружения не читает.
Последние два параметра ограничивают размер запроса и объём расчёта, не игровую
квоту чанков. Квоту чанков настраивают существующие FTB ranks. Изменение политики
в остановленной копии применяется при следующем запуске.

Для профиля, где квота обязательна, добавьте `ftb.territories` к существующему
списку `required.capabilities` в `omkalitycore-profile.properties`. Это обеспечивает
отказ запуска при невключившемся адаптере, в том числе если файл политики забыли.
Существующие профили лабораторий и рабочего сервера автоматически не меняются.

Без файла политика не включается. При наличии файла неправильная схема,
неподдержанный JAR FTB либо выключенные claims отклоняют запуск. Неожиданная ошибка
проверки во время игры закрывает изменения приватов через адаптер и даёт одну
запись ошибки; она не удаляет приваты и не отключает обычное строительство.
Для восстановления проверки нужны исправление причины и проверенный перезапуск.
Эта политика не защищает от администратора с доступом к консоли, файловой системе
или произвольного серверного мода, напрямую меняющего внутреннее хранилище FTB.

## Проверки 7 ноября 2026

DJ2 2.23.4, Forge 14.23.5.2860, закреплённый Temurin 8, контейнер 4 CPU / 6 GiB,
heap 4 GiB. Core 0.3.3 и прежний DJ2Fix 0.1.2. Использованы настоящие протокольные
игроки Drasl и серверный обработчик штатных FTB-запросов; графическая карта FTB
этой приёмкой не объявляется проверенной.

| Проверка | Условия |
| --- | ---: |
| Территории, состав команды, fault и тот же том после restart | 156 / два старта |
| Прежние приваты, контейнеры, mute и TNT с обязательной квотой | 54 |
| Минимальный Forge: три рабочих режима и шесть ожидаемых отказов | 32, включая проверку целости исходного JAR |
| Независимое чтение остановленных TAR/NBT новой пары | 63 |
| JVM-алгоритм против независимого Python-эталона | 305 случаев / 627 условий, не игровые тесты |

Подтверждены 3/6/9 территорий, ровно 50/150 native claim-чанков, запрет разрезания
мостового чанка командой и GUI-запросом, полное снятие области, соединение перед
новым выделением, диагонали/отрицательные координаты/разные измерения, отзыв прав,
server-owned команда без участников, дубликаты и слишком большой запрос.
После уменьшения команды девять территорий сохранились; после restart они
соединились до восьми. Независимый NBT подтвердил точные 31/50/9 итоговых чанков
трёх команд и состав 2/1/0. Тестовый fault дал одну ошибку, сохранил защиту и обычное
строительство; новый старт восстановил адаптер.

Минимальный Forge работает без DJ2/MixinBooter/FTB, а также с FTB без политики;
env со значением 1 действительно ограничивает новую команду одной территорией.
Неверная схема/число, изменённый FTB JAR, выключенные/отсутствующие FTB-приваты
и обязательная возможность без файла политики дали конкретные ожидаемые отказы
до входа игроков. Такие отказы не считаются здоровыми игровыми запусками.

Предыдущий Core 0.3.2 отдельно сохранил шесть областей: 8 native / 9 independent
условий контроля, не включённых в приёмку новой пары. Семь ранних неуспешных
привязок/кандидатов/фикстур также исключены. Все 19 собственных Docker scopes
сверены отсутствующими после экспорта. DJ2Fix и прежние API/обработчики Core,
кроме изменённых классов подключения политики, сохранены; 24 проверки состава
и повторной сборки. SHA и папки: [обезличенный протокол](validation/dj2-territories-2026-11-07.json).

Windows: unit 1040, UI 44, 12 skipped; публичный Ruff/Black и новые приватные
Python-драйверы прошли. UI лаунчера, клиентский адаптер, рабочие миры и расписания
бэкапов не менялись. Spawn/RTP, полный графический клиент и GTNH здесь не повторялись.
