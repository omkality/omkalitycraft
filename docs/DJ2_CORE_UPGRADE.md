# Серверные адаптеры DJ2 2.23.4

Часть [обновления #49](https://github.com/omkality/omkalitycraft/issues/49), 3 ноября 2026.
Это проверка конкретных серверных адаптеров **Core 0.2.8**, не готовность всей сборки.
Профиль лаунчера остаётся 2.21.3; клиент, перевод и перенос существующего мира ещё
не приняты. Исходники Core и подробные security-fixtures остаются приватными.

## Входы и правила переноса

Официальный сервер 2.23.4 взят из [закреплённого ZIP](../profiles/upgrade-inputs/dj2-2.23.4.json).
[Сравнение шести зависимостей](validation/dj2-core-artifact-review-2026-11-03.json)
подтвердило одинаковые JAR FTBU, FTBLib, WR-CBE и Iron Chest. Обновились MixinBooter
10.6 → 10.7 и Twilight Forest 3.11.1021 → 3.15.1. Сравнивались содержимое и фактические
версии, а не только имена: у Iron Chest версия в имени отличается от заявленной модом.

Интерфейс late-loader совпал побайтно. ASM-представление нужного native-метода Twilight
совпало после исключения отладочных номеров строк. Это позволило сохранить поведение
адаптера и проверить новые точные артефакты. Весь остальной код/контент Twilight таким
сравнением не проверяется. Неизвестная версия или неверный SHA256 прерывают старт;
перечень проверенных артефактов упакован с Core и не задаётся игроком через env.

Старая версия [Core 0.2.7 действительно отклонила новый loader](validation/dj2-core-old-version-rejection-2026-11-03.json).
Два первых прототипа 0.2.8 выявили особенности определения JAR coremod-а в Forge;
они завершились ошибкой и не засчитаны успешными. Исправленный resolver проверен
шестью отдельными JRE-проверками файловых/JAR URL и настоящими Linux-запусками.
Повторная сборка дала тот же SHA256 Core:
`ee86e32a913792854e25e37c93ae494b1903a8fbc75683883577986d32ea86ed`.

## Что прошло на настоящем Forge

Все игровые прогоны выполнялись локально в новых Linux Docker volumes. Java 8 закреплена
digest, лимит контейнера 6 ГиБ / 4 CPU, heap 4 ГиБ. Использовались временный настоящий
Drasl и протокольные тестовые игроки. Их mod list — явно синтетическая фикстура,
не разрешённый manifest будущего клиентского выпуска.

| Прогон | Результат | Граница доказательства |
| --- | --- | --- |
| [Старт Core и сохранность мира](validation/dj2-core-2.23.4-startup-2026-11-03.json) | 17 условий, два старта и restart; независимый NBT подтвердил 17 предметов | Новый мир, без графического клиента; RTP настраивается в отдельном прогоне |
| [Границы автоматических инвентарных операций](validation/dj2-core-regressions-2026-11-03.json) | 220 проверок, 28 случаев, restart; сохранена штатная работа в своей области | Один исследованный механизм, не весь список модов/машин/дюпов |
| WR-CBE | 67 проверок, три старта и два restart; связь и lifecycle callbacks сохранены | Отдельный диагностический probe, не часть выпуска Core |
| RTP без диагностических модов | 50 проверок измерений, таймеров, посадок, отказов и двух игроков | Протокольный клиент/подготовленные площадки; природный рельеф и ресурсный мир отдельно |
| Контроль 2.21.3 с Core 0.2.8 | 25 проверок, три инвентарных случая, чистая остановка | Не полный повтор всех старых отчётов |

На отдельной 2.23.4 без исследованной защиты контроль воспроизвёл исходное поведение
(24 проверки / три случая). Сам возраст новой версии не сделал адаптер ненужным.
Отдельно корректный JAR прежней версии с изменённым ZIP-комментарием был отклонён
именно проверкой хеша; все 3975 записей внутри него оставались одинаковыми.
Первый некорректный вариант контрольного архива отвергла Java до запуска Core —
он отдельно сохранён как неудачная фикстура, не как доказательство работы защиты.

## Исправления стендов

`_copy_server` сохраняет `groovy`: все 42 файла официальной папки совпали в копии
сервера. Этот помощник не переносит миры, исходные `server.properties`/`ops.json`,
прежний каталог рангов и runtime-кеши. Для миграции сохранённого мира нужен отдельный
согласованный снимок; произвольные mod-configs требуют отдельного аудита секретов.

Forge может вывести `Done`, а затем завершиться с exit 0 при ошибке мода.
Проверка готовности теперь повторно проверяет процесс и fatal-маркеры после паузы
инициализации. Отдельные unit-тесты покрывают поздний exit 0 и позднее сообщение о краше.

Первый RTP-прогон остановился после восьми условий на проверке водной площадки.
[Независимое чтение остановленного мира](validation/dj2-rtp-water-fixture-review-2026-11-03.json)
показало `flowing_water` (ID 8), тогда как стенд ожидал `water` (ID 9): обе имеют
одинаковое отображаемое имя. Теперь фикстура подтверждает точный вариант жидкости и
записывает его. Проверки запрета посадки в воду, задержек и координат не ослаблены;
после исправления прошли все 50 условий.

WR-CBE стенд выбирает проверенные pins через `--pack-version 2.23.4`; default остаётся
2.21.3. Неизвестный профиль/изменённый артефакт отклоняются до создания контейнера.
Остальные аргументы и изоляция описаны в [WR-CBE](WRCBE_SHUTDOWN.md).

## Следующий этап

Нужны перенос полного лабораторного снимка 2.21.3 → 2.23.4 и возврат старой копии,
registry IDs, квесты, AE2/машины, FTB/playerdata и клиентская установка/обновление.
Полный новый графический клиент ещё не собран: остаются два точных client-only
артефакта; доступные загрузки не заменяют их произвольными версиями.
Перевод/книга/JEI/шрифт и скины проверяются в настоящем клиенте отдельно.

Эти результаты не закрывают весь #49, остальные обходы #29, журнал авторства #52
или архив чата #58. Новый подписанный выпуск, переключение профиля и live deployment
не выполнялись. VPS для следующего локального этапа пока не требуется.
