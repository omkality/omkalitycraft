# Кто создал лаг-машину или опасный чанк

Статус: **требования, не установленная защита**. Задача до открытия DJ2 —
[#52](https://github.com/omkality/omkalitycraft/issues/52).

Crash-report обычно помогает определить сбойный блок/сущность и координаты, но не
содержит историю действий игроков. Профиль нагрузки помогает найти дорогую машину,
но сам по себе не устанавливает её автора. Наши текущие клиентские отчёты не являются
журналом строительства. Восстановление области из backup также не отвечает на вопрос
«кто это сделал»; [откат базы](REGION_RECOVERY.md) остаётся отдельной операцией.

## План

1. Проверить готовые средства журналирования для точного Forge 1.12.2/DJ2 2.23.4.
   Fast Log Block и PlayerLogger из ForgeEssentials — кандидаты для исследования,
   а не утверждённые компоненты. Полный ForgeEssentials может пересекаться с правами FTB.
2. Сохранять подтверждённые сервером UUID/имя, UTC-время, сервер/версию/boot ID,
   измерение, координаты, тип действия и registry ID блока/предмета. Начать с установки,
   разрушения и значимых взаимодействий. Книги, таблички, контейнеры, перемещение блоков
   и автономные механизмы требуют отдельной проверки покрытия; одно событие place/break
   не фиксирует всю историю содержимого и активации.
3. При инциденте сохранять ограниченный набор доказательств до исправления/отката:
   логи, версию/хеш профиля, координаты и временное окно. Предусмотреть запрос истории
   через административный `omk` по области/времени/UUID. Команды ещё не реализованы.
4. Ограничить очередь, время хранения и общий объём через проверяемые настройки.
   Запись пакетами не должна блокировать игровой tick. Разрывы журнала при переполнении,
   ошибке диска или аварийной остановке должны быть заметны в отчёте, а не маскироваться
   как отсутствие действий. Проверить restart, kill, полный диск и ротацию.
5. Испытать двух игроков, невиновного соседа, отложенное срабатывание, автоматизацию,
   передачу опасного предмета и переименование аккаунта. Подробные сценарии злоупотреблений
   остаются приватными. Только после этого выбирать реализацию и считать этап принятым.

Журнал и экспорты доступны только владельцу, вне CDN и игрового API. Не сохранять
неограниченные тексты книг/чат, пароли, токены или полный произвольный NBT в обычных логах.
Для всего игрового чата отдельно запланирован [закрытый журнал с лимитами](CHAT_HISTORY.md),
включая личные/командные каналы; он не копируется в обычные диагностические отчёты.
Отдельное хранилище истории выбирается после проверки формата и нагрузки кандидата;
PostgreSQL не назначается автоматически и не требует переноса Drasl с SQLite.

## Как читать результат расследования

- «UUID A установил блок здесь в это время» — наблюдаемое серверное событие.
- «Машину включил UUID B» — отдельное событие; оно может отсутствовать у автоматизации.
- «Блок находится в привате A» или «B был рядом» — контекст, а не доказательство действия.
- FakePlayer/модовая автоматика, рост и цепные реакции могут не иметь достоверного
  игрока-инициатора. В таком случае результат — «автор не установлен» с указанием пробела.

Даже полная запись установки не доказывает злой умысел: машина может оказаться причиной
случайного бага сборки. Автоматический бан по совпадению координат/времени не планируется.
