# Журнал действий DJ2

Журнал помогает сопоставить время и координаты инцидента с тем, что сервер
наблюдал на этом месте. Доступ к записям есть у владельца через `omk admin`.
История начинается с момента включения. Откат области описан отдельно в
[инструкции по восстановлению](REGION_RECOVERY.md).

## Какие действия попадают в журнал

| Действие | Что записывается |
| --- | --- |
| Установка и разрушение | Блок, координаты и результат проверки к концу тика. Все части двери и других многоблочных установок имеют общий номер установки в пределах одного запуска |
| Взаимодействие | Блок, который обработал нажатие игрока. Срабатывание поршня записывается отдельно без UUID игрока |
| Книги и таблички | Изменение или подписание книги, сохранение таблички, координаты и ID. Страницы, заголовки и строки остаются в игре |
| Предметы | Крафт, выбрасывание и подбор через события Forge. Для выброшенного предмета записывается UUID сущности, по которому можно сопоставить выбрасывание и подбор до слияния или замены сущности |

У каждой записи есть сервер, профиль, версия Core, время UTC в миллисекундах,
идентификатор запуска, номер записи, измерение, координаты и ID блока или предмета.
UUID и ник берутся из активного профиля игрока на сервере. Журнал сохраняет
отдельные признаки для Forge FakePlayer, автоматики и событий без подтверждённого
аккаунта. Записи не содержат переписки, токенов и полного NBT.

`changed` означает, что состояние блока в конце тика совпало с ожидаемым
изменением. `observed` отмечает событие Forge, эффект которого ещё не удалось
подтвердить, например выбрасывание до появления предмета в мире. `cancelled`
фиксирует отмену события. `accepted` отмечает уже выполненный нативный вызов или
уведомление Forge о завершении действия. Открытие сундука и перенос вещей между
слотами модовых инвентарей имеют разное покрытие. Журнал фиксирует обработанное
открытие сундука. Перекладывание по слотам и произвольные внутренние изменения
модов остаются за пределами адаптера.

При разборе сопоставляйте по времени действие аккаунта, последующее срабатывание
автоматики и диагностический стек. Соседство и владение приватом дают контекст.
Автоматического наказания по журналу нет.

## Подключение

Подготовьте каталог `.omk-admin/action-history/dj2` с правами `700`. Подключите
его только в контейнер Forge с записью, например в `/run/omk-action-history`.
Каталог должен находиться вне рабочей папки игры. Владелец и процесс Forge
должны иметь доступ к этому каталогу. Для каждого сервера используется своя папка.

```dotenv
OMK_ACTION_HISTORY_ENABLED=true
OMK_ACTION_HISTORY_SERVER=dj2
OMK_ACTION_HISTORY_DIRECTORY=/run/omk-action-history
OMK_ACTION_HISTORY_DAYS=30
OMK_ACTION_HISTORY_MIB=128
OMK_ACTION_HISTORY_RESERVE_MIB=512
```

Core 0.3.18 и DJ2Fix 0.1.14 оставляют настройку выключенной по умолчанию. Допустимы
1–90 суток, 1–256 МиБ журнала и 1–8192 МиБ свободного места в резерве. Пределы
включают до 512 сегментов, до 128 наблюдений за тик и очередь до 256 записей.
Диском занимается фоновый writer. Он удаляет старые сегменты по сроку и квоте,
записывает пропуски и оставляет резерв свободного места. По повреждённому хвосту
после аварийной остановки видна неполнота записи.

## Поиск

```sh
uv run omk admin --config .omk-admin/operator.toml action-history --server dj2 \
  --dimension 0 --area -32 0 -32 32 255 32 \
  --from 2026-11-27T18:00:00+03:00 --until 2026-11-27T18:10:00+03:00
```

Координаты задаются как минимум X/Y/Z и максимум X/Y/Z, обе границы включены.
Время запроса заканчивается перед `--until`. `--player` фильтрует по UUID,
`--action` по типу действия. `--export` сохраняет результат в приватный
`.omk-admin/action-export.json`. По умолчанию выводятся первые 200 совпадений,
`--limit` принимает от 1 до 1000. `coverage` показывает непокрытые интервалы,
повреждённые сегменты, пропуски номеров и число потерянных записей. Пустой поиск
при неполном покрытии требует сверки с другими источниками.

## Сохранение материалов перед исправлением

1. Сохраните время, измерение и координаты инцидента. В приватный файл
   `incident-input.json` добавьте их вместе с путём к локальному фрагменту стека
   размером до 32 КиБ. При наличии добавьте TPS и средний тик в миллисекундах.
2. Возьмите завершённую [холодную копию](COLD_BACKUPS.md), сделанную после
   инцидента и до правки мира. Положите два файла выбранного поколения,
   `archive.zip` и `manifest.json`, в приватную папку с именем `snapshot-…`
   из результата операции. Исходное поколение можно читать из `store/<id>`
   тома бэкапов, подключённого только для чтения.
3. Повторите поиск по участку с флагами
   `--evidence case-name --incident incident-input.json --backup-operation ID --snapshot snapshots/snapshot-ID`.
   Для сохранения материалов выберите интервал и область, включающие координаты
   инцидента. Поиск для кейса включает все виды действий и аккаунты в этой области.

Пример содержимого `incident-input.json`.

```json
{
  "time": "2026-11-27T18:04:20+03:00",
  "dimension": 0,
  "position": [12, 70, -4],
  "kind": "minecraft_crash",
  "diagnostic": "stack.txt",
  "tps": 17.4,
  "mspt": 57.5
}
```

Поддерживаются `minecraft_crash`, `jvm_crash` и `thread_dump`. Из диагностики в
кейс попадают имена исключений и методов, сигнатура и координаты при наличии.
CLI сверяет ID поколения, инвентарь файлов, SHA-256 и содержимое ZIP с завершённой
операцией и сохраняет независимую копию в `.omk-admin/action-evidence/<case>`.
Там остаются журнал выбранного участка, сводка, хеш runtime снимка, архив и его
манифест. Предел составляет 8 кейсов или 8 ГиБ, резерв диска 512 МиБ. Прежние
кейсы следует переносить вручную, когда нужен дополнительный объём.

## Проверенные источники и выбор реализации

[FastLogBlock](https://github.com/LionZXY/FastLogBlock) собран для Forge
1.12.2-14.23.1.2555 и описывает журнал установки и разрушения с таблицей ников.
[ForgeEssentials](https://github.com/ForgeEssentials/ForgeEssentials/tree/1.12.2/develop)
включает журналирование в более широкий набор модулей, включая права и защиту.
[spark](https://spark.lucko.me/docs/Command-Usage) показывает код, занявший
ресурсы. Для проверенного UUID, выбранных взаимодействий и сохранения материалов
на DJ2 2.23.4 использован адаптер на имеющихся Forge 14.23.5.2860 и Core.
