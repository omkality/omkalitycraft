# Генерация ресурсного мира DJ2

Правила подготовки относятся к проверенному кандидату DJ2 **2.23.4**, Forge 1.12.2.
Конфигурацию готовят Python и профиль сборки. Core **0.3.5** отвечает за безопасный
вход, DJ2Fix **0.1.3** — за согласование поздней регистрации JED с фильтрами
Thaumcraft Fix. Особых веток в интерфейсе лаунчера нет.

`omk policy dj2-resource --source-config PATH_TO_STOPPED_COPY/config --output NEW_BUNDLE`
сначала читает и проверяет все необходимые конфигурации, затем создаёт только новую
папку. `bundle.json` содержит SHA исходников и копий. Исходники, существующие миры
и работающий контейнер команда не изменяет. Без `--output` выполняется только просмотр.
Неполный/неизвестный формат отклоняется до создания папки; частично записанная папка
не получает завершающий `bundle.json`. Без `--source-config` генерация остаётся pending.

## Какие правила копируются

| Генератор | Адаптация ресурсного мира |
|---|---|
| Underground Biomes | ID добавляется в `IncludedDimensions`; сохраняются камни и обёртки руд. |
| CoFH World | ID добавляется в проверенные Overworld-списки `oil_ore`, `amber`, `aquamarine`. Остальные параметры генераторов сохраняются. |
| Extreme Reactors | ID добавляется в whitelist мира для существующей генерации урана. Отключённые руды не включаются. |
| Natura | ID добавляется только в Overworld whitelist; настройки деревьев, ягод, хлопка и Nether сохраняются. |
| Integrated Dynamics | ID добавляется в **blacklist** Menril/Meneglin: запреты основного мира тоже должны сохраняться. |
| Thaumcraft Fix | В whitelist кристаллов и растительности добавляется **имя типа** `omk_resource`, а не числовой ID. |

Шесть Forge-списков и три CoFH-правила описаны в
[`resource-generation.json`](../profiles/server-defaults/dj2/resource-generation.json).
Проверяются не только значения, но и режимы whitelist/blacklist у правил с отдельными
переключателями. Повторная обработка не дублирует ID. Новые/исчезнувшие CoFH-правила
с членством Overworld требуют отдельной проверки при обновлении сборки.

### Почему одного whitelist Thaumcraft недостаточно

JED по умолчанию может использовать уже зарегистрированный `jed_surface_0`, даже
если в JSON указано другое имя. Поэтому профиль требует `require_exact_match=true`
и `allow_different_id=false`: фактический тип должен быть `omk_resource`.

Thaumcraft Fix 1.1.11 строит кэш разрешённых типов в postInit, а JED регистрирует
обычные дополнительные измерения в serverStarted. DJ2Fix в существующем extension
prepare пересчитывает штатный кэш **после** регистрации, **до** первой инициализации
ресурсных чанков. Конфигурация и неизменяемые наборы правил вручную не переписываются.
Включённость контролей, имя типа, разрешённость основного/ресурсного мира и SHA
обоих внешних модов проверяются; ошибка отклоняет старт. Профиль DJ2 требует
`fix.resource.generation`. Для общего Core без этого профиля Thaumcraft не нужен.

Основание: [JED, закреплённый исходник](https://github.com/maruohon/justenoughdimensions/tree/b3929ed6b0775954dd3eba463de9b528ba4a3769),
[Thaumcraft Fix v1.1.11](https://github.com/TheCodex6824/ThaumcraftFix/tree/cb362520d0204000b999b0a2a4f12221eabb4b40).

## Что сохраняется по замыслу сборки

Не включаются отключённые структуры Astral Sorcery, метеориты AE2, ретрогенерация,
отключённые Shoggoth Lairs, Anglesite/Benitoite. Не расширяются разрешения ресурсов
Atum/Erebus/DivineRPG и других сюжетных измерений. Recurrent Complex и специальные
структуры EvilCraft сохраняют исходные правила измерений: ресурсный мир не заменяет
путешествия и прохождение квестов.

Янтарь и нефтяные породы могут встречаться и до адаптации CoFH благодаря другим
генераторам. Их наличие само по себе не доказывает, что конкретный CoFH whitelist
работает. Количество в небольшой выборке — наблюдение для данного seed, не обещание
одинаковой плотности ресурсов в каждом биоме.

Изменение whitelist влияет на **новые** чанки. Уже сгенерированный неполный мир
нельзя считать исправленным после замены конфигурации. Ретрогенерация и удаление DIM
этой командой не выполняются. Для существующего мира нужен отдельный согласованный
план; безопасный административный сброс остаётся самостоятельной задачей #32.

## Проверка

Полная DJ2 проверена в Linux Docker: **78 условий / два запуска** на одном volume.
Контроль до правок — **29 условий**. В обоих сохранениях независимо прочитано по
**75 полностью сгенерированных чанков**, seed 0, одинаковые центры выборки:
чанки (0, 0), (−24, −8), (32, 56). Условия включают подготовку и метаданные.

| Блоки в выборке 75 чанков | До | После |
|---|---:|---:|
| Аквамарин | 0 | 7 |
| Yellorite, Extreme Reactors | 0 | 4357 |
| Янтарь | 164 | 676 |
| Нефтяные породы `thermalfoundation_ore_fluid` и UB-обёртки | 145 | 4368 |
| Растения Natura | 0 | 1 |
| Vis-кристаллы Thaumcraft | 0 | 54 |

Более широкий остановленный снимок содержит **206** полностью сгенерированных
ресурсных чанков и **123 блока всех шести типов** Vis-кристаллов. Это проверка наличия,
не обещание плотности или равномерности. Обычные железо и кварц AE2 также сохранились.

Два retrieval-квеста BQ (848/бревно и 824/песок) проверены через native detect:
предметы для них выданы консолью, принудительного завершения квестов нет.
Прогресс пережил переход, смерть в ресурсном мире, возрождение, повторный вход
и restart; второй аккаунт его не получил. Остановленные QuestProgress/player NBT
подтвердили UUID владельца, незабранные награды, точные вещи/опыт и сохранённую могилу
при новой точке входа.

Общий Core без DJ2Fix проверен отдельно: **94 условия / два запуска**, ещё **33**
независимых проверки сохранения. При полном отсутствии безопасной точки телепортация
отклоняется без аварийного состояния; восстановление границы возвращает вход.
Windows unit/UI: **1127 passed / 12 skipped**, Ruff/Black. Повторные SHA сборки совпали.

Первый опыт с ошибкой чтения Java properties, опыт со старым Core, обнаруживший
проблему могилы, и кандидат с алиасом типа не входят в полную приёмку. Семь собственных
scopes очищены и сверены; исходные отчёты/снимки сохранены. [SHA, протокол и границы
проверки](validation/dj2-resource-generation-2026-11-07.json).

Полная предгенерация, графический клиент, рабочий client manifest и безопасный wipe
этим этапом не объявляются готовыми. `ready_for_players=false`, #32 остаётся открытой.
