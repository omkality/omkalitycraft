# Ванильные механизмы на границах FTB

Кандидат DJ2 2.23.4 с приватным Core 0.2.11 ограничивает запись ванильных
поршней и воды/лавы через границу чужого или серверного claim. Это узкая защита
поверх FTB, без новой системы приватов, команд игрока и запретов предметов.
Рабочий профиль и опубликованные сборки автоматически не меняются.

## Правило

FTB остаётся источником текущего владельца каждого чанка и измерения.
Проверяются затронутые блоки, включая перемещаемый источник, конечное положение,
головку поршня и разрушаемые блоки. Для жидкости учитывается направление записи,
в том числе превращение защищённой лавы при контакте с внешней водой.

- Внутри общей FTB-команды и на незаприваченной земле штатная работа разрешена.
- Запись из чужой команды или незанятой земли в защищённый чанк отклоняется.
- Выход из своей территории в незаприваченную землю разрешён; перенос чужого
  защищённого блока наружу не становится разрешённым из-за свободного назначения.
- Серверные claims имеют собственный домен. Ручное разрешение союзнику само по себе
  не даёт прав механизму без игрока; для общей автоматики нужна общая команда.
- Смена claim действует без перезапуска и не требует отдельной таблицы владельцев.

Проверены обычное перемещение и липкое втягивание, боковой перенос, пустая головка,
разрушаемый блок, вода/лава и два варианта смешивания. Нативное правило поршня
на 12/13 блоков сохранено. Рецепты, предметы и квесты не отключаются.

## Приёмка 6 ноября 2026

Все серверные опыты проведены в новых изолированных Linux Docker volumes,
Java 8 закреплена digest, контейнер ограничен 4 CPU / 6 ГиБ, heap — 4 ГиБ.
Старые миры, аккаунты и чужие контейнеры не использовались.

| Проверка | Результат |
| --- | --- |
| Исходный Core 0.2.10 | 53 условия / 32 сценария; подтверждены 16 записей в защищённое чужое/server назначение |
| Core 0.2.11 | 229 условий / 111 сценариев / два старта того же мира |
| Игровой ввод | Три non-OP survival взаимодействия настоящими пакетами игрока: снаружи, в своей и на чужой границе |
| Изменение полномочий | Девять сценариев после передачи claim другой команде без рестарта |
| Перезапуск | Повтор девяти механизмов в трёх доменах: незанятая земля, чужой и серверный claim |
| Независимое чтение | 161 проверка TAR/Anvil/NBT, включая 150 фактических состояний блоков в двух остановленных экспортах |
| Воспроизводимость | Повторная сборка дала тот же SHA256 Core |
| Существующая защита | 54 условия / 8 независимых проверок: сундуки и отзыв доступа, квоты/права, мут, TNT, Drasl/Forge и заявленный mod list |

Исходная матрица характеризовала также запись из claim наружу; по принятому правилу
она разрешена и не включена в 16 нарушений. Положительные контроли нужны наряду
с отказами: запретить механизмы везде не считалось бы исправлением.

Независимая сверка выявила устаревший номер Core в служебном startup-каталоге:
версия мода/артефакт были верны, отдельная строка каталога оставалась прежней.
Теперь значение берётся у загруженного Forge mod container, рядом сохраняется
состояние нового адаптера. Итоговый JAR перепроверен; ложное совпадение версии
reader не разрешает. Подробности прежних сценариев — в
[DJ2_CLAIM_REGRESSIONS.md](DJ2_CLAIM_REGRESSIONS.md).

Сохранённые данные независимо подтвердили защищённые/разрешённые результаты,
отрицательные координаты, текущую передачу claim, UUID из Drasl и серверную команду
без участников. Reader только читает архивы, не исправляет мир после опыта.
Здоровые запуски завершились exit 0 / fatal=false / OOM=false; свои игровые и
auth-ресурсы убраны после проверенного экспорта.

Отдельный негативный опыт изменил только ZIP comment **копии** Minecraft JAR.
Core отказал на проверке закреплённого артефакта. Forge оформил ожидаемую fatal-ошибку
старта; это не чистый игровой выход и не случайный краш принятого runtime.
Оригинал не изменён, неуспешный том удалён только после сверки экспорта и ownership.

Два ранних опыта остановились на неоднозначном чтении состояния жидкости в драйвере;
ещё один — на проигнорированном взаимодействии во время подтверждения телепортации.
Reader теперь проверяет допустимые состояния одним серверным пакетом команд,
а survival-драйвер ждёт/повторяет реальный клик, не подменяет его консольным питанием.
Эти опыты не объявлены принятыми. Все три завершились без игрового краша и оставшихся
своих ресурсов; полный финальный прогон выполнен заново.

## Артефакты и локальные данные

[Обезличенный протокол с SHA256 и результатами](validation/dj2-vanilla-boundaries-2026-11-06.json).
Закрытый Core остаётся соседним приватным проектом, подробные fixtures не публикуются.
В каталоге проекта `omkalitycraft/.local/vanilla-boundaries-<id>/` находятся
`report.json`, `independent-validation.json`, `server-output.log`,
`pre-restart/world.tar` и `export/world-after.tar`. Отдельный негативный старт:
`.local/vanilla-pin-negative-<id>/`. Аккаунты/session-файлы из лабораторий публиковать нельзя.

## Что остаётся

Это настоящий сервер и его физика с протокольными игроками, не графический клиент
и не прохождение квестов. Общая приёмка обновления #49 ещё не завершена.
Защита всех видов огня, модовых жидкостей, труб, деревьев, машин, AE2 и служебного
PlaneFix-профиля этим результатом не доказана; родитель #29 остаётся открытым.
Урон сущностям, все дюпы и длительная игра также требуют отдельных сценариев.
Политику аварийных откатов и единственного автоматического backup writer этот этап
не меняет. VPS для следующего локального тестирования пока не нужен.
