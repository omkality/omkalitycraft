# Памятка в чате

Core 0.3.8 добавляет необязательную общую для Forge 1.12.2 памятку. Текст/квоты
находятся в профиле DJ2, в Core нет ветвлений по названию сборки или своих приватов.
Источник времени — существующий vanilla/FTB `stat.playOneMinute`, без новой БД
или счётчика сессий. [Семантика игрового времени](PLAYER_TIME.md).

## Для игрока

После входа в первые **3 игровых часа** памятка приходит в обычный чат через
**8 секунд**. Автоповтор — не чаще раза в **30 минут**, включая обычный restart.
Повтор возможен при следующем входе; периодической рассылки внутри сессии нет.
Смерть и переход между измерениями не ставят новое приветствие в очередь.
Выход до задержки отменяет ожидающий показ. Порог проверяется в момент показа.
AFK входит, низкий TPS замедляет игровые часы; cooldown/задержка от TPS не зависят.

`/guide` показывает ту же памятку по запросу и после первых часов. Частые повторы
тихо ограничены пятью секундами; старого `/omkguide` и алиасов нет. Запрос памятки
также отменяет ещё ожидающее автоприветствие. Команда только выводит текст,
ничего не выдаёт и не повышает права. Консоль может прочитать текст без player state.

В профиле DJ2 перечислены `/sethome <имя>`, `/home <имя>`, `/spawn`, `/resource`,
`/rtp`, 3 дома и 50 claim-чанков на игрока. RTP явно описан как доступный только
в разрешённых текущих измерениях: команда не обещает телепорт в любой мир.
Подробные правила/ограничения остаются в [справочнике](commands/dj2/README.md).
Это короткая подсказка, не будущая подробная страница лаунчера (#39).

## Включение на сервере

Скопировать [профиль DJ2](../profiles/server-defaults/dj2/omkalitycore-welcome.properties)
в `config/omkalitycore-welcome.properties` **нового подготовленного runtime**.
Без этого файла Core не регистрирует команду/обработчики и сообщает
`core.welcome=disabled`. Можно потребовать capability `core.welcome` в явном
server profile, если её отсутствие должно прерывать запуск. На минимальном Forge
без FTB/DJ2 можно использовать свой текст в том же формате.

Профиль UTF-8: `schema=1` и последовательные `line.1`…`line.N`, от 1 до 8 строк,
каждая до 240 UTF-16 code units. Общий файл до 16 КиБ, без управляющих символов,
дубликатов, неизвестных ключей, пропусков номеров и symlink. Это обычный текст,
без исполняемых команд, шаблонного кода, ссылок RUN_COMMAND или player input.
Содержание отражает проверенные правила именно этого сервера; универсальный
Core не проверяет, что произвольно указанные владельцем квоты верны.

Неверный профиль/env отклоняется при старте без echo значения. Конфликт уже
зарегистрированного `/guide` также прерывает включение, чужая команда не заменяется.
Обычный MOTD FTB оставляем выключенным, чтобы не дублировать приветствия.
Изменения профиля/env применяются при следующем запуске, hot reload не добавлен.

[Пример окружения](../deploy/welcome.example.env) передаётся контейнеру сервера:

| Переменная | Default | Допустимо |
| --- | --- | --- |
| `OMK_WELCOME_ENABLED` | `true` при наличии профиля | `true`, `false` |
| `OMK_WELCOME_PLAY_HOURS` | 3 | 1–168 игровых часов |
| `OMK_WELCOME_DELAY_SECONDS` | 8 | 1–60 секунд |
| `OMK_WELCOME_COOLDOWN_SECONDS` | 1800 | 30–86400 секунд |
| `OMK_WELCOME_HELP_COOLDOWN_SECONDS` | 5 | 1–60 секунд |

`false` отключает и автопоказ, и команду. Дополнительных public endpoints, GUI
переключателей, owner CLI, Telegram или доступа к Drasl DB не требуется.

## Сохранение и сбои

Отметки — два `TAG_Long` (`last_auto`, `last_help`, Unix seconds) в серверном
player NBT: `ForgeData / PlayerPersisted / omkality_guide`. Это cooldown по UUID,
не хранилище часов или история сообщений. Имя игрока ключом не служит.
Отметка обновляется перед отправкой, поэтому частичная отправка в текущем процессе
не запускает бесконечные повторы. Очередь ограничена 1024 UUID; ошибки логируются
по типу, не чаще раза в минуту, без данных аккаунта и сообщений игроку.

Данные сохраняются штатным механизмом player save/logout/stop. После жёсткой
аварии может потеряться несохранённая отметка и приветствие повторится — отдельный
sync write на каждый показ не добавлен. При откате всей старой копии откатывается
и cooldown. Перевод часов назад не открывает обход ограничения: показ ждёт
прежнюю отметку и заданный интервал. Могилы, вещи, XP и чужие NBT-поля не очищаются.

Ресурсный reset сохраняет player cooldown вместе с прочими невыбранными данными;
это отдельно проверяется в data-only stage fixture. Полный player/world wipe
удаляет и эту отметку, как прочие данные сохранения.

Runtime читает загруженный сервером vanilla stats object, а не owner snapshot
из файла. Ошибка чтения/неизвестный тип/отрицательный счётчик пропускают автопоказ,
не подставляют вечный ноль; ручной `/guide` не требует счётчика. Это не детектор
потери истории, если сам Minecraft восстановил/обнулил повреждённую статистику.
До будущих наград всё равно нужна отдельная политика lifetime/rollback (#43).
