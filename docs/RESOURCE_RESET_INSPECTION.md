# Проверка ссылок перед сбросом ресурсного мира

Владелец может получить сводку сохранённых ссылок на ресурсное измерение:

```text
omk admin --config .omk-admin/operator.toml resource-resets inspect --server dj2 --dimension -18000
```

Команда только читает остановленную копию. План и выполнение сброса ещё предстоят
в #32; результат всегда содержит `world_changes=false`, `reset_plan=false`,
`can_apply=false`, `backup_verified=false`. Успешная сводка не подтверждает
безопасность вайпа или наличие пригодного бэкапа. Настройки границ не меняются.

## Источник и ограничения

Источник выбирается из приватных `.omk-admin/operator.toml` и
`.omk-admin/backups.toml` по [настройке cold backup](COLD_BACKUPS.md).
Нужен локальный Linux Docker engine, явно принадлежащие источнику container/data
volume и отдельный настроенный backup volume. Контейнер должен штатно завершиться
с exit 0 без OOM и автоматического restart; его ограниченный журнал должен
содержать остановку сервера. Игровые пароли и Drasl API token не требуются.

Повторно сверяются container checkpoint и конфигурация источника. Общая блокировка
owner backup/restore исключает параллельные операции этой утилиты. Изменения мира,
resource policy или runtime при проверке приводят к отказу. Администратор Docker
по-прежнему может менять ресурсы вручную; labels не защищают от владельца daemon.

Закреплённый Python worker запускается без сети и Docker socket, с read-only
rootfs и source volume. Backup volume в worker не монтируется. Проверяются SHA
FTBLib 5.4.7.2, FTBUtilities 5.4.1.131 и JED 1.6.0-dev.20211009.214847,
Core resource policy, SHA JED-конфигурации и обе записи принадлежности мира.
Основной/сюжетный ID, несовпадающий настроенный ID, неизвестный формат NBT,
дубли UUID/claims и перекрывающееся владение отклоняются.

Используются существующие env-лимиты: `OMK_BACKUP_WORLD_MAX_BYTES` (16 ГиБ),
`OMK_BACKUP_HELPER_MEMORY_MIB` (512), `OMK_BACKUP_HELPER_CPUS` (1),
`OMK_BACKUP_TIMEOUT_SECONDS` (1800). [Диапазоны](COLD_BACKUPS.md).
Это лимиты проверки, а не утверждённые размеры будущих миров. При таймауте или
прерывании выполняется очистка только временного helper с точными name/label/ID.
При недоступности самого Docker daemon очистка требует его восстановления.

## Что видно в результате

- Число основных player NBT и игроков, сохранённых в ресурсном мире; отдельно
  резервные `.dat_old`, точки возрождения и записи игроков на транспорте.
- Ресурсные FTB homes, warps, death/back/teleportTracker и JED player dimensions.
- Число claimed chunks ресурсного и остальных миров. Источник прав хранится
  штатно в FTB; серверная команда спавна может законно не иметь `Owner`.
- Число непрочитанных модовых файлов playerdata, полный inventory SHA мира и
  fingerprint исходной остановки. Ники, координаты, инвентари и credentials
  в сводку не выгружаются.

Точные папки при `level-name=world`: `world/playerdata/`,
`world/data/ftb_lib/`, `world/data/justenoughdimensions/data_tracker.dat`,
`world/omk-resource-world.properties`, `world/DIM-18000/.omk-resource.properties`.
Данные находятся внутри настроенного Linux Docker volume; вручную извлекать или
изменять их для проверки не требуется.

JSON выводится в терминал; при необходимости владелец сохраняет его в приватный
файл, например `.omk-admin/resource-inspection.json`. Короткий audit пишется в
`.omk-admin/audit.jsonl` (время/операция/успех, с ограничением размера).
Команда не создаёт дополнительное хранилище снимков и не запускает backup schedule.

Модовые порталы и прочие непрочитанные ссылки остаются в `unreviewed`.
Отсутствие известных ссылок не означает их отсутствие во всех модах. Следующий
этап — [план сброса](RESOURCE_WORLD.md#контракт-безопасного-сброса), эвакуация,
адаптеры ссылок, проверяемая новая копия и игровой restart с квестовым прогрессом.

## Приёмка 7 ноября 2026

Linux Docker worker прочитал архив штатно остановленного DJ2 2.23.4/Core 0.3.5 /
DJ2Fix 0.1.3. Подтверждены один offline игрок и один home в ресурсе, 196 ресурсных
и 1444 остальных server claimed chunks; два Astral-файла сохранены непрозрачными.
Повторная проверка дала тот же inventory, запись запрещалась самим read-only mount.
Отрицательные действия/ID/лимит размера получили отказ.

Всего **27 условий**, включая preflight. Полный owner CLI, Docker checkpoint,
audit и очистка прерванного helper проверены на реальных Docker-ресурсах с
контейнером-фикстурой остановки; этот процесс **не запускал Minecraft**. Сам архив
получен в [предыдущем игровом опыте](RESOURCE_CLIENT.md). Нового игрового входа,
сброса, миграции, восстановления из бэкапа и проверки порталов здесь не было.
Один ранний prestart контейнер с неподходящей настройкой Docker logging исключён;
его собственные ресурсы очищены. [Обезличенный протокол](validation/dj2-resource-inspection-2026-11-07.json).
