# Установка подготовленного мира

`omk admin world-cutovers` устанавливает проверенную ресурсную копию в **тот же
остановленный контейнер**. Меняется только каталог мира. Runtime, адреса,
Drasl, proxy и привязка резервных копий сохраняются. Прежний мир остаётся рядом;
команда не удаляет его и не запускает Forge сама.

Это локальный интерфейс владельца. Он продолжает
[подготовку ресурсного мира](OWNER_RESOURCE_STAGING.md) и требует
[закрытый вход](OWNER_INGRESS.md). Публичное развёртывание и готовность сервера
для игроков этим испытанием не подтверждаются.

## Условия

- Исходное maintenance window `M` находится в `stopped`, его cold backup `B`
  завершён и соответствует этой остановке.
- Ресурсная операция `R` имеет `runtime-ready`: мир, runtime и receipt полностью
  проверены. Target не запускался после запечатывания. Если был создан
  [проверочный slot](OWNER_CANDIDATE_SLOTS.md), он должен быть `released`;
  запущенный кандидат нельзя выдавать за неизменённую sealed копию.
- Тот же HAProxy закрыт, активных TCP-соединений нет. Прямой обход proxy не
  предусмотрен deployment. Других контейнеров, включая остановленные helpers,
  с доступом к source volume быть не должно.
- Текущий адаптер рассчитан на root-owned source volume и контейнер с root
  User. Поддержка произвольного UID требует отдельной приёмки. Helper лишён
  capabilities, сети и Docker socket; Java image и JAR остаются прежними.

До установки повторно читаются backup, исходный runtime и sealed target,
сверяются все SHA и сохранённые Docker identities. Настройки берутся из
замороженного ресурсного плана, включая staging budget, свободный резерв,
TTL и лимиты helper. Изменение конфигурации требует нового плана.

## Обычная последовательность

`C` — ID, возвращённый `world-cutovers plan`. Не подставляйте вместо ID название
сервера. Все команды ниже выполняются владельцем на хосте Docker:

```console
uv run omk admin --config .omk-admin/operator.toml world-cutovers plan --resource-operation R
uv run omk admin --config .omk-admin/operator.toml world-cutovers apply --operation C
uv run omk admin --config .omk-admin/operator.toml world-cutovers status --operation C
uv run omk admin --config .omk-admin/operator.toml maintenance start --operation M --backup-operation B
uv run omk admin --config .omk-admin/operator.toml world-cutovers commit --operation C
```

`apply` разрешён один раз. Он копирует только новый мир в source volume,
синхронизирует файлы, переносит прежний каталог в историю и ставит новый каталог
на прежнее место. **Два перемещения не являются одной атомарной операцией.**
Если процесс оборвётся между ними, Forge остаётся остановленным до явного
восстановления. Ни одна из команд не перезаписывает существующее поколение.

Перед `maintenance start` helper ещё раз проверяет установленный мир и
сохранённый прежний мир. Только после этого запускается тот же immutable
контейнер. `commit` подтверждает завершённый start и обновляет два журнала;
данные мира он не переписывает. Если подтверждение прервалось, повторите
`commit`: промежуточный `commit-requested` оставляет вход заблокированным.

Вход открывается отдельным новым `ingress plan/apply` после подтверждения
готовности. Автоматического открытия после установки или restart нет.

## Прерывание и возврат

При потерянном ответе сначала прочитайте сохранённый `status`, затем факты:

```console
uv run omk admin --config .omk-admin/operator.toml world-cutovers verify --operation C
```

`verify` монтирует source read-only, ничего не перемещает и отзывает разрешение
завершённой попытки записи. Если он подтвердил `installed`, повторять `apply`
нельзя: переходите к запуску. Если проверен промежуточный каталог, продолжение
требует отдельного решения:

```console
uv run omk admin --config .omk-admin/operator.toml world-cutovers recover --operation C
```

`recover` только завершает оставшиеся перемещения уже проверенных полных
поколений. Он не повторяет копирование. Неполная копия, посторонние файлы,
изменившийся runtime или неоднозначное состояние отклоняются.

Пока прежний мир ещё на месте и перемещений не было, можно выполнить `cancel`.
Незавершённая копия останется в истории. Если установленный мир надо вернуть
**до первого запуска**, используйте `revert`:

```console
uv run omk admin --config .omk-admin/operator.toml world-cutovers cancel --operation C
uv run omk admin --config .omk-admin/operator.toml world-cutovers revert --operation C
```

Это альтернативы для разных состояний, а не команды для последовательного
выполнения. После потери ответа `revert` выполните `verify`; при незавершённом
возврате снова явно выполните `revert`. Отменённый или возвращённый `C` не
используется повторно. Для новой установки создаётся новый план.

Любой начатый start, новый boot или изменение world запрещает такой возврат.
После приёма игровых изменений нужен отдельный согласованный restore с новой
резервной копией. Иначе можно потерять прогресс игроков. Прямые `docker start`,
перемещения каталогов и изменение журналов обходят координатор и делают его
доказательства недействительными.

## Где находятся данные

Внутри исходного data volume, рядом с активным каталогом мира:

```text
.omk-cutovers/<C>/identity.json
.omk-cutovers/<C>/next/<world>/
.omk-cutovers/<C>/previous/<world>/
.omk-cutovers/<C>/rejected/<world>/
```

`previous` удерживает прежний мир после установки, `rejected` — новый мир после
возврата. Каталоги могут быть пустыми согласно фазе. Host-журнал хранится в
`.omk-admin/world-cutovers/<C>.json` с приватными правами.

В `.omk-admin/world-cutover-control/<C>/lease.json` находится только несекретное
разрешение одной попытки. Оно отзывается до отмены/подтверждения; новая попытка
получает новый nonce. Helper проверяет его перед записью и каждым перемещением.
Запоздавший Docker helper не сможет продолжить старую попытку после отмены.
В контейнер read-only монтируется каталог, чтобы атомарная замена `lease.json`
была видна сразу. На Linux каталог имеет `755`, файл `644`; приватный родитель
и основной журнал остаются закрытыми. Паролей и игровых токенов здесь нет.

Подсчёт перед копированием включает удержанную историю, прежний мир, новый мир
в source, sealed target и его runtime; отдельно проверяется свободный резерв.
Не более 128 каталогов истории: при достижении предела новая установка
отклоняется. История не удаляется автоматически и не включается повторно в
обычный backup активного мира. Её нужно учитывать отдельно при планировании
диска и внешних резервных копий. Общий storage budget и единый scheduler —
следующий этап, нового периодического backup writer эта команда не создаёт.

Поддерживается только проверенный ресурсный adapter текущего DJ2. Это не
разрешение сбрасывать произвольный мир и не гарантия очистки ещё не покрытых
модовых порталов/ссылок. `ready_for_players=false` остаётся явной границей.
