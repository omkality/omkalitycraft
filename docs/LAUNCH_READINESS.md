# Входная точка для аудита первого запуска DJ2

Состояние на 13 ноября 2026. **Финальный допуск игроков ещё не выдан**.
Основной трекер — [#41](https://github.com/omkality/omkalitycraft/issues/41);
актуальные остатки и приоритеты ведём в issues, этот файл помогает найти код,
контракты и доказательства. Наличие API или unit tests не заменяет реальную
проверку соответствующего действия в Minecraft.

Для первого запуска выбрана DJ2 2.23.4 / Forge 1.12.2. Текущие принятые owned
artifacts: Core 0.3.6, DJ2Fix 0.1.4, Client 0.1.1 — `mods/forge-1.12.2/versions.json`.
GTNH не объявляем готовой. Стабильность имеет приоритет перед ускорением загрузки.
Все серверные acceptance выполняются в изолированных Linux Docker labs.

|---|---|---|

| Лаунчер, manifest, update | `PORTABLE_SESSIONS.md`, `SIGNED_PACK_INSTALL.md`, `RELEASES.md` | Подписи, minimum version, repair/сеть, сохранение настроек, portable paths и реальные клиенты |
| Разделение модов | `mods/README.md`, `mods/forge-1.12.2/THIRD_PARTY.md` | Generic Core отдельно от pack fixes, reproducible hashes, архив/lab не в публичном runtime |
| Команды, роли, FTB | `commands/dj2/README.md`, `DJ2_PLANT_PLACEMENT.md` | Все игроки без OP, PvP/Hard, лимиты, защита spawn, обычные разрешённые действия вместе с негативными контролями |
| Измерения и ресурсный мир | `OWNER_WORLD_CUTOVERS.md`, `RESOURCE_WORLD.md` и связанные с #32/#37 документы | Безопасная высадка, mod portal/teleporter state, очистка приватов/домов/варпов только выбранного мира |

Названия документов выше проверяются при обновлении этой входной точки. Порядок
развёртывания и acceptance не следует восстанавливать по старой записи changelog.
Точные протоколы находятся в `docs/validation/`; их ограничения так же важны,
как число пройденных проверок.

## Что сейчас мешает объявить всю подготовку завершённой

- **#29/#105:** остаётся обобщённый случай multi-place через границы FTB.
  Поздний rollback всех блоков отвергнут: он может дублировать содержимое
  TileEntity. Узкий pre-write фикс Twilight Forest уже принят; это разные scope.
- **#33:** capture, транспорт и nightly существуют, но их полный эксплуатационный
  путь, общий budget/retention и quarantine/authority return ещё не закрыты.
  REST/TLS lab на одном ПК не доказывает отдельный физический fault domain.
- **#32/#34/#37/#49:** довести оставшиеся portal/reset/landing, rollback механизмов,
  границы/сюжетные структуры и финальный upgrade/release regression до принятых
  протоколов. Большую предгенерацию выполняем после фиксации версии и границ.
- **#43/#44/#52/#58/#146:** учёт времени, приветствие, структурированный полный чат,
  авторство действий и игровая часть мониторинга нельзя считать готовыми только
  потому, что они перечислены в плане.
- **#30/#36:** заключительный configuration audit и выпускной клиент. CI на трёх
  ОС проверяет Python/Qt/portable bundle, но не доказывает реальную игру на
  графических Linux/macOS Minecraft-клиентах.

Это не новые требования: перечислены уже согласованные открытые scope. Не закрываем
их общим коммитом «подготовка завершена» и не публикуем незавершённые security
reproducers. Конкретные задачи продолжаем в связанных issues.

## После локальных проверок

1. Владелец проводит аудит выбранного точного commit в `dev`.
2. Отдельный этап #38: подготовка уже купленного PL RX-4, SSH/firewall, постоянные
   volumes, реальные домены/HTTPS/CDN/auth, отдельная внешняя копия, доступность
   из сетей игроков, reboot/recovery и лимиты 16 GiB RAM/200 GB SSD.
3. Закрытый пробный вход нескольких приглашённых игроков, наблюдение за нагрузкой
   и только затем первый обычный запуск.

На VPS ничего не разворачиваем до аудита. Rust TUI, GTNH, магазин, привязки к
почте/Telegram и полное автоматическое прохождение всей сборки не блокируют DJ2.
