# История игрового чата для разбора жалоб

Статус: **требование до открытия DJ2, архив и поиск пока не реализованы**.
Задача [#58](https://github.com/omkality/omkalitycraft/issues/58).

Сейчас сообщения могут оставаться в `logs/latest.log` и ограниченных ротируемых
архивах сервера. Отдельного полного хранилища с заданным сроком истории нет;
из наличия файла нельзя делать вывод о сохранности всей переписки за период.
Автоматические клиентские crash reports намеренно исключают чат. В приватном Core
есть защита mute/команд, но нет журнала сообщений; её наличие не означает запись истории.

## Что сохранять

Владелец выбрал **весь внутриигровой текстовый чат**, включая:

- общий чат и публичные действия `/me`;
- личные `/msg`, `/tell`, `/w` и фактически доступные алиасы ответов;
- командный, административный и другие модовые каналы, существующие в сборке;
- серверные/модовые сообщения с отдельным типом источника, без выдуманного UUID игрока.

Для каждой записи нужны UTC-время, сервер/профиль/версия, boot ID и последовательный
номер, UUID автора, аккаунтный и отображаемый ник на момент отправки, канал,
адресаты/команда и исходный текст. Идентичность берётся на сервере у авторизованного
игрока. Имя в теле сообщения, отображаемый псевдоним или скриншот не заменяют UUID.

Проверить источники каждого канала: один `ServerChatEvent` не является готовым
покрытием всех личных и FTB-сообщений. Отдельно различать полученное, отклонённое
мутом/правами и фактически отправленное сообщение. Запись о получении сервером не
доказывает, что её увидел адресат. Сначала оцениваются готовые решения точного Forge,
затем необходимые узкие адаптеры. Drasl/авторизация от этого не меняются.

«Весь чат» не означает запись всех команд с аргументами. Вне chat-журнала остаются
пароли, коды приглашений и управляющие токены из посторонних команд. При этом нельзя
обещать распознавание любого секрета, случайно посланного как обычное сообщение:
сам журнал закрыт и не отправляется в автоматическую диагностику.

## Поиск владельца

Предлагаемый интерфейс, **ещё не существующая команда**:

```powershell
omk admin --config .omk-admin/operator.toml chat search dj2 --nick Player --since 2026-11-01T18:00:00+03:00 --until 2026-11-01T20:00:00+03:00 --context 10
```

Нужны фильтры по серверу, интервалу с явным часовым поясом, UUID/нику, адресату и
каналу. Поиск учитывает имя на момент записи. Результат должен показывать соседние
сообщения участников, выделять совпадения и не терять порядок при одинаковом времени.
Пересекающиеся окна контекста объединяются. Лимит выдачи/обрезка явно обозначаются.

Экспорт — в закрытый файл владельца, не в публичный stdout сервиса/CDN/лаунчер.
Содержимое является данными: экранировать управляющие символы/переносы при выводе,
не исполнять команды и ссылки из сообщений. Команда появится в справочнике готовых
команд только после реальной проверки.

## Хранение и полнота

Предложенные начальные пределы: **90 суток или 256 МиБ суммарно**, что наступит раньше.
Это не обещание наличия любых 90 суток при заполненном лимите. Настройки срока,
объёма и очереди должны иметь проверяемые env overrides и войти в общий бюджет VPS.

Для старта достаточно структурированных журналов с ротацией и ограниченным чтением.
При необходимости поиска индекс SQLite добавляется отдельно; PostgreSQL и перенос
Drasl ради этой задачи не требуются. Конкретная реализация пока не выбрана.

Запись не должна выполнять сетевой запрос на каждое сообщение или создавать
неограниченную очередь в памяти. Проверить заполненную очередь, слишком длинную
запись, ENOSPC, ротацию, чистый stop/restart и SIGKILL. Flush уменьшает потери при
штатной остановке, но не гарантирует сохранность последней записи при аварии.

Поиск сообщает доступный период и известные пропуски/потери. Отсутствие сообщения
в утраченном или уже удалённом диапазоне не подтверждает ложность жалобы. Экспорты
и резервные копии имеют свои ограничения и не должны бесконечно дублировать архив.

Только серверное закрытое хранилище и административный `omk`. Игрокам и клиентскому
лаунчеру оно недоступно. Файлы/содержимое не публикуются в Git и не попадают в world
snapshots по умолчанию. В правилах сервера кратко сообщается о хранении всех игровых
chat-каналов для модерации, без новых предупреждающих окон в лаунчере.

## Приёмка

Нужны два настоящих авторизованных игрока на отдельной DJ2 2.23.4: общий/личный/FTB-чат,
адресат offline и поддерживаемые селекторы, mute/отказ, изменение отображаемого имени,
чужой ник внутри текста, Unicode/форматирование/переносы. Затем restart, запрос периода,
полнота контекста, ограничения диска и отказ игроку в доступе к архиву.

Связанные задачи: [история действий #52](ACTION_ATTRIBUTION.md),
[технические логи](LOGGING.md), [откат базы](REGION_RECOVERY.md).
Это разные источники: переписка помогает разбирать жалобу, но не заменяет журнал
установки блоков и резервные копии.
