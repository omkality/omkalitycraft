# История чата DJ2

Владелец может искать общий чат и личные сообщения DJ2 по времени, UUID и нику.
Сервер сохраняет реплики отдельно от обычных логов, чтобы разбирать жалобы.
[Задача #58](https://github.com/omkality/omkalitycraft/issues/58)

## Какие сообщения попадают в историю

| Канал | Источник |
| --- | --- |
| public | Общий чат сервера, включая форматирование FTB |
| private | Личные сообщения /tell, /msg и /w |
| emote | Действия /me |
| broadcast | Объявления /say |
| tellraw | Сообщения /tellraw с конкретными адресатами |

В проверенном составе DJ2 2.23.4 команда /team управляет группами FTB. Отдельных
каналов командного чата, админ-чата и алиаса ответа в этом реестре нет. Технические
уведомления модов и посторонние команды в историю переписки не входят.

Запись хранит UUID, аккаунтный ник, отображаемое имя и псевдоним FTB на момент
реплики. Текст общего чата берётся из исходного
пакета до форматирования. В личных сообщениях хранится тело команды, у успешной
отправки указан фактический адресат. У сообщений из консоли отдельный тип источника.

Статус **sent** означает, что после проверок Forge и настроек чата игра передала
пакет сети. Для общего чата это одна запись на сообщение, для личного сообщения
отдельная запись на адресата. **Accepted** означает, что штатная отправка завершилась
без подходящего пакета, например если получатель скрыл весь чат. **Rejected**
означает отмену Forge или отказ команды. Получение пакета не подтверждает
прочтение сообщения. [Проверки команд Forge](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.12.x/patches/minecraft/net/minecraft/command/CommandHandler.java.patch)

При входе на сервер с включённым архивом игрок получает краткое правило о хранении
общего и личного чата для модерации.

## Поиск с хоста сервера

`--from` включает начальный момент, `--until` исключает конечный. Оба значения
требуют часовой пояс. Поиск по игроку учитывает имя на момент записи и UUID автора
или получателя. Фильтр адресата по нику также находит попытки отправить сообщение
офлайн-игроку. `--context 2` добавляет до двух соседних записей с каждой стороны
в пределах выбранного интервала.

```sh
uv run omk admin --config .omk-admin/operator.toml chat-history --server dj2 \
  --from 2026-11-27T18:00:00+03:00 --until 2026-11-27T20:00:00+03:00 \
  --player Player --channel private --context 2
```

Выдача отмечает совпадения в `entries`, а `more_matches` показывает, есть ли
совпадения за пределами лимита. `--limit` принимает от 1 до 100 совпадений.
`coverage` показывает интервалы без подтверждённой истории, повреждённые сегменты,
обрезанные тексты и известные пропуски. Счётчики пропусков охватывают затронутые
запуски целиком. Незакрытый последний запуск может ещё работать. Незакрытый
предыдущий запуск мог потерять хвост записей.

При `--export` итоговый JSON записывается в `.omk-admin/chat-export.json` с правами
владельца. Следующий экспорт заменяет этот файл. Экспорт хранится отдельно от
срока хранения самого журнала.

## Включение при плановом обслуживании

Нужны серверные Core 0.3.17 и DJ2Fix 0.1.13 из одного выпуска и соответствующий
профиль расширения. Архив по умолчанию выключен. На хосте создайте выделенную
папку `.omk-admin/chat-history/dj2` с правами `700`. Forge и CLI владельца должны
иметь того же Unix-владельца файлов. В контейнер передайте папку отдельным bind
mount с записью, например в `/run/omk-chat-history`, за пределами рабочей папки игры.

```dotenv
OMK_CHAT_HISTORY_ENABLED=true
OMK_CHAT_HISTORY_SERVER=dj2
OMK_CHAT_HISTORY_DIRECTORY=/run/omk-chat-history
OMK_CHAT_HISTORY_DAYS=90
OMK_CHAT_HISTORY_MIB=256
```

ID совпадает с ключом в `[servers]` файла владельца. Один каталог обслуживает один
сервер и профиль. Лимиты срока и размера принимают целые числа от 1 до указанных
значений по умолчанию. Журнал ротируется по суткам и по 1 МиБ на сегмент.
Старые сегменты удаляются по сроку, объёму или достижении 512 сегментов.
Объём учитывается отдельно от миров, метрик и резервных копий.

Поток игры отдаёт записи в очередь из 256 элементов. Запись и проверка лимитов
выполняются в отдельном потоке. Обрезка длинного текста, переполнение очереди и
восстановление после ошибки записи отражаются в истории. После аварийной остановки
читатель использует завершённые строки и отмечает неполный хвост. При недоступной
папке Forge продолжает запуск, причина видна в его журнале.

Хранилище и экспорт доступны через локальный CLI владельца. Размещайте их вне
каталогов мира, CDN, игровых файлов и выгрузок диагностики. Сервер сохраняет
написанное в чате, поэтому случайно отправленный туда секрет тоже останется в
архиве. Аргументы остальных команд архив не собирает.
