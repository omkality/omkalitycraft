# Онлайн на карточке сервера

API запрашивает штатный Java server-list status у **заданных владельцем** серверов.
Лаунчер получает только состояние, количество игроков, максимальное число слотов и время
проверки. Ники/UUID из sample, MOTD, favicon и внутренний адрес не выдаются.

```powershell
$env:SERVER_STATUS_TARGETS = '{"dj2":{"host":"127.0.0.1","port":25576}}'
$env:SERVER_STATUS_CACHE_SECONDS = '15'
$env:SERVER_STATUS_TIMEOUT_SECONDS = '2'
```

В Docker передаются те же env; `host` может быть именем игрового контейнера в общей сети.
Не задавать URL, путь или credentials вместо host; port — целое число. Допустимо до 8
целей. Значения читаются при старте API, после изменения нужен restart. По умолчанию
целей нет и запросов к произвольным адресам не происходит. Публичные адреса ещё не настроены.

`GET /servers/status` не принимает адрес опрашиваемого сервера от игрока. Кеш принадлежит
worker API; параллельные запросы используют предыдущий результат, а не создают новые
опросы. TTL по умолчанию 15 секунд (env: 1–300), timeout всего обмена — 2 секунды
(env: 0.1–5). Цели опрашиваются параллельно; пакет ограничен 64 КиБ, VarInt и счётчики
проверяются. HTTP-ответ имеет `Cache-Control: no-store`, чтобы внешний кеш не удерживал
устаревший онлайн. Настройку общего reverse proxy/rate limit проверить при развёртывании.

Лаунчер опрашивает API раз в 30 секунд только при видимой странице сборок, без токена,
без блокировки GUI и без повторной задачи, пока предыдущая не завершена:

- Доступный сервер: `Онлайн: 1 / 20`; `0 / 20` показывается только после успешного ответа.
- Недоступный Minecraft: `Сервер недоступен`, без выдуманного нуля.
- Ошибка API/формата ответа: `Онлайн недоступен`; это не доказательство остановки Minecraft.
- Нет настроенной цели: `Сервер готовится`. У планируемого GTNH показатель скрыт.

Предельное число мест первого сервера — **20**. Изолированный Forge-стенд задаёт
`max-players=20`, реальный server-list ответ подтвердил этот максимум. UI показывает
фактически сообщённый сервером предел, а не подменяет его числом 20. Перед VPS запуском
явно применить это значение в server.properties; API/GUI не меняют лимит игрового процесса.

Сквозной тест: полный Linux Docker DJ2, временный настоящий Drasl, протокольный Forge-игрок,
реальный HTTP Granian и Qt-карточка. Проверена последовательность `0/20 → 1/20 → 0/20`,
после остановки — offline без `online=0`. GUI использует изолированную фиктивную сессию,
но количество получает настоящим HTTP из живого Forge. Это не тест графического клиента
в данном сценарии. Granian здесь был Windows-процессом; контейнеризация API/БД остаётся
следующим эксплуатационным этапом. Мир клонировался из тестового volume read-only,
после штатной остановки экспортирован; принадлежащие сценарию контейнеры/volume/API удалены.
