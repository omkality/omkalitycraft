# Правила первого DJ2: решения и состояние реализации

## Чанки, команды и дома

Для обычного игрока: **50 claim-чанков и 3 дома**. Новые подготовленные DJ2-копии
получают эти значения в `local/ftbutilities/ranks.txt`. В Linux-стенде обычный non-OP
игрок получил все 50 чанков; 51-й остался свободным. После вступления второго игрока
в команду тот же чанк удалось занять. Старый рабочий сервер не изменялся.

FTB защищает чанки 16×16 по всей высоте, а не прямоугольники WorldEdit. Владельцем
является команда. Личные квоты её участников складываются: 3 человека — 150 чанков.
Выбирать можно через FTB-карту и `/chunks claim`; `/wand` не требуется. Дом относится
к игроку, а не к общему бюджету команды. Квоты claim и chunkloading различаются:
изменение первой не увеличивает и не уменьшает вторую автоматически.

Операторские значения для новой остановленной копии:

| Переменная | Default | Диапазон |
| --- | ---: | --- |
| `OMK_DJ2_CLAIMS_PER_PLAYER` | 50 | 1–30000 |
| `OMK_DJ2_HOMES_PER_PLAYER` | 3 | 1–1000 |

Пример — [deploy/dj2-player-limits.example.env](../deploy/dj2-player-limits.example.env).
Python готовит rank-файл; сам Forge не читает эти env. Неправильное значение или
неизвестная структура файла отклоняются до записи. Другие ранги сохраняются.

**Число территорий пока не ограничивается кодом.** Согласованная цель — до 3 отдельных
территорий на участника, общий бюджет команды: 3 человека — до 9. Территорией считаем
связную по сторонам группу чанков; диагональ не соединяет, измерения разделены.
Соседние участки одной FTB-команды объединяются в одну группу. В текущем FTBU такого
rank node нет. Нужен небольшой адаптер поверх FTB, с проверками GUI/команд, пакетного
claim, снятия мостового чанка, объединения зон и изменения состава команды. Новую БД
приватов и собственную защиту блоков ради этого не создаём. При выходе участников
нельзя автоматически удалять существующие базы/чанки.

Все игровые аккаунты предполагаются обычными, без OP. Владелец пользуется консолью
и закрытыми операторскими инструментами. Примеры moderator/admin в старом тестовом
шаблоне не означают назначенные людям роли. Магазин/платные ранги отложены.

## Спавн — обязательный этап до открытия

Запрошенные зоны: overworld — квадрат **X/Z от −300 до 300 включительно** вокруг
нуля, ресурсный мир — **от −100 до 100**. Строительство, разрушение и занятие игроком
чанков спавна должны быть запрещены. Пустой OP-список не должен отключать защиту.

**Эта защита ещё не внедрена.** Одного `spawn-protection` ваниллы недостаточно;
FTB `safe_spawn` в установленной версии не является универсальной защитой строительства
и обслуживает только overworld. Проверяем предпочтительный вариант: постоянные
server-owned FTB-чанки спавна, без OP-аккаунта и без расходования личных квот.
FTB работает целыми чанками: покрытие запрошенных квадратов даст границы −304…303
и −112…111 соответственно. Этот небольшой запас нужно отразить в итоговой настройке.
Подготовка не должна перезаписывать чужие существующие claims.

Ресурсный мир ещё не создан; его ID не угадывается и старый Simple Void World не
объявляется ресурсным. Политику −100…100 подключаем при регистрации нового мира.
Отдельно проверяются TNT снаружи, жидкости, поршни, рост деревьев и модовые механизмы:
правильный владелец FTB-чанка сам по себе не доказывает защиту от всех этих путей.

## RTP — обязательная замена назначения до открытия

**Текущее `/rtp` FTB не соответствует новым требованиям:** код выбирает
`FTBUtilitiesConfig.world.spawn_dimension`, а не мир вызова. Этот факт проверен
по исходникам установленной ветки. Старые тесты overworld не проверяли межмировой
сценарий. Исправление ещё не внедрено; текущий профиль нельзя считать готовым по RTP.

Новый адаптер должен сохранять dimension вызова, повторно проверять его после warmup,
использовать штатные FTB cooldown/warmup и не менять глобальный `spawn_dimension`
на время запроса. Неизвестные измерения получают отказ, а не перенос в overworld.
Для Nether обязательна проверка безопасной поверхности **под крышей**, а не поиск
первого блока сверху. Отказ поиска, граница, чужой claim, вода/лава/пустота и смена
измерения во время ожидания — отдельные игровые проверки. Принятое ранее ограничение
магмы не отменяет этих новых требований.

Предварительная политика по реально зарегистрированным типам текущей сборки:

| Измерение / ID | Цель политики RTP | Причина / что проверить |
| --- | --- | --- |
| Overworld `0` | Разрешить в том же мире | Исходный игровой мир |
| Ресурсный, ID ещё не назначен | Разрешить после создания | Регистрация/вход/вайп и своя защита спавна |
| Nether `−1` | Разрешить после проверки поиска | Ресурсы, исключить крышу/лаву/пустоту |
| Twilight Forest `7` | Разрешить после проверки | Владелец согласен на встроенные ограничения прогрессии TF |
| Deep Dark `−11325` | Кандидат на разрешение после теста | Ресурсный мир; свой вертикальный поиск и темнота |
| End `1` | Пока отказ | Пустота и эндгейм-структуры; посадка/маршрут ещё не проверены |
| Aether `4`, Atum `17`, Erebus `66` | Пока отказ | Острова/сюжетные структуры; сначала проверить авторский доступ |
| DivineRPG `420–427` | Отказ | Прогрессия/особые структуры и устройство измерений |
| AbyssalCraft `50–53` | Отказ | Ритуальная/сюжетная прогрессия |
| Galacticraft `−28…−31` | Пока отказ | Планетарный доступ/структуры и специальная посадка |
| AE2 Storage Cell `2`, Quarry `−9999`, Emptiness `14676` | Отказ | Служебные/особые пространства, не обычная область случайной посадки |
| Simple Void `−100`, Underworld `−9`, динамические RFTools и неизвестные ID | Отказ до отдельной классификации | Название/наличие измерения не доказывает пригодность для RTP |

Это **план allowlist, не действующие ограничения**. Типы взяты из настоящего
`forge dimensions` свежего Linux-стенда; перечисление не означает генерацию всех миров.
Обычные авторские порталы/прохождение сохраняются. Остальные одобренные таймеры и
настройки `/home`, `/tpa`, `/back` не менялись; ограничение RTP не является общей
проверкой доступа через все виды телепортации.

## Первое приветствие

Требуется однократный заголовок по центру при первом входе и краткие пояснения команд
в чате: `/sethome` — сохранить дом, `/home` — домой, `/rtp` — случайная точка текущего
мира, `/spawn` — спавн. В Minecraft 1.12.2 заголовок возможен, но четыре пояснения
лучше не пытаться вместить в одну длинную строку subtitle. Штатный FTB MOTD пишет
в чат при каждом входе; для однократности/заголовка нужен небольшой серверный адаптер.
Приветствие ещё не внедрено и не должно рекламировать неверный межмировой RTP.

## Приоритет работ

1. Личные лимиты 50/3, описание команд и предварительный аудит риска — текущий этап.
2. Перед открытием: защита спавна/запрет его claim, корректный RTP с allowlist и
   целевые защиты подтверждённых обходов claims. Предметы до решения владельца не банить.
3. Счётчик территорий 3 на участника и первое приветствие, затем регрессии всех
   затронутых команд/границ, в том числе из обычного Minecraft.
4. Продолжить Linux backup/аварийный возврат, создание ресурсного мира и остальные
   пункты матрицы. Полную предгенерацию оставляем на конец, GTNH — после DJ2.

Подробные сценарии неприкрытых рисков сохраняются локально в
`minecraft_server/project-analysis/security/`, а не прикрепляются к пользовательским
Releases. Подтверждённый обход инвентаря не объявляется доказанным дюпом или крашем.
