# Настоящий клиент DJ2 2.23.4

Промежуточная приёмка #49, 3 ноября 2026 года. Выпуск для игроков пока не принят:
рабочие profile/payload остаются 2.21.3. VPS для этих локальных проверок не нужен.

## Что именно запущено

Windows-клиент Forge 1.12.2 / 14.23.5.2860 с Temurin 8u472, heap 6144 МиБ,
подключался через настоящий Drasl + authlib-injector к отдельному Linux Docker
серверу с приватным Core 0.2.8. Сервер ограничен 4 CPU / 6 ГиБ, Java heap 4 ГиБ;
точный образ закреплён в [отчёте](validation/dj2-rendered-client-2026-11-03.json).
Свежие миры и учётные записи принадлежат стенду. Данные владельца не использованы.

Собраны все **223 авторских клиентских JAR** из точного manifest 2.23.4:
205 взяты из закреплённого server pack, остальные — точные client-only артефакты.
Для 15 файлов, повторно использованных из прежнего подписанного выпуска,
независимая загрузка по исходным CurseForge file IDs подтвердила те же хеши.
Mouse Tweaks Unofficial 3.1.5 и MorphOverlay 1.0.1 получены по точным file IDs
через CurseMaven; Crash Assistant 1.11.9 — из авторского Modrinth.
[Полный BOM](../profiles/upgrade-inputs/dj2-2.23.4-client.json) содержит версии входных
архивов, project/file IDs, размеры, SHA256 и источники; игровые файлы в Git не входят.

Fresh config/scripts/groovy взяты из новой сборки. Старые рецепты не переносились.
Русский overlay содержит только пять locale-файлов на основе перевода BMProjects
commit `1f6764559cf2118b929ad880abd03b53b6f9daa0` с адаптацией изменённых строк.
Включены `ru_ru`, FM_NewFont и начальные square/no-grid настройки JourneyMap.

## Зависшее «Выполняется вход» — #63

В UniversalTweaks **1.20.0** обработчик `UTLoadSound.utMenuSound` вызывает
`getClass()` у отсутствующего GUI до первого главного меню. При прямом запуске
на сервер событие закрытия GUI получает `null`: мир уже появился, но поверх
остаётся окно подключения. Нативные краш-репорты показывают тот же обработчик
в штатных `handleJoinGame` / `handlePlayerPosLook`. В прежнем **1.14.0** этой
добавленной проверки с `getClass()` нет; сравнивался bytecode точных JAR.

Поддерживаемая настройка `"load sounds" → S:"[1] Mode"=NOTHING` отключает
регистрацию декоративного обработчика. Это подтверждено `initClient` именно
закреплённого JAR, а не только текущей веткой upstream. Рецепты и моды не меняются.

`omk.dj2_client_policy.configure_load_sounds` применяется **только к остановленному
staging-каталогу до подписи выпуска**. Он требует точный SHA256 UniversalTweaks,
ограничивает чтение config и отклоняет неизвестную/двусмысленную структуру.
Остальные настройки и окончания строк сохраняются; повторное применение стабильно.
Это подготовка контента, а не pack-specific условие GUI или перезапись пользовательских
настроек при каждом запуске. Публикация исправленного payload ещё не выполнялась.

| Завершение обычного контроля | Client exit 0, Linux server exit 0, OOM false | Не нагрузочный тест 20 игроков |
| Три входа из меню и выхода обратно | AgriCraft JSON записаны, но после выхода возникли новые task exceptions; **проверка не принята** | Ранний итог 21 условия отозван; #65 |

Клиентский диагностический mod используется только в помеченном owned lab с явным
JVM-флагом; он отдельно разрешается сервером на время конкретного теста. Он не входит
в Core/BOM/пользовательский выпуск. После него обязателен контроль без диагностики.
Снимки создаются штатным Minecraft ScreenShotHelper и проверяются после полного
декодирования PNG; первичный metadata snapshot во время async-записи не принимается
за готовое изображение. Пароли/токены/аргументы процесса в отчёт не включаются.

Первый GUI-прогон прервался из-за падения тестового персонажа с неверно подготовленной
площадки. Он сохранён как неуспешный; последующая успешная проверка выполнена после
восстановления аватара и отдельной установки контрольного инвентаря. Это не
доказательство сохранности прежнего инвентаря после смерти.

Отдельный NPE AgriCraft в `MessageSyncMutationJson.getServerId` оказался дефектом
лабораторного подключения: старый probe вызывал конструктор `GuiConnecting(host, port)`
без создания `ServerData`. Точный bytecode AgriCraft обращается к этому отсутствующему
объекту при сохранении mutation JSON. В probe 0.1.2 используется штатный конструктор
`GuiConnecting(ServerData)`, как в списке серверов. Три повторных подключения/выхода
подтвердили сохранение сетевых JSON; AgriCraft/рабочий Core не менялись.
Первые два запуска проверки остановились на неверном ожидании имён base GUI:
сборка подменяет их BQTweaker `GuiQuestOverride` и CustomMainMenu `GuiCustom`.
Эти попытки сохранены отдельно. Первоначальный итог 21 условия проверял отсутствие
новых reports до disconnect и слишком рано завершился после последнего выхода.
Последующий аудит нашёл поздние NPE в `SPacketEntityHeadLook.getEntity` и Bewitchment
`SyncExtendedPlayer.Handler`, несмотря на exit 0. Общий успех отозван, исходный отчёт
сохранён; [#65](https://github.com/omkality/omkalitycraft/issues/65) требует штатного
контроля без probe и проверки reports после disconnect/закрытия процесса.

## Что осталось

- Разобрать поздние ошибки выхода #65, отделив диагностический метод от штатной

  восстановленных task exceptions; скрывать Crash Assistant вместо разбора нельзя.
- JEI/tooltips, все изменённые квестовые описания и смысл перевода требуют дальнейшей
  выборочной игровой проверки; runtime-key audit не заменяет её. Английские Tips,
  часть mod-locales и Patchouli fallback отдельно от русского квестового overlay.
- Подготовить и принять полноценный подписанный кандидат: установка/обновление с
  2.21.3, repair/обрыв сети, сохранение личных настроек, skins и повторный вход.
- Продолжить серверные регрессии #29, журнал действий #52, историю чата #58 и
  остальные обязательные пункты трекера #41. Этот отчёт их не закрывает.
- Linux/macOS здесь относятся к серверу/CI лаунчера; настоящие игровые клиенты этих
  ОС ещё не приняты. Выводов об их renderer по Windows-тесту нет.

## Выбор стабильной версии

По решению владельца 3 ноября свежесть уступает стабильности. 2.23.4 — кандидат,
а не обязательная цель любой ценой. Если штатный клиент воспроизводит серьёзные
ошибки и для запуска потребуются многочисленные патчи, сравниваем тот же сценарий
с 2.21.3 и выбираем более стабильную основу. Прежняя версия тоже требует проверки,
а не автоматически объявляется безошибочной. Полезные инструменты/доказательства
сохраняются независимо от выбранной сборки; открытие не должно превращаться в
бесконечный ремонт всех модов.
