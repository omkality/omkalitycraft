# RFTools: реальные переходы и переносимые приёмники при сбросе

Продолжение [preflight ресурсного сброса](RESOURCE_RESET_PREFLIGHT.md).
Проверка владельца остаётся read-only. Нативная отвязка в этом опыте выполняется
**только лабораторным observer** на изолированной копии; рабочей команды wipe
или новой миграции модовых NBT в owner CLI этот этап не включает.

## Что исправлено в проверке

У выпавшего Matter Receiver сохраняется `tag.destinationId`. Старый проход
проверял `destId` передатчиков и цели Porter, поэтому мог пропустить такой
переносимый блок. Теперь ID сравнивается с ресурсным registry и общим списком
существующих приёмников. Ресурсная либо осиротевшая привязка блокирует auto stage.
Для вложенных контейнеров остаётся тот же проход NBT; отдельные нестандартные
сериализаторы по-прежнему требуют адаптеров.

Обычные `destinationId=-1`/Porter `target=-1` не считаются старой целью. Но если
при этом у Porter остался `tpTimer`, проверка отклоняет неполную отвязку: его
нативный `onUpdate` всё равно попробует завершить переход. `destId=-1`
передатчика не означает штатную отмену dial и не получает такого исключения.
Регрессионные тесты сначала воспроизводят пропуски/ложные срабатывания.

Это уточнение совместимого read-only адаптера. Старый frozen plan, которому
раньше не помешала пропущенная ссылка, не проходит текущую повторную проверку.
Цели/таймеры/предметы рабочей сборки автоматически не переписываются.

## Что показали нативные устройства

Использованы полная DJ2 2.23.4, Forge 14.23.5.2860, прежние Core 0.3.5 /
DJ2Fix 0.1.3 и отдельный gated observer. Сервер и persistent Drasl работают в
изолированных Linux Docker volumes с ограничениями 4 vCPU / 6 ГиБ, heap 4 ГиБ.
Тестовый игрок авторизуется и действует по настоящему Forge/игровому протоколу.
Он не исполняет клиентские моды и не рисует кадры: это серверная функциональная
проверка, а не графическая приёмка Minecraft.

- Физический Matter Transmitter переносит игрока к физическому Matter Receiver
  в ресурсном мире. Advanced Charged Porter возвращает его в основной мир.
- Basic Charged Porter штатно отказывает в межмировом переходе без расхода
  заряда: ёмкость в этом pack — 20 000 RF, стоимость — 150 000 RF. Advanced
  вмещает 1 000 000 RF. Значения проверены в native stack/конфиге; баланс не менялся.
- Настоящий `getDrops` приёмника сохраняет ID в ItemStack. В лаборатории создан
  контрольный стек этим API; это **не воспроизведение дюпа** через действия игрока.
- Удаление resource registry не меняет cached ID живого блока. Неизменённый
  приёмник сам по себе не восстанавливает запись за короткое окно наблюдения,
  но восстановление переносимого блока штатным placement hook может вернуть ID.
  Только монотонности `lastId` для этого случая недостаточно: нужна отвязка
  переносимых блоков, предметов и передатчиков до старта новой копии.
- Выборочная тестовая отвязка сохраняет заряд и остальные теги предметов,
  main-world цель Advanced Porter и оба основных приёмника. Их сохранённые ID
  совпадают с registry после перезапуска и data stage.
- Новая копия готовится из свежего проверенного backup. Старый ресурсный мир
  исключается, offline-игрок получает замороженную точку основного мира.
  Основной рельеф не заменяется тестовой площадкой для выбора этой точки.
- Установка очищенного блока отдельно проверяется обычным игровым пакетом в
  защищённом спавне и за его пределами. Приват не отключается, права не расширяются.
  Нативный новый ID не должен совпадать с удалённым ресурсным ID.
- Затем существующий передатчик перенастраивается на основной приёмник и снова
  переносит игрока. На принятых переходах здоровье не уменьшается.

Независимый stopped TAR/Anvil/NBT аудит сравнивает инвентарь, конкретные поля
приёмников/передатчика, registry и ID-счётчик, основной контрольный приёмник и
каждый другой retained файл на этапе stage. Итоговые числа, хэши и исключённые
ранние прогоны — в [обезличенном протоколе](validation/dj2-rftools-reset-2026-11-09.json).

## Что ещё требуется перед owner wipe

Реализация transactional transport adapters на остановленной копии, все
поддерживаемые места хранения и их неизвестные форматы; сохранённый список
ресурсных ID до удаления registry; отмена незавершённых переходов. Не проверены
все варианты RFTools Dialer, чужие/закрытые приёмники и каждое содержимое bags/
capabilities, реальные сети других модов и графический клиент.

Online-эвакуация, maintenance/start barrier и interrupted recovery остаются
отдельными условиями #32. `portal_adapters_reviewed=false`, `ready_for_start=false`,
`ready_for_players=false`. Нового backup writer/расписания нет; рабочие миры,
Core/Fix, manifest и player releases не менялись. VPS для этой проверки не нужен.
