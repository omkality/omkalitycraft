# Разработка OmkalityCraft

## Цель первого запуска

Приглашение → ник → автоматически созданный пароль → вход и запомненная сессия.
Пароль показывается один раз для сохранения пользователем. Обычный повторный запуск не требует пароля.
В лаунчере будет загрузка скина, выбор сборки и установка/запуск игры.
До публикации нужны смена пароля, отзыв сессий и восстановление доступа без обязательной почты.
Запомненная сессия не заменяет восстановление после потери устройства.

Python остаётся для API, операций и пока GUI PySide6. Аутентификация — Drasl + authlib-injector.
Не нужны Telegram, Microsoft, Ely.by, PHP, сайт или платёжная интеграция.
FTB Utilities / ServerUtilities предоставляют приваты и доступные команды; их данные сохраняются штатно.
PostgreSQL добавим для собственных данных, когда возникнет конкретная необходимость.

## Рабочая папка и Git

Все исходники находятся в `minecraft_server/omkalitycraft`. Разработка ведётся здесь;
отдельная копия проекта или worktree не создавались.

- `master` — проверенные этапы, существующая история сохраняется.
- `dev` — текущая интеграция разработки. Новые задачи можно вести в ветках с PR в `dev`.
- Небольшие коммиты разделяют API, аутентификацию, проверки и документацию.
- `0.2.0.dev0` — версия разработки. Релизные теги добавляются после проверки игрового сценария.
- Репозиторий публичный. Миры, БД, сессии, `.env`, клиентские сборки и OmkalityCore не публикуются.

Старый прототип Telegram/паролей и его тесты не перенесены в новую основу.
Он сохранён только в локальном снимке исходников и локальной архивной ветке;
архивную ветку не отправлять в GitHub.

## Что сейчас работает

Из папки `omkalitycraft`:

```powershell
uv sync --locked --all-groups
uv run omk doctor
uv run omk server list
docker compose -f deploy/auth-lab/compose.yaml pull
uv run omk lab auth smoke
uv run pytest -q
```

`omk` пока содержит только диагностику, список профилей и тест авторизации.
Команд вайпов, резервных копий и управления игровым сервером пока нет.

CDN API запускается без сервисов учётных записей:

```powershell
uv run granian --interface asgi api.app:app --host 127.0.0.1 --port 8000
```

Сохранены manifest/config/launch-profile и скачивание файлов. Исправлены пути настроек после
переноса `src` → `api`, добавлены проверки выхода за пределы папки контента.
Старый параметр с паролем OmkalityCore и фиктивный игровой accessToken удалены из профиля запуска.
Сам профиль ещё требует подключения authlib-injector и проверки в игре.

`profiles/servers.toml` описывает существующий DJ2 RU 2.21.3 и планируемый GTNH RU.
Версия GTNH ещё не выбрана. Названия адаптеров задают направление архитектуры;
реальные адаптеры команд модов ещё не реализованы. Готового GUI в этой ветке пока нет.

## Проверки Drasl

Закреплён официальный образ Drasl 4.0.0 по SHA256 digest. Одноразовый стенд доступен
только на `127.0.0.1:25586`, хранит данные в памяти контейнера и не подключает рабочие БД/миры.
HTTP допускается только на loopback; внешний сервис должен использовать HTTPS.
Команда создаёт уникальный Compose-проект и удаляет только его, включая тестовые аккаунты.
Занятый порт считается ошибкой: чужой сервис не останавливается.
Отчёт не содержит приглашений, паролей или токенов.

На реальном Drasl проверены 12 сценариев:

1. Создание начального администратора.
2. Отказ в регистрации без приглашения.
3. Регистрация игрока с приглашением.
4. Запрет повторного использования приглашения.
5. Запрет изменения скина без авторизации.
6. Загрузка PNG скина через API.
7. Запрет изменения скина другого игрока.
8. Отказ при неверном пароле.
9. Игровая авторизация со стабильным UUID зарегистрированного игрока.
10. Протокол `join` / `hasJoined`.
11. Обновление и проверка сессии без пароля.
12. Отказ после отзыва сессии.

Это тест API и протокола, ещё не запуск Minecraft. Не проверены отображение скина в игре,
истечение сессии, конкурентное обновление токенов и хранение сессии средствами Windows.
Локально проходят 19 тестов CDN/настроек/профилей/HTTP-адаптера, Ruff и Black.
GitHub Actions запускает эти проверки и отдельный одноразовый тест Drasl.
Litestar выдаёт предупреждение о своём импорте Pydantic v1 под Python 3.14;
наш код использует Pydantic v2, текущие тесты проходят. Предупреждение требует учёта при обновлении Litestar.

## Следующие этапы

1. Новый GUI: регистрация с выдачей пароля, вход, системное хранилище сессии, скин,
   смена пароля и понятное восстановление доступа.
2. Отдельные клиент и Forge-сервер DJ2 с authlib-injector: повторный вход, чужой ник,
   неверная/отозванная сессия, отображение скина. Старый OmkalityCore не использовать для доверия к аккаунту.
3. Установка по закреплённому manifest и восстановление прерванных загрузок.
4. FTB, границы, RTP, резервные копии и отдельный ресурсный мир.
5. Выбор GTNH и отдельная проверка его модов; откаты машин/контейнеров/NBT требуют реальных тестов.

https://github.com/BMProjects-Development/Divine-Journey-2-Translate

Обновление проверяем в копии сборки, не поверх существующего мира.
