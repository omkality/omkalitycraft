# Регистр путей моделей puzzle tiles

Для DJ2 2.23.4 подготовлена адресная политика имён клиентских моделей.
Она пока не включена в player manifest. #181/#36/#49/#41 остаются открытыми:
проверка файловой системы не заменяет Linux OpenGL и прохождение заданий.

## Причина и точный состав

В upstream `2743c22b177ab0479819dadb15785925cfe7d0aa` есть 60 JSON-моделей
`resources/contenttweaker/models/item/puzzle_tile_*.json` с заглавной первой
буквой кода. Resource Location использует нижний регистр; Windows ResourceLoader
разрешал 59 используемых моделей через fallback, чувствительная к регистру Linux
ФС не находит такой путь. Все 60 model blobs сверены с Git-деревом upstream.

`ContentTweakerItems.zs` регистрирует ровно 59 соответствующих предметов. Для всех
59 есть отдельные PNG с нижним регистром пути. Модель `puzzle_tile_Grgrg.json`
не имеет ни текстуры, ни регистрации; она сохранена побайтно и не получает
выдуманную текстуру. PNG, регистрации и `ContentTweakerBag.zs` также сверены с
upstream; изменения их содержимого в эту политику не входят.

[Профиль](../profiles/pack-overlays/dj2-2.23.4/resource-models.json) содержит
59 точных пар source/target, размеры и SHA256 моделей/текстур, два script pin
и отдельно сохранённую неиспользуемую модель. Blanket lowercase не применяется.
Результат меняет только имя файла, его JSON и texture reference остаются прежними.
Registry ID, рецепты, задания, предметный NBT и игровые JAR не изменяются.

## Подготовка кандидата

`omk.localization.dj2_resource_models.compose_resource_models` — внутренняя чистая функция
композиции до подписи. Она принимает полный список путей подписанного исходника,
только перечисленные ресурсы и проверенный профиль. Сверяет payload, регистрации,
ссылки и отсутствие коллизий, возвращает `files` и точный список `removed`.
Функция не читает и не пишет игровую папку, не устанавливает файлы и не делает rollback.

Применять результат следует только к отдельной новой staging-копии проверенного
snapshot. На Windows case-only rename выполняется через временное имя в этой
копии. Затем `build_release` проверяет полный inventory и подписывает новое
поколение; хранение и установка остаются в существующих ReleaseStore/Installer.
Новый CLI, игровая ветка GUI или runtime-адаптер не добавлены.

## Проверка и границы

23 новых контракта и 49 прежних проверок locale bundle прошли на Windows и в
readonly/nonroot Linux Docker без сети. Настоящая Linux ФС: 303 условия, включая
59 исходных промахов lowercase, 59 точных моделей и PNG после композиции, прежние
script/orphan bytes, отсутствие коллизий и полный обратный путь к исходному дереву.
Исходный mount остался побайтно прежним; свой контейнер удалён.

В отдельном приватном подписанном кандидате `2.23.4-omk.6-rc.1` 5971 файл:
от принятого содержимого rc.3, повторно подписанного поколением rc.5,
отличаются только 59 путей. Все payload, launch flags и 226 mod JAR прежние.
Исходное принятое поколение восстановлено из сохранённого signed manifest и
immutable rc.2 с одним уже принятым owned Forge-label; все его хеши проверены.
Временный ключ нового кандидата не сохранён, launcher trust policy прежняя.

Настоящий Windows-клиент вошёл на изолированный Linux Forge/Drasl с прежними
Core 0.3.9 / DJ2Fix 0.1.8 / Client 0.1.7 и strict258 policy. Явно добавлен только
закреплённый диагностический MCP overlay; в signed payload его нет. Все 59 плиток
проверены в обычном GUI двойного сундука: 54 в сундуке, пять в панели игрока.
Hover каждого слота подтвердил registry ID/count/meta. Независимое сравнение
60 416 пикселей всех 59 значков с исходными 16×16 PNG дало ноль различий.
Предупреждений case fallback для этих моделей ноль; в прежнем принятом rc.2 их 59.
Это сравнение с сохранённым журналом, а не новый параллельный A/B запуск rc.2.

Клиент завершился штатно с кодом 0, сервер — stop0/noOOM. Независимое чтение
холодного TAR/Anvil/playerdata сохранило все 59 ID по одной штуке: 54 в двух
половинах сундука и пять у игрока, без ground drops. Сериализованный NBT каждого
предмета имеет ожидаемые registry ID, Damage=0 и native Count=1 типа TAG_Int;
создавать новый тип сериализации эта политика не пытается. Свои Docker resources
и диагностические доступы удалены, игровых процессов нет. Неуспешная подготовка
с длинным служебным ником остановилась до первого запуска Minecraft и не засчитана.

Upgrade/return существующей папки при case-only смене путей проверены отдельно
на Windows и Linux исправлением #229, включая все 59 моделей и полные SHA.
[Файловый контракт](SIGNED_PACK_INSTALL.md) отделён от игрового запуска.
Linux/WSLg render и native рецепт пазла приняты ограниченным шагом ниже.
macOS и готовый Linux player profile остаются открытыми. Предметная проверка
BetterQuesting 814 добавлена ниже; полное прохождение сборки не заявлено.
Обратная композиция файлов не означает возврат серверного мира или аккаунтов.
Политика не меняет live-мир, VPS и приостановленный календарный scheduler.
[Протокол и хеши](validation/dj2-resource-models-2026-11-16.json).

## Графический Linux/WSLg и рецепт 9×9 — 17 ноября 2026

В отдельную свежую папку Linux ext4 скопированы и сверены 5 785 файлов принятого
приватного rc.6. 186 Windows runtime/native файлов заменены отдельным Java 8 и
тремя Linux native artifacts по официальному manifest Minecraft 1.12.2 с проверкой
SHA1/размера и сохранением SHA256. Java — Temurin 8u504-b01 из прежнего pinned
образа `eclipse-temurin:8-jre@sha256:377fe8e36a4b1530d9d52020069367ef44313fa891a82ae102b1016a6a3a72f5`.
Системная Java 21 не менялась. Windows-кандидат с Java 8u472 остался прежним.

Фактический вывод: Ubuntu 24.04/WSLg, Mesa 25.2.8 llvmpipe, OpenGL 4.5 compatibility,
1280×720. Это софтовый рендер. Оверлей MCMCP 2026.11.02 закреплён отдельно от
подписанного payload; его HTTP доступен только через Linux loopback. Windows
orchestrator permissions не расширялись. Захват WSLg-окна через Windows helper
дважды вернул timeout; для кадров использован штатный screenshot игры.

Первый старт упал до меню: LWJGL 2 запрашивает экран через внешний `xrandr`, которого
в этой WSL не было. Проверенный Ubuntu `x11-xserver-utils 7.7+10build2` распакован
только в стенд, его `bin` добавлен в PATH одного процесса. Установка пакета в ОС,
изменение JAR или отключение проверки OpenGL не понадобились. Это отдельная
зависимость будущей Linux-упаковки, а не подтверждение её готовности для всех ОС.

В первом новом singleplayer-мире подготовлены 59 разных плиток; GUI-проверка
в survival подтвердила каждый ID/Count=1/Damage=0. Все 60 416 пикселей иконок
совпали с исходными PNG, предупреждений с целевыми 59 именами нет. После выхода
из мира независимое чтение Anvil/NBT проверило 126 условий: 54 предмета в двойном
сундуке, пять у игрока, без ground drops. Архив 7-Zip протестирован и распакован
для сверки всех файлов; исходник при чтении остался прежним.

Второй новый мир проверил рецепт `contenttweaker:it5` в гигантском верстаке 9×9.
Подготовлены 82 единицы: 81 по исходному рецепту и одна заведомо неправильная
запасная плитка. После заморозки предметы командами не выдавались и не заменялись.
60 обычных левых кликов выполнили переносы, неправильную/правильную последнюю
ячейку и получение результата. Всего 287 MCP шагов с чтением состояния:
неправильный вариант не даёт output, правильный показывает и отдаёт ровно один
`it5`. Дополнительно совпали все 82 944 пикселя 81 плитки рабочего поля.

Холодный NBT второго мира проверил ещё 16 условий: один `it5`, одна запасная
`puzzle_tile_gbbgr`, пустая сетка, без ground drops. 81 входная плитка израсходована
нативным рецептом. Первый мир побайтно прежний; все 226 исходных mod JAR после
опыта совпали с signed hashes. Client 0.1.7 — единственный owned клиентский мод
этого состава; server-only Core/Fix здесь повторно не проверялись.

Оба опыта используют диагностическую offline identity и singleplayer, с подготовкой
в creative. Это приёмка отрисовки/рецепта в survival, а не новое подтверждение
Drasl, выделенного сервера, полного BetterQuesting progression или Linux GPU.
macOS и готовый Linux portable profile остаются отдельными проверками.

Клиент завершён штатным Quit с exit 0. После проверенных экспортов удалена только
своя остановленная Linux-папка и её лишние проверочные копии: 972 240 300 байт.
Два 7-Zip архива миров, скриншоты и диагностика сохранены приватно. Исходники
игровых модов, player manifest, live/VPS и paused calendar scheduler прежние.
[Протокол и точные pins](validation/dj2-linux-resource-render-2026-11-17.json).

## BetterQuesting: пазл и сохранение прогресса — 17 ноября 2026

В свежем Linux/WSLg singleplayer проверено исходное задание 814: коробка
`Puzzle Pieces` с 81 плиткой и результат `contenttweaker:it5`. Только три прямых
предварительных задания 794/807/813 отмечены командой при подготовке; исходные
материалы также подготовлены в стенде. Само 814 и следующее 795 командами не
завершались. После фиксации инвентаря все действия выполнялись в survival;
инструмент запретил выдачу/замену предметов и изменение прогресса командами.

Пустая коробка правильного типа/meta вместе с посторонним `it4` оставила оба
требования 0/1 после «Обнаружить/Отправить». Обычный крафт 3×3 из четырёх эссенций,
четырёх сингулярностей и пустого ящика дал исходную коробку: 59 разных стопок,
81 плитка. BetterQuesting засчитал её 1/1, оставил у игрока и сохранил `it5` 0/1.
Штатный выход из мира, холодный NBT/QuestProgress и повторный вход подтвердили [1,0].

Из этой же коробки плитки перенесены через инвентарь в гигантский верстак тремя
партиями. Перестановка двух последних плиток не дала результата; исправленная
сетка выдала один `it5` и израсходовала все 81 вход. Всего 278 обычных кликов по
контейнерам, включая крафт коробки, переносы и получение результата. Новых
предметов или прогресса после фиксации командой не добавлялось.

Приватный скрипт последней плитки ошибочно ожидал пустую ячейку; проверка
остановила его перед изменением занятой ячейки. Продолжение выполнило обычные
перестановки кликами. Сбой стенда не объявлен игровым дефектом, предметы командами
не восстанавливались. Последующие счётчики и независимый холодный разбор подтвердили
сохранность. Перед принятым прогоном также были отклонённые запросы подготовки;
они сохранены приватно и не засчитаны как успешные случаи.

Книга показала оба требования 1/1, завершение 814 и доступность 795. Затем клиент
полностью завершён и запущен заново с тем же профилем/миром и прежними JAR:
завершение, один `it5` и доступность следующего задания сохранились. 795 остаётся
невыполненным. Оба процесса Java завершились с кодом 0, новых crash reports,
hs_err, fatal/task/OOM markers и целевых case warnings нет.

Три холодных снимка и отдельная рекурсивная проверка дали 66 проверок сохранений
и архивов. В финале — один `it5` у игрока, пустой поставленный алмазный шалкеровый
ящик и пустой верстак; оставшихся/выброшенных плиток и копий результата нет.
Посторонний `it4`, семь контрольных булыжников с собственным NBT и книга прежние.
Inventory в level.dat и playerdata совпали. Все 226 signed mod JAR и 119 файлов
моделей/текстур после обоих запусков совпали с исходными хешами.

Стенд использовал прежние pinned Linux JRE/natives, Client 0.1.7, отдельный MCP
overlay, Mesa llvmpipe и диагностическую offline identity. Книга открывалась
через MCP keybinding и событие Windows/WSLg; это не приёмка физической клавиатуры
из #191. Начальный master volume задан 0; звук и Windows OpenAL #163 здесь не
проверялись. Core/Fix на dedicated сервере, Drasl/multiplayer, macOS, готовый
Linux portable profile и полное прохождение сборки не приняты этим опытом.

Приватно сохранены три 7-Zip снимка мира и отдельный архив из 1321 файла; тесты
архивов и SHA256 всех файлов прошли. После сверки удалены только собственный
остановленный Linux-стенд и проверочные копии/дубли входов: 996 418 198 байт.
Игровой код, задания, рецепты, player manifest, Release/VPS и paused scheduler
прежние. [Обезличенный протокол](validation/dj2-bq-puzzle-retrieval-2026-11-17.json).
