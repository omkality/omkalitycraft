# Регистр путей моделей puzzle tiles

Для DJ2 2.23.4 подготовлена адресная политика имён клиентских моделей.
Она пока не включена в player manifest. #181/#36/#49/#41 остаются открытыми:
проверка файловой системы не заменяет Linux OpenGL и прохождение заданий.

## Причина и точный состав

В upstream `2743c22b177ab0479819dadb15785925cfe7d0aa` есть 60 JSON-моделей
`resources/contenttweaker/models/item/puzzle_tile_*.json` с заглавной первой
буквой кода. Resource Location использует нижний регистр; Windows ResourceLoader
разрешал 59 используемых моделей через fallback, чувствительная к регистру Linux
ФС не находит такой путь. Все 60 model blobs сверены с Git-деревом upstream.

`ContentTweakerItems.zs` регистрирует ровно 59 соответствующих предметов. Для всех
59 есть отдельные PNG с нижним регистром пути. Модель `puzzle_tile_Grgrg.json`
не имеет ни текстуры, ни регистрации; она сохранена побайтно и не получает
выдуманную текстуру. PNG, регистрации и `ContentTweakerBag.zs` также сверены с
upstream; изменения их содержимого в эту политику не входят.

[Профиль](../profiles/pack-overlays/dj2-2.23.4/resource-models.json) содержит
59 точных пар source/target, размеры и SHA256 моделей/текстур, два script pin
и отдельно сохранённую неиспользуемую модель. Blanket lowercase не применяется.
Результат меняет только имя файла, его JSON и texture reference остаются прежними.
Registry ID, рецепты, задания, предметный NBT и игровые JAR не изменяются.

## Подготовка кандидата

`omk.dj2_resource_models.compose_resource_models` — внутренняя чистая функция
композиции до подписи. Она принимает полный список путей подписанного исходника,
только перечисленные ресурсы и проверенный профиль. Сверяет payload, регистрации,
ссылки и отсутствие коллизий, возвращает `files` и точный список `removed`.
Функция не читает и не пишет игровую папку, не устанавливает файлы и не делает rollback.

Применять результат следует только к отдельной новой staging-копии проверенного
snapshot. На Windows case-only rename выполняется через временное имя в этой
копии. Затем `build_release` проверяет полный inventory и подписывает новое
поколение; хранение и установка остаются в существующих ReleaseStore/Installer.
Новый CLI, игровая ветка GUI или runtime-адаптер не добавлены.

## Проверка и границы

23 новых контракта и 49 прежних проверок locale bundle прошли на Windows и в
readonly/nonroot Linux Docker без сети. Настоящая Linux ФС: 303 условия, включая
59 исходных промахов lowercase, 59 точных моделей и PNG после композиции, прежние
script/orphan bytes, отсутствие коллизий и полный обратный путь к исходному дереву.
Исходный mount остался побайтно прежним; свой контейнер удалён.

В отдельном приватном подписанном кандидате `2.23.4-omk.6-rc.1` 5971 файл:
от принятого содержимого rc.3, повторно подписанного поколением rc.5,
отличаются только 59 путей. Все payload, launch flags и 226 mod JAR прежние.
Исходное принятое поколение восстановлено из сохранённого signed manifest и
immutable rc.2 с одним уже принятым owned Forge-label; все его хеши проверены.
Временный ключ нового кандидата не сохранён, launcher trust policy прежняя.

Настоящий Windows-клиент вошёл на изолированный Linux Forge/Drasl с прежними
Core 0.3.9 / DJ2Fix 0.1.8 / Client 0.1.7 и strict258 policy. Явно добавлен только
закреплённый диагностический MCP overlay; в signed payload его нет. Все 59 плиток
проверены в обычном GUI двойного сундука: 54 в сундуке, пять в панели игрока.
Hover каждого слота подтвердил registry ID/count/meta. Независимое сравнение
60 416 пикселей всех 59 значков с исходными 16×16 PNG дало ноль различий.
Предупреждений case fallback для этих моделей ноль; в прежнем принятом rc.2 их 59.
Это сравнение с сохранённым журналом, а не новый параллельный A/B запуск rc.2.

Клиент завершился штатно с кодом 0, сервер — stop0/noOOM. Независимое чтение
холодного TAR/Anvil/playerdata сохранило все 59 ID по одной штуке: 54 в двух
половинах сундука и пять у игрока, без ground drops. Сериализованный NBT каждого
предмета имеет ожидаемые registry ID, Damage=0 и native Count=1 типа TAG_Int;
создавать новый тип сериализации эта политика не пытается. Свои Docker resources
и диагностические доступы удалены, игровых процессов нет. Неуспешная подготовка
с длинным служебным ником остановилась до первого запуска Minecraft и не засчитана.

Upgrade/return существующей папки при case-only смене путей проверены отдельно
на Windows и Linux исправлением #229, включая все 59 моделей и полные SHA.
[Файловый контракт](SIGNED_PACK_INSTALL.md) отделён от игрового запуска.
Linux/macOS render и прохождение соответствующих заданий ещё не приняты.
Обратная композиция файлов не означает возврат серверного мира или аккаунтов.
Политика не меняет live-мир, VPS и приостановленный календарный scheduler.
[Протокол и хеши](validation/dj2-resource-models-2026-11-16.json).
