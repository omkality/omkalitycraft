# OmkalityCraft · Forge 1.12.2

Текущие исходники: Core 0.3.5, DJ2Fix 0.1.4 и Client 0.1.1.
Первый импорт сохраняется отдельными тегами и `source-import.json`.
Два чистых Linux Docker build должны побайтно совпадать с принятыми JAR из
`versions.json`; это проверяет CI. Игровые миры, внешние моды, учётные данные
и native-пробники сюда не переносятся. История до импорта остаётся в приватном
архиве владельца.

## Компоненты

- `src/` и `integrations/ftb/src/`: общий серверный Core, API расширений,
  проверка объявленного FML-списка, адаптер восстановления подключений и
  интеграции с FTB для приватов, команд и ресурсного мира.
- `patches/` и `packs/dj2/`: набор исправлений и их композиция для DJ2.
  Наличие исправления не означает проверку всех устройств и механик сборки.
  DJ2Fix 0.1.4 включает серверную проверку переносимого телепортера Mekanism;
  [правило и границы проверки](../../docs/DJ2_MEKANISM_PORTABLE.md).
- `client/`: отдельный клиентский адаптер заданий сетевого подключения;
  косметическое оформление Forge подключается опционально. Подробнее —
  [в описании клиента](client/README.md).
- `abi/` и `client/abi/`: минимальные compile-only объявления типов Minecraft.
  В итоговые JAR они не попадают; исходный код игры здесь не распространяется.

Core и DJ2Fix помечены как server-side. Проверка объявленного списка модов не
доказывает, какой код запущен на чужом ПК. Аккаунты проверяет Drasl +
authlib-injector; права и допустимость действий проверяются на сервере.

## Проверка сборки

Из корня монорепозитория с Python и Docker в режиме Linux containers:

```sh
python scripts/check_mod_sources.py
python scripts/check_forge_mods.py
```

Первая команда проверяет именно Git-индекс: полный список публичных файлов,
отсутствие лаборатории/бинарных зависимостей и размер объектов. Перед локальной
проверкой новые файлы должны быть добавлены в индекс. В CI используется checkout
проверяемого коммита.

Вторая команда загружает пять compile-only входов по SHA256 из
[`build-tools.json`](build-tools.json), собирает из закреплённых образов Java 8 /
Python 3.14.2 отдельный compiler container и выполняет две сборки. Компиляция
проходит без сети, с read-only исходниками, 2 CPU и 1 ГиБ памяти. Исходные
серверные контейнеры и их тома не используются.

Выполняются 13 Python-контролей загрузки/упаковки, 14 Java helper-условий клиента,
две проверки Forge splash ABI, проверка Java 8 class version, отсутствия чужих
классов и совпадения всех трёх JAR с
[`versions.json`](versions.json). Это проверка сборки, а не новый игровой тест.

Зависимости хранятся в игнорируемом `tools/`, результат — в новой папке
`.local/mod-build-<id>/` корня проекта. Log4j используется только как API для
компиляции; его реализация не включается в мод и серверный runtime не меняется.
Повреждённый кеш входов отклоняется, не перезаписывается молча.

Для ручной сборки доступны `fetch_inputs.py`, `build.py` и `client/build.py`.
Сначала загрузите входы, затем передайте Java 8 и пути к закреплённым Forge,
FTBLib и MixinBooter через аргументы `--java`, `--forge`, `--ftblib`,
`--mixinbooter`. Скрипты не устанавливают файлы в сборку игрока.

## Версии и изменения

Порядок обновления одного компонента:

1. Feature-ветка и небольшой PR в `dev`.
2. Изменение Java `@Mod.version`, имени/версии в `versions.json` и записи в
   [`CHANGELOG.md`](CHANGELOG.md). Для изменения только сборочных скриптов без
   изменения байтов JAR версия мода сохраняется.
3. Новое поведение проходит соответствующий native Docker/клиентский тест;
   после проверки фиксируется SHA256 нового JAR. CI не обновляет этот хэш сам.
4. После ревью и CI фиксируется компонентный Git tag вида
   `omkalitycore-0.3.5`, `omkalitydj2fix-0.1.3`, `omkalityclient-0.1.1`.
   Такие теги отмечают исходный снимок, не включают профиль для игроков и не
   создают отдельный GitHub Release лаунчера.

[`source-import.json`](source-import.json) хранит исходные SHA256 файлов первого
импорта с LF. Это исторический снимок, а не текущий список файлов после будущих
изменений. Текущая граница публикации — [`public-files.json`](public-files.json).

Лаборатория и детальные воспроизведения открытых проблем остаются приватными.
Сообщение об уязвимости — по [SECURITY.md](SECURITY.md).
Сторонние входы и ресурсы описаны в [THIRD_PARTY.md](THIRD_PARTY.md).
Отдельная лицензия на переиспользование собственного кода пока не выбрана;
публикация исходников не меняет права авторов сторонних проектов.
